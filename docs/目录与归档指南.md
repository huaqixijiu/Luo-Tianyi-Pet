## 本地产物布局

`artifacts/` 整体被 Git 忽略。保留既有打包脚本的输出路径：

```text
artifacts/
  msix/release/                  MSIX、公钥 CER、当前 SHA256SUMS
  msix/private/                  签名私钥和密码；不展示、不归档到 Git、不清理
  msix/staging/                  最近一次打包中间目录
  portable/release/              便携 ZIP 与同名 SHA-256
  sideload/release/              完整安装 ZIP 与同名 SHA-256
  portable/staging/              便携打包中间目录
  sideload/staging/              安装 ZIP 打包中间目录
  archive/2026-09-11/research/    旧压缩研究、原始包图标备份与素材调查
  archive/2026-09-11/review/      已完成的视觉比较、设置方案及抽取资料
  maintenance/                  清理清单、隔离验证构建和维护日志
```

本轮主发布目录保留 `0.1.0.56` 与 `0.1.0.51`，二者均校验 ZIP 哈希，最新版 MSIX 与发布哈希一致。它们是**这个目录现有的最新两版**；正式已安装版本和其它工作区的更新发布不受此保留策略影响。旧二进制删除后仅保留审计清单及 Git 开发历史，不承诺能逐字节重建过去未提交源码生成的安装包。

以下工作目录正在使用或带有独立状态，因此保留原位：

- `music-fix-worktree`、`notification-worktree`、`top-drag-fix-worktree`、`tray-fix-worktree`：注册的 Git 工作区，须由所属任务结束后通过 Git 管理；禁止直接递归删除。
- `music-metadata-build`、`music-visual-qa`、`notification-probe`、`qa`、`qa-long-idle-*`、`quick-actions` 及根部音乐诊断脚本/截图：当天联调或仍被测试入口使用的现场。

## 以后如何清理

在项目根目录运行：

```powershell
# 默认只预览；每类发布保留最新两个数字版本。
pwsh -File tools/maintenance/clean_old_releases.ps1
# 实际删除经过校验的更早发布文件及其同名 SHA-256。
pwsh -File tools/maintenance/clean_old_releases.ps1 -Apply
# 隔离验证，不使用真实发布文件。
pwsh -File tools/maintenance/test_clean_old_releases.ps1
```

可用 `-KeepVersions 3` 增加保留数量（至少两版）。旧 `Portable-Test` 与现有 `Portable` 属于同一便携产品的版本序列。报告存入 `artifacts/maintenance/release-cleanup-*.json`，包括处理动作、相对路径、大小和 SHA-256。工具只删除严格匹配命名规则的文件，默认预览；保留包校验失败、路径经过链接或待删除文件发生变化时停止。不要与发布构建同时执行；本轮其它构建均在各自独立工作区进行。

不会自动清理 staging、任何 Git 工作区、签名材料、解压目录、`UserData`、源码或原始素材。新调研放入 `docs/research/`，制作说明放入 `docs/authoring/`；已结束实验放入按日期命名的 `artifacts/archive/`。可重建产物删除前核对来源、运行进程、目录边界及是否存在用户数据，不按“旧、备份、final”字样批量删除。
