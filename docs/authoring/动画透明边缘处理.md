# 动画透明边缘处理

2026-09-12：用户要求检查所有运行时动画并修复毛边，保留人物内部、白色衣服和文字，不重画原素材。

## 范围与处理

扫描 69 套运行时动画、3375 个逻辑帧，实际解码 3373 帧（两套进食 WebP 各合并了一对重复帧）；深浅背景查看全部动画的筛查代表帧，另外查看实际 WPF 中间帧。筛查分数只用于定位，不把白色描边得分当成缺陷数量。

`config/animation-sources.json` 的 30 套素材显式设置 `edgeCleanup`，共处理 373 个源帧。仅允许已核对的二值 Alpha 来源；已有半透明的全身动作、睡眠光效及摸鱼无损 RGBA 不重复处理。

- `coverage`：透明交界内侧一像素按 sigma 0.45 生成覆盖率；不向透明区扩散、不删除任何非零 Alpha 像素，RGB 不变。用于元旦演唱、十二周年表情等自带白色贴纸描边的素材。
- `coverage-white-matte`：上述处理加保守的灰边还原；只检查中性灰、相邻深色轮廓、且附近没有白色笔画的像素。颜色拟合误差最多 8；保留白色／米白色文字外描边。用于心律共鸣组。
- `dark-contour-white-matte`：仅用于已经目视确认的“来不及了”黑线外侧白底残留，包含纯白颗粒；旁边必须有深色轮廓。白底重合成误差最多 1/255，人物内部仍逐字节不变。

处理发生在编译器缩放之前，缩放继续使用预乘 Alpha。选中素材的动态 WebP 使用无损编码，并关闭旧的放大锐化，避免再引入色边。所有处理参数在配置和 `animation_edge_cleanup.py` 中固定；官方源文件与 sourceSha256 不变。

## 验证与局限

`test_animation_edge_cleanup.py` 覆盖白色衣服、彩色内部、孤立标点、原生白描边、去白底重合成及拒绝重复处理柔和 Alpha。`validate_animation_edges.py --baseline <旧 manifest> --output <报告>` 检查 30 套全帧内部像素、非零 Alpha 支撑区域、69 套时长／尺寸／锚点／alphaBounds／来源哈希及图集哈希；39 套未选中素材的 manifest 和图集必须完全不变。

本次有 520892 个边界像素恢复半透明，其中 6521 个像素还原白底混色。摸鱼 69 帧独立全像素验证仍通过，133042 个不透明白色像素数量不变。

WPF `--qa-animation-edges --portable` 逐套显示中间帧，100/150/200% × 深色/浅色背景，在 .NET 10 和 net48 各 414 项检查通过；实际画面见 `docs/validation/animation-edges-wpf-01` 至 `08-2026-09-12.png`。发布 EXE 四边拖拽 553 项通过，验证透明边缘变化不破坏定位。双目标编译 0 警告／错误，现有 1382 项自动化和 6 项 Python 边缘回归通过。

WPF QA 为可靠截图使用软件渲染，正式 GPU 设置未改变。原始 162/240/300px 表情的纹理、抖动量化和低分辨率细节不会凭空增加；原有白色贴纸描边与光效不是抠图残留，刻意保留。并非对每一帧进行人工逐张审美检查：全帧使用像素不变量，人工核对筛查代表帧及实际窗口代表帧。
