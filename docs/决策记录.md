# 决策记录

本文件追加重要决策。新决定可以取代旧决定，但要注明替代关系，不能删除历史原因。

## 2026-09-12：长待机装饰按像素锚点定位并保留完整起身段

- 取代 ADR-064 中“默认位于头部右上”的粗略布局：最小 Z 与最小云朵按各自运行帧中的真实像素中心对齐人物头侧；默认使用右侧，工作区内无法完整显示时镜像到左侧对称位置。
- 睡觉和鸭子坐统一使用 600×476 / 300×238 DIP 透明宽画布，只增加透明留白，不缩小人物；zzz 灰褐阶段用首帧淡蓝色阶确定性校正，原始序列不覆盖。
- 长待机会话优先于通用鼠标按下恢复；一次点击必须续播原动作的完整起身段后才能回到 Idle。固定装饰和右边缘位置仅作为隔离 QA 参数，不进入用户设置。

## ADR-001：使用 C#、.NET 10 LTS 和 WPF

- 日期：2026-08-30
- 状态：已采用
- 决定：主程序采用 C#、.NET 10 LTS 和 WPF。
- 原因：项目只面向 Windows，并大量依赖透明窗口、Win32、Core Audio、OLE、COM 和 Shell 能力；WPF 的窗口互操作成熟，适合先完成个人桌宠。
- 影响：不追求跨平台；现代 Windows API 通过平台适配层接入。

## ADR-002：把仓库作为跨对话记忆

- 日期：2026-08-30
- 状态：已采用
- 决定：`AGENTS.md` 规定每轮恢复流程，`docs/项目总控.md` 保存当前状态，开发日志保存验证历史。
- 原因：聊天可能变长、压缩或切换任务，不能依赖模型对旧对话的隐式记忆。
- 影响：每个可交付变更必须同步更新项目总控和开发日志，否则不算完成。

## ADR-003：原始素材和运行时素材分离

- 日期：2026-08-30
- 状态：已采用
- 决定：`候选素材_官方/` 只保存原始来源；`assets/` 保存可追溯的运行时派生资产。
- 原因：现有格式和画布差异较大，直接在 UI 中混用解码器会增加故障和性能风险。
- 影响：建立资产编译工具、动画清单、来源哈希和转换参数。

## ADR-004：显示模式、持续状态和一次性反应分离

- 日期：2026-08-30
- 状态：已采用
- 决定：不使用一个枚举表示桌宠全部状态；调度器从三个正交状态生成播放计划。
- 原因：QQ提醒、音乐、睡眠和用户选择模式会交叉；单一状态容易在动画结束时恢复错误。
- 影响：所有平台联动只能发领域事件，不能直接命令窗口播放并写死返回动画。

## ADR-005：安全降级优先于功能命中率

- 日期：2026-08-30
- 状态：已采用
- 决定：受保护应用前台、通知权限拒绝、回收站不可用或媒体结果不确定时，功能可以不触发，但不能绕过权限或给出错误成功反馈。
- 原因：账号安全、文件安全和隐私高于动画完整性。
- 影响：每个外部联动必须提供禁用、超时、取消和恢复路径。

## ADR-006：音乐状态临时覆盖显示，不修改用户模式选择

- 日期：2026-08-30
- 状态：已采用
- 决定：音乐开始后播放“享受音乐”并进入“音乐摇摆”；音乐停止后恢复用户此前选择的迷你或完整全身模式。
- 原因：保留已经确认的音乐专属待机，同时不让音乐事件永久改变用户的交互选择。
- 影响：设置中需要分别保存 selected display mode 和 resolved playback state。

## ADR-007：运行时统一使用透明 PNG 图集和帧时序清单

- 日期：2026-08-30
- 状态：已采用
- 决定：选定的 GIF、动态 WebP 和 PNG 在构建前编译为透明 PNG 图集；WPF 根据带来源哈希的 JSON 清单逐帧裁切播放。
- 原因：WPF 对现有动画格式的原生支持不一致；统一图集可以准确保留透明度、毫秒级帧时长、循环次数和结束回调，并减少运行时解码器依赖。
- 影响：新增可复现的图集生成脚本和清单校验器；原始文件继续保留，图集通过 Git LFS 管理；需要在 M1 完成内存稳定性验证。

## ADR-008：每次播放会话随机选择一个音乐持续动画

- 日期：2026-08-30
- 状态：已采用；覆盖 ADR-006 中“享受音乐后固定进入音乐摇摆”的两阶段描述，ADR-006 的显示模式恢复约束继续有效。
- 决定：每次从暂停或停止进入播放状态时，在 0.5 倍速“享受音乐”和“音乐摇摆”中随机选择一项，并让它在整个播放会话中循环；暂停后继续播放重新选择。
- 原因：两种素材人物大小、服装和画风不同，播放中途强制切换仍会让体验割裂；按播放会话选择可保留随机性并避免会话内换装。
- 影响：两项素材都必须支持无限循环；持续状态保存当前会话选中的动画，音乐停止后仍恢复用户原本选择的“嘿嘿”或完整全身模式。

## ADR-009：使用只读 Core Audio 会话峰值判断网易云是否有声

- 日期：2026-08-30
- 状态：已采用
- 决定：通过 Windows Core Audio 枚举默认多媒体输出设备的会话，以公开的会话进程号匹配 `cloudmusic.exe`，读取归一化峰值；使用 `NAudio.Wasapi` 3.0.1 作为薄封装。默认每 250 毫秒读取一次，峰值达到 0.001 立即视为播放，连续 1.5 秒无声才视为停止。
- 原因：用户要求不接网易云私有接口；单纯检查进程无法区分播放和暂停，而公开音频会话峰值无需注入、Hook、内存读取或网络监听。
- 影响：功能可以在运行时配置中单独关闭；会话消失立即停止，临时探测失败保留上次状态并重试；不记录进程号、峰值或歌曲信息。真实播放器在不同输出设备、静音歌曲和独占输出下仍需端到端验证。

## ADR-010：将音乐静音宽限缩短为 0.5 秒

- 日期：2026-08-30
- 状态：已采用；覆盖 ADR-009 的 1.5 秒默认宽限参数，其余检测方案不变。
- 决定：连续检测到 0.5 秒无声后退出音乐状态并恢复用户选择的“嘿嘿”或完整全身模式。
- 原因：1.5 秒会让暂停操作显得迟钝；0.5 秒仍能过滤极短的采样空隙，同时明显改善暂停反馈速度。
- 影响：用户 `settings.json` 配置版本升级为 2；旧版本恰好使用原默认值 1500 毫秒时自动迁移为 500 毫秒，用户已设置的其他数值保持不变。

## ADR-011：将音乐静音宽限调整为 1.0 秒折中值

- 日期：2026-08-30
- 状态：已采用；覆盖 ADR-010 的 0.5 秒默认宽限参数。
- 决定：连续检测到 1.0 秒无声后退出音乐状态；未来由桌宠发起的上一首/下一首操作使用独立加载状态，不再只依赖静音宽限判断。
- 原因：0.5 秒会把网易云切换下一首时的常见加载时间误判为暂停，1.5 秒又让真实暂停反馈偏慢；1.0 秒作为当前只读检测阶段的折中值。
- 影响：用户 `settings.json` 配置版本升级为 3；版本 1 的旧默认 1500 毫秒和版本 2 的旧默认 500 毫秒均迁移为 1000 毫秒，其他自定义值保持不变。

## ADR-012：全局快捷键发送采用失败关闭的用户级输入适配器

- 日期：2026-08-30
- 状态：已采用。
- 决定：网易云控制只使用普通用户权限的 `SendInput` 发送用户配置组合；发送前确认前台进程不在受保护名单，并检查相关实体键未被用户按住。前台查询不可靠、输入被占用、过于频繁或系统未完整接受时一律不发送或报告失败。
- 原因：桌宠需要复用网易云自身全局快捷键，同时不得把组合键送入原神等受保护应用，也不能打乱用户正在进行的键盘输入。
- 影响：默认提供 `Ctrl+Alt+Left`、`Ctrl+Alt+P`、`Ctrl+Alt+Right` 作为首轮可见配置；右键菜单显示当前组合。快捷键“已发送”与播放器“已响应”是两个事件，只有后者可触发 OK，下一阶段需用音频状态变化完成确认、加载和超时闭环。

## ADR-013：媒体控制改为角色内悬浮控制条

- 日期：2026-08-30
- 状态：已采用；覆盖 ADR-012 中“右键菜单显示媒体组合”的临时界面决定，ADR-012 的输入安全约束继续有效。
- 决定：鼠标移入角色后显示上一首、播放/暂停、下一首、喜欢歌曲四键控制条，移出后隐藏；控制条覆盖在现有透明窗口底部，不扩大桌宠常驻窗口。喜欢歌曲使用网易云默认 `Ctrl+Alt+L`。
- 原因：常用媒体操作需要比右键子菜单更直接，并与用户给出的简洁播放器按键参考保持一致；悬停显示可避免长期占据屏幕和遮挡角色。
- 影响：右键菜单只保留显示模式、调试、置顶和退出等低频功能；按钮工具提示显示当前快捷键，播放/暂停字形跟随检测状态，控制条隐藏时不得参与身体命中。

## ADR-014：悬浮媒体组件使用项目内轻量矢量样式

- 日期：2026-08-30
- 状态：已采用；细化 ADR-013 的视觉与显隐行为。
- 决定：媒体控制岛使用洛天依代表色 `#66CCFF`、蓝色玻璃表面、本地 WPF `Path` 矢量图标和轻量淡入淡出控制器；只在指针停留于桌宠窗口时可交互，移出后经过 220 毫秒宽限隐藏。
- 原因：MahApps、MaterialDesignInXaml 和 WPF-UI 都提供成熟按钮与图标组件，但当前只需要四个按钮；引入整套框架会增加包体、主题资源和升级风险，本地组件可以保留同样的圆形按钮、状态反馈和 DPI 清晰度。
- 影响：当前不新增第三方 UI 依赖；后续设置页若需要大量标准控件再单独评估 UI 框架，媒体组件仍可复用当前品牌色和矢量图标资源。

## ADR-015：媒体控制岛移到角色动画正下方

- 日期：2026-08-30
- 状态：已采用；覆盖 ADR-013 中“覆盖在现有透明窗口底部、不扩大窗口”的布局决定，四键内容和显隐规则不变。
- 决定：为媒体控制区在窗口底部预留 58 DIP，高度随当前动画画布一起计算；角色视觉层与音乐切换闪白层均避开该区域。控制岛只在悬停期间显示，但即使显示也不覆盖角色、表情文字或身体命中区。
- 原因：用户希望控制按钮出现在动画正下方，不能挡住桌宠本身；单纯继续缩小覆盖层会损害按钮可点性和视觉层级。
- 影响：窗口高度比素材显示高度多 74 DIP（基础边距 16 DIP 加控制区 58 DIP），桌宠主体尺寸不变；旧窗口位置仍可恢复，贴近屏幕下缘时由现有工作区约束校正。

## ADR-016：新增官方动态素材先进入独立候选区

- 日期：2026-08-30
- 状态：已采用。
- 决定：将洛天依 12 周年 QQ 动态表情的 16 个 300×300 原始 GIF 放入独立“新添加”目录，在动画挑选器中统一显示蓝色标记并提供专用筛选；不自动写入运行时状态映射。
- 原因：这组素材覆盖场景广，但画风、动作时长和语义仍需用户实际预览后决定，直接接入会推翻已确认的动画规则。
- 影响：素材来源、归档提交、原始文件名和 SHA-256 都随目录保存；用户选择前，程序包大小和运行时行为不受这些候选影响。

## ADR-017：曲目信息使用系统媒体会话并以网易云窗口标题兜底

- 日期：2026-08-30
- 状态：已采用。
- 决定：曲名和歌手优先读取 Windows `GlobalSystemMediaTransportControlsSessionManager`；目标网易云没有注册系统媒体会话时，只读其顶层主窗口标题并按“歌曲 - 歌手”解析。角色上方预留 52 DIP 显示曲名，悬停时显示，曲目变化或切歌后保留 4 秒。
- 原因：系统媒体会话是语义最可靠的公开来源，但用户当前运行的网易云实测没有任何系统媒体会话；窗口标题仍由 Windows 桌面管理器公开，能够在不接入网易云接口、不读取进程内存的前提下满足功能。
- 影响：只匹配 `cloudmusic.exe`，不枚举其它应用内容；标题和歌手只在内存中保存，日志只记录“曲目已变化”事件而不记录文本。网易云标题为空、通用或格式改变时显示安全降级文案。

## ADR-018：启动按本地时间问候，系统恢复统一播放苏醒

- 日期：2026-08-30
- 状态：已采用。
- 决定：桌宠启动时按 06:00～12:00、12:00～13:30、13:30～20:00、20:00～次日 06:00 四个半开区间播放一次既定问候；Windows 解锁或电源恢复统一播放“心律共鸣·苏醒弹出”，5 秒内的解锁/电源重复事件只响应一次。
- 原因：启动问候表达当前时间，而同一轮系统唤醒常会同时触发两个 Windows 事件；统一苏醒语义并去重可避免恢复时连续换装和重复打扰。
- 影响：时间边界由 Core 解析器和自动化测试维护；平台层只订阅公开 `SystemEvents`，不安装服务或 Hook。反应不激活、不置顶，结束后恢复用户选择的显示模式和当前音乐等持续状态。

## ADR-019：长待机睡眠复用输入空闲查询并与系统苏醒去重

- 日期：2026-08-30
- 状态：已采用。
- 决定：每秒使用既有公开 `GetLastInputInfo` 读取系统空闲时长；5 分钟进入“躺平”，15 分钟且无音乐时进入“晚安浮动”。睡眠后的首次输入播放一次“心律共鸣·苏醒弹出”，并与 Windows 解锁/电源恢复共用 5 秒去重门。
- 原因：轮询公开的累计空闲时长足以判断状态，不需要键盘/鼠标全局 Hook；真实睡眠恢复通常同时产生输入、会话和电源事件，共用去重可以避免同一动作被播放两次。
- 影响：桌宠不记录具体按键、鼠标位置或输入内容；音乐、拖拽和安全隐藏状态不会被空闲规则覆盖。睡眠素材为官方静态 PNG 的可追溯单帧图集，低幅度漂浮由 WPF 在运行时生成。

## ADR-020：原神存在性使用低频过滤进程枚举

- 日期：2026-08-30
- 状态：已采用。
- 决定：正式应用每 2 秒只按配置的 `YuanShen` 与 `GenshinImpact` 名称执行一次普通权限进程枚举，只读取进程标识并立即释放对象；启动时存在的进程仅作为基线，不补播启动反应。前台和全屏状态另用公开 Win32 窗口 API 失败关闭。
- 原因：原计划采用的 WMI `Win32_ProcessStartTrace` / `StopTrace` 在本机普通用户会返回“拒绝访问”；要求提权会扩大风险，轮询公开进程表即可满足低频桌宠场景，并更容易审计其读取边界。
- 影响：检测延迟上限约为 2 秒，不新增 `System.Management` 依赖；不读取游戏内存、模块、线程、文件、画面或网络，不向游戏发送输入，也不建立长期游戏句柄。若一次枚举失败，保留上次状态并在下一轮重试，不猜测启动或退出。

## ADR-021：消息提醒使用有包身份的 Windows 通知监听器

- 日期：2026-08-30
- 状态：已采用；真实授权等待 MSIX 测试包。
- 决定：QQ/微信提醒只使用 `UserNotificationListener` 的应用来源元数据。应用必须先具备 MSIX 包身份并声明 `uap3:userNotificationListener`；设置页仅在用户明确点击后从 UI 线程申请权限。当前免安装 EXE 检测到没有包身份时显示原因并安全停用，不尝试绕过。
- 原因：通知监听器能在不接触聊天进程内部数据的前提下提供可靠的来源分类，但 Windows 将该能力绑定到包身份和用户同意。任务栏闪烁只能作为以后另行验证的兼容性补充，不能冒充已收到消息。
- 影响：平台层只读取 AUMID、应用显示名和创建时间，从不访问消息负载；Core 只在内存中保留来源和时间做 3 秒去重。实际 QQ/微信通知测试需要先构建、签名并由用户安装 MSIX，再由用户亲自批准通知访问。

## ADR-022：测试 MSIX 使用自包含发布和未自动信任的开发证书

- 日期：2026-08-30
- 状态：已采用；等待用户确认安装。
- 决定：用微软 `WinAppCLI` 将 .NET 10 `win-x64` 自包含输出打为 MSIX；包名、发布者和版本由仓库清单固定。首次构建生成随机密码自签名开发证书，PFX 与密码只留在 Git 忽略的本地 `artifacts/msix/private/`，发布目录只放 MSIX、公钥 CER 和 SHA-256。
- 原因：自包含包不依赖目标机预装 .NET；确定性脚本比手工打包更容易审计通知能力和包内容。开发证书可以用于本机旁加载，但自动信任证书会改变系统安全状态，不应由普通构建步骤代替用户决定。
- 影响：当前包约 103 MB，签名完整但在信任公钥前会显示证书链不受信任。构建脚本不会安装证书、应用或申请通知权限；这三项依次等待用户明确确认。实机证明 `CurrentUser\TrustedPeople` 不足以部署该自签名 MSIX，因此测试安装需要用户批准管理员操作，将公钥导入 `LocalMachine\TrustedPeople`；不改用当前用户根证书存储，也不自动开启开发者模式。正式分发仍需要受信任的生产证书或 Microsoft Store 签名。

## ADR-023：通知监听只在用户成功授权后启动

- 日期：2026-08-30
- 状态：已采用；细化 ADR-021 的授权时序。
- 决定：配置新增“Windows 通知访问已成功授权”标志，默认和所有版本 6 旧配置均为否。应用启动与设置页打开不得在该标志为否时调用 `UserNotificationListener.Current` 或 `GetAccessStatus`；只有用户在设置页亲自点击按钮后才调用 `RequestAccessAsync`，且仅在返回 `Allowed` 后缓存标志并启动监听。
- 原因：微软要求在使用 `UserNotificationListener` 前从 UI 线程取得明确许可；本机 `0.1.0.0` 在未授权启动阶段探测监听器时同时触发 Windows 推送通知服务故障和未处理 `COMException`。消息提醒是可选联动，不应阻止桌宠主体启动。
- 影响：设置架构升级到版本 7；更新后的包即使 Windows 通知服务不可用也能启动音乐、动画和其它功能。权限被拒绝或请求失败时保持未授权，不在下次启动自动重试；用户需要在设置页再次主动操作。

## ADR-024：外部普通测试使用自包含便携包

- 日期：2026-08-30
- 状态：已采用。
- 决定：普通外部测试提供 x64 自包含 ZIP，以 `--portable` 启动并把设置、日志全部写入解压目录的 `UserData`；不包含 MSIX、开发证书或安装步骤。附带的清理脚本必须验证包标记、可执行文件和目标路径，只停止可执行路径完全匹配的便携进程并删除包内数据。
- 原因：测试者需要能直接解压运行、方便移除且不在个人电脑留下应用配置；为普通功能测试导入本机级自签名证书会扩大安全和清理成本。
- 影响：便携版可测试动画、鼠标、音乐、音量、时间和原神低权限联动，但因没有包身份而不能测试 QQ/微信通知监听；后者继续使用单独的 MSIX 测试流程。“无残留”只承诺程序自身创建的数据，不试图删除 Windows 下载历史、SmartScreen、安全扫描或系统事件记录。

- 影响：网易云没有音频会话时滑杆安全显示不可用，绝不退回系统主音量。开机自启动默认关闭，只在用户主动启用时写入当前用户 Run 项中的一个产品值；不安装服务、计划任务或驱动。受保护游戏前台或前台查询失败时，两类音量写入与快捷键发送都失败关闭。

## ADR-028：边缘躲藏采用明确越界意图和素材原生触发面

- 日期：2026-08-31
- 状态：已采用；覆盖原 18 DIP 近边即隐藏和 12 DIP 天依蓝三点条方案。
- 决定：以人物实际画面越过工作区 28 DIP 作为躲藏意图，单纯贴边保持普通摆放；左右隐藏后保留“偷看”素材砖墙，底部隐藏后保留“闪亮登场”猫耳/头发。动画只遍历连续第 3～7 帧，并在鼠标方向变化时从当前帧反转。距底边 80 DIP 内将媒体控制岛移到歌名/作者上方。
- 原因：透明窗口为歌名和控制区保留的边距不等于人物边界，旧判定导致人物无法贴边、底部离任务栏过远；人工触发条破坏素材画面；每次正放/倒放都从端点重启会产生跳帧和首帧闪烁。
- 影响：拖拽期间只临时允许 96 DIP 受控越界，未达到阈值时人物夹回工作区；边缘模式仍不显示媒体控制、不接受身体点击，且不增加全局鼠标 Hook、系统服务或新权限。

## ADR-029：消息提醒读取结构化标题但永不读取正文

- 日期：2026-08-31
- 状态：已采用；细化并部分覆盖 ADR-021 的“完全不访问通知负载”限制。
- 决定：继续只使用用户授权的 Windows `UserNotificationListener`。除应用来源、时间和应用 Logo 外，只在 Toast 绑定至少包含两个独立文本元素时读取第一个标题元素，用作联系人昵称或群名；绝不读取第二个及后续正文元素的值。标题和图标只在内存中传递，结构不明确时回退为仅显示来源。
- 原因：用户希望在不显示消息内容的前提下辨认是哪位联系人或哪个群发来消息。Windows 的结构化文本元素可以把标题与正文分槽，但单文本通知语义不明确，不能冒险显示；公开 `UserNotification.Notification.Visual` 没有联系人头像字段。
- 影响：提醒卡显示应用图标、来源和可用标题；领域模型预留可选联系人头像槽，但当前适配器保持为空并回退应用图标。禁止为补头像读取聊天缓存、私有 XML、窗口画面、远程 URL、进程内存或网络；日志仍只记录来源类别与处理结果，不记录标题、头像或正文。

## ADR-030：边缘动画采用含字展开与无字收回的非对称路线

- 日期：2026-09-01
- 状态：已采用；覆盖 ADR-028 中左右与底部统一只遍历第 3～7 帧的部分，越界门槛、素材原生触发面和底部控制岛布局继续有效。
- 决定：左右“偷看”展开使用第 3→19 帧以保留“偷看”文字和完整人物，收回只使用无文字第 7→3 帧；底部“闪亮登场”展开保持第 3→7 帧，收回改用无文字第 5→3 帧。左右隐藏墙面只保留靠人物侧约 10.5% 图宽的砖墙窄条，并按裁剪后的变换边界贴屏和命中。
- 原因：原第 3～7 帧展开只显示头部，删掉了用户希望看到的文字和完整人物；整块 26.5% 图宽砖墙又显得过宽。反向播放含字段会让文字跟随角色缩进墙内，也不符合用户要求。

## ADR-031：边缘动画速度按方向独立设置

- 日期：2026-09-01

- 决定：以当前帧时长为基准，左右钻出使用 1.2 倍速，左右收回保持 1.0 倍速；底部下钻使用 0.8 倍速，底部钻出保持 1.0 倍速。左右隐藏砖墙由 10.5% 图宽缩至 7.5%，约 14 DIP。
- 原因：用户实测认为下钻仍偏快、左右钻出偏慢，且现有约 20 DIP 墙面仍略宽。不同方向共用素材但节奏诉求不同，修改素材全局帧时长会误伤相反方向和其它场景。
- 影响：范围播放器新增仅作用于本次调用的速率参数，素材清单、源 GIF 和其它动画速度不变；非法、零值或非有限速率失败关闭。窄墙的透明命中区与可见裁剪同步缩小，仍按裁剪后边界贴屏。

## ADR-032：普通拖拽取消降落并为边缘候选建立稳定回差

- 日期：2026-09-01
- 状态：已采用；覆盖早期“迷你拖拽持续循环膨胀且每次松手都播放降落”的规则。
- 决定：迷你“膨胀”只完整播放一次并停在末帧；普通松手经短脉冲遮罩恢复持续动画，不播放降落。仅当总向下移动至少 72 DIP、最近 180 ms 向下至少 22 DIP 且速度达到 650 DIP/s 时播放“降落”和弹簧回弹。边缘候选使用切换素材前缓存的人物本地边界，28 DIP 进入、14 DIP 退出。
- 原因：三套不同画风素材在每次拖拽中的硬切比速度差异更显突兀；降落作为快速下甩彩蛋更符合动作语义。完整全身与边缘素材尺寸不同，若用当前素材重新判定边缘，会在临界点反复进入和退出预演。
- 影响：音乐拖拽、完整全身拖拽和边缘收纳仍优先于降落；普通迷你拖拽更安静，长时间拖动不会重复播放膨胀。边缘候选退出需要明确向屏幕内退回，减少临界抖动但仍可撤销收纳。

## ADR-033：偷看素材在编译期统一裁掉外侧大墙体

- 日期：2026-09-01

## ADR-034：再次微调左右钻出与底部下钻速度

- 日期：2026-09-01

## ADR-035：先用同模型二维程序动作验证完整全身交互方向

- 日期：2026-09-01
- 状态：候选阶段；尚未写入桌宠运行时映射。
- 决定：从现有官方模型 32 帧完整全身待机渲染确定性派生轻轻鞠躬、开心跳跃、左右探身、害羞摇摆、惊喜弹起 5 个透明 WebP，先放入动画挑选器让用户决定保留项和触发场景。所有动作首尾回到同一源帧并保持 480×520 画布，不切换角色、衣服或表情包。
- 原因：完整全身互动大量跳转到不同周年表情包会产生画风、服装、人物尺寸的突变；当前仓库虽保留官方 PMX，但没有可复现的 MMD/Blender 骨骼渲染环境。二维程序动作能快速验证统一模型方向，同时避免生成非官方自设形象。
- 影响：这 5 项只能表达整个人物的平移、缩放和脚底轴旋转，不能实现真实挥手、抬腿或独立转头。用户确认需要局部动作后，再单独恢复 PMX 骨骼渲染流水线；候选阶段不改变现有身体点击映射和安装版。

## ADR-036：建立可复现的官方 PMX 骨骼动画流水线

- 日期：2026-09-01
- 状态：已采用；补充 ADR-035，二维候选继续保留但不再承担精细局部动作。
- 决定：固定使用便携式 Blender 4.5.13 LTS 与 MMD Tools 4.5.13 导入仓库已有的官方洛天依 V4 Q 版 PMX；动作以 Python 关键帧脚本记录，透明渲染后进入现有 WebP/图集流水线。第一项正式动作是完整全身模式拖拽时的“双脚乱甩”，松手不播放跨画风“降落”，直接恢复原模式。
- 原因：用户要求真正可见的肢体动作，同时希望保持官方模型、服装和比例一致；在用户机器已拥有 MMD 的情况下，仍以便携 Blender 流水线为项目权威环境，可避免人工 GUI 操作不可复现，也不要求测试者安装制作软件。

## ADR-037：收敛身体候选并建立可提前收起的一分钟暂停反馈

- 日期：2026-09-01
- 状态：已采用；覆盖普通身体六项随机、切歌加载动画、暂停 5 秒、苏醒弹出、夜间问候与长睡眠素材以及原神启动三轮展示的旧规则。
- 决定：普通身体只使用实际画面为“十二周年·抱抱”的素材；旋转舞、九周年点赞、八周年点赞、我推、真好和加载中摇摆退出当前触发映射但保留候选。音乐暂停进入独立 `MusicPaused` 持续状态并显示“九周年·没睡醒呼吸”最多 60 秒，双击可提前恢复原显示模式而不切换模式；桌宠发起暂停后的 2 秒内可由首个可靠静音样本快速确认。夜间启动改用“晚安浮动”，15 分钟睡眠改用“眠了呼吸”，启动问候也适用于 Windows 开机自启动；系统恢复与输入苏醒不再播放“苏醒弹出”。黑化、重罪分别使用 0.5、0.7 倍速；原神启动“你不许玩”只播一轮并保持末帧，使总展示约 5 秒。

- 影响：Core 新增 `MusicPaused` 持续状态，空闲解析器不会覆盖这 60 秒；恢复播放会立即取消暂停计时并重新选择音乐动画。快速确认只作用于桌宠自己发送的暂停命令，不改变外部暂停和切歌检测。十二周年源文件仍保持上游名称，运行时通过实际可见文案把 `12_在吗.gif` 映射为“抱抱”，并在文档与挑选器中标明命名倒置。

## ADR-038：播放按钮在网易云未运行时执行安全冷启动

- 日期：2026-09-01
- 状态：已采用；重新分配 ADR-037 暂停使用的“加载中”素材，但不恢复切歌加载动画。
- 决定：播放/暂停按钮发现 `cloudmusic.exe` 不存在时，先经前台安全检查，再从 Windows App Paths 或明确的常见安装目录启动网易云。等待阶段静止显示“心律共鸣·加载中”原始单帧图，不叠加旧的左右摇摆，并保持文字提示；约 2 秒后若仍未有声，只发送一次用户配置的播放快捷键。Core Audio 确认有声后直接进入当前歌曲的音乐动画，整个流程 30 秒超时。

## ADR-043：撤销系统主音量并只考虑网易云应用会话音量

## ADR-045：在设置页启用 Win11 风格网易云应用会话音量

## ADR-050：边缘收纳以实际人物三分之一越界为意图门槛

## ADR-054：模式三边缘预演锁定外窗与当前方向

- 日期：2026-09-05
- 状态：已采用。

## ADR-055：身体区域由离线描边工具输出归一化多边形

## ADR-056：吃包子运行素材提升为 384 像素与光流 2 倍补帧

- 日期：2026-09-05
- 状态：已采用。
- 背景：两套源序列都是 720×720、标称 24 FPS，但运行图集曾先缩到 256×256；用户把桌宠放大后会再次上采样而发糊，24 FPS 的奔跑姿态变化也有明显跳帧感。直接把相邻帧透明叠加会形成双重轮廓，不能作为正式补帧。
- 决定：运行帧提高到 384×384；在中性底上计算相邻帧的双向光流，把前后帧分别扭到时间中点，再以预乘 Alpha 合成。每个 42 ms 源间隔拆成两个 21 ms 间隔，循环末尾也补首尾中间帧，单次动画末帧补等时定格，所以总时长完全不变。
- 权衡：384 像素在默认 205 DIP 与最大 200% 显示之间兼顾清晰度和解码内存；不采用 512 像素加 48 FPS，以免单个 132 帧进食图集的解码内存过高。OpenCV 只属于离线资产生成依赖，不进入桌宠安装包。

## ADR-057：晶蓝礼服版内部假棋盘按限定区域转为 Alpha

- 日期：2026-09-05
- 状态：已采用。
- 背景：`Q版小人全身_新默认.png` 是整张 Alpha=255 的 RGB 合成图，灰白棋盘已经烘焙。原有边缘洪泛能清除外部背景，却无法进入被两侧发丝和薄纱线条围住的棋盘区域。
- 决定：保留候选原图不变，在确定性派生工具中登记两块源像素内部背景区域；区域内只有近白、低色差的棋盘像素转为透明，有色发丝、装饰线和深色轮廓保留。运行时继续引用派生透明图，不增加运行时图像处理。
- 理由：直接擦除矩形会损伤人物线稿，生成式重绘又可能改变角色细节；“限定区域 + 原背景色判定”可复现、可审计，也能精确回应当前两处残留。

## ADR-062：身体部位动作播放期间锁定双击换装

## ADR-064：上下边缘使用统一的附件纵向顺序

- 日期：2026-09-06

## ADR-065：第二模型身体动作取消通用换图过渡

## ADR-066：第二模型运行图集加入精确待机首尾帧

- 日期：2026-09-06
- 状态：已采用；补充 ADR-065，修正其中“动作素材首尾已经是中立站姿”的判断。
- 事实：逐帧检查用户提供的七套 720×720 源序列后确认，它们从第 0 帧就已经处于动作姿势；例如“摸摸头”第一帧已有完整外部手掌。仅取消 WPF 闪光并对齐脚底，仍会在待机切入第 0 帧时产生一瞬间轮廓抽搐。
- 决定：离线准备阶段把真实晶蓝礼服待机图映射到 256×256 动作显示空间，以它替换每套运行图集的第 0 与第 144 帧；第 1～6 帧从待机逐步混入对应原动作，第 139～143 帧逐步混回待机。混合在预乘 Alpha 色彩空间执行，保留原 145 帧、42 ms 帧时长和完整中段动作。
- 影响：运行时第一次换图和最终恢复时看到的像素都与待机一致，人物不会瞬间换姿势；约 0.25 秒的进入/退出段承担姿势衔接。源 PNG 永不覆盖，运行图集、WebP 预览、哈希和派生元数据同步重建。

## ADR-067：第二模型动作与待机共用固定显示槽

- 日期：2026-09-06
- 状态：已采用；覆盖 ADR-065 的 244×244 DIP 动作槽与 7 DIP 运行时补偿。
- 事实：即使图集第 0 帧与待机内容一致，WPF 从 220×238 待机切到 244×244 动作时仍会把透明窗口加宽 24 DIP、增高 6 DIP并重新居中。在屏幕边缘、缩放或非整数 DPI 下，窗口取整与钳位会表现为开始瞬间左右移动。

## ADR-076：第二模型动作按待机图校准亮度

## ADR-082：经典猫耳版按左右部位分流并增加成对点击彩蛋

- 日期：2026-09-10
- 背景：经典猫耳版的双眼、双手、双脚此前各自共用同一方向画面，整张脸也只触发“贴贴”，左右点击缺少对应感；用户同时指定眼睛和脚部连续第二次点击的新表情。

- 资产：三张十二周年源 GIF 不覆盖；运行时分别只保留“充电”15 帧、“哭唧唧”14 帧、“斯到普”13 帧的首个完整周期，统一缩放为 240×240 图集并按 190×190 DIP、0.80 倍速单次播放。
- 理由：运行时镜像使左右反馈方向准确且不增加重复二进制；在现有脸部多边形内部按中心线分发可直接复用用户标注，不要求重新描边；成对计数器只承认真正连续的同类点击，避免用户中途点击其它部位后误触发第二段。
- 状态：已采用；覆盖 ADR-080 中双眼、双手、双脚和整张脸使用单一反馈的映射。
- 速度：1080p 基准初速度改为 180 DIP/s，4 秒达到既有三倍巡航上限；根据当前显示器工作区的逻辑 DIP 对角线使用 1～2 倍速度系数。原生工作区像素必须先除以 WPF DPI，确保 4K 200% 与 1080p 100% 的相对穿屏时间一致。16:9 1080p、2K、4K 完整对角线理论追逐均约 4.28 秒。
- 进食：包子飞入口中后不再等待原 173 帧自然走完；从第 128 帧续播闭嘴尾段约 800 ms，把进嘴后的停顿从约 1.65 秒缩短一半，同时保留可见闭嘴结果。
- 队列：返程中的新包子立即中断返程并恢复最近目标追逐，继续保留整轮最初起点；最后一个包子清空后再返回。包子拖动屏幕坐标统一转换到 DIP。
- 未决定：官方“我很可爱，请给我小笼包”彩蛋、手动投喂命中范围和剩余包子处理流程只写入桌面待确认文档，本 ADR 不提前采用。

## ADR-083：“摸鱼一分钟”仅清除边缘连通白底

- 日期：2026-09-10
- 背景：原 GIF 是不带 Alpha 的白底图，旧派生脚本强制把 GIF 调色板第 0 项设为透明；量化后人物内部的白色衣服、皮肤高光和身体区域也可能落入同一颜色项，导致运行图集中出现大块缺失。
- 决定：逐帧从画布四边遍历与白色距离不超过 96 的外部连通分量，仅将其中与纯白距离不超过 32 的像素设为透明；任何未与画布边缘连通的像素都保持不透明。GIF 编码后重新读取 69 帧，强制检查画布角点已透明且内部保护区没有新增透明像素。
- 理由：连通关系能区分外部白底与人物内部同色细节，不依赖不稳定的调色板编号；保留现有 60 秒时间轴、240×240 帧尺寸和原始素材，不引入生成式重绘。
- 状态：已采用，覆盖 ADR-074 中仅描述倒计时裁帧但未约束白底清除方法的部分。

## ADR-084：移除桌宠本体测试菜单并把托盘开场位移放入内容层

- 日期：2026-09-10

## ADR-085：快捷回收站与桌面吃包子彻底分流

- 日期：2026-09-10
- 背景：直接把文件拖到桌宠原本会在 Shell 回收成功后继续创建包子；同时文件拖放复用了“任意全屏都拒绝”的判断，Windows 桌面外壳覆盖整屏时被误判，表现为必须先点击桌宠才能接收。
- 决定：窗口 OLE 拖放始终作为快捷移入 Windows 回收站的独立能力，支持桌面和任意资源管理器目录；成功后结束“给我”末帧定格并恢复原持续动画，不写入包子队列。设置中的开关改为只控制桌面项目消失后的吃包子动画。前台判断对 `explorer.exe` 的桌面外壳和最大化目录窗口放行，其它全屏程序、受保护游戏和查询失败仍拒绝。

## ADR-087：网易云优先定向媒体命令并跨加载间隙保持音乐状态

- 日期：2026-09-10
- 背景：当前网易云即使能由桌宠启动，也会忽略过早发送或与本机全局快捷键设置不一致的控制；切歌期间 0.5 秒到数秒的静音和音频会话重建又会让人物在音乐动画与待机间闪烁。失败反应引用了未登记的 `resonance-cry-shake`，因此可能显示通用缺素材占位；文件回收成功也不应复用媒体 OK。
- 决定：上一首、播放/暂停、下一首先向配置目标进程的可交互主窗口发送 Windows 标准 `WM_APPCOMMAND`，目标窗口不可用时才回退现有全局快捷键。冷启动至少等待 2 秒并优先等曲目信息出现，10 秒仍未出现才兜底，之后只发送一次播放/暂停；Core Audio 确认有声后先播一次 OK，再恢复已选音乐持续动画。普通静音和会话缺失统一使用 5 秒宽限，桌宠发起切歌后另保持当前音乐状态最多 15 秒；用户主动暂停仍由 2 秒窗口内首个静音或会话缺失样本即时确认。
- 动画：正式登记“心律共鸣·呜呜”单帧并叠加短促晃动，供媒体控制失败和超时使用；正式登记“心律共鸣·大成功”10 帧 GIF，文件经 Windows Shell 成功移入回收站后播放一次。OK 只表示网易云控制得到确认，不再表示文件回收成功。
- 安全：两种控制路径都先执行受保护前台检查和 350 毫秒限流；定向消息只允许三种标准媒体命令且只匹配 `cloudmusic.exe` 主窗口，不发送普通字符、不读取进程内存或私有协议。快捷键回退继续执行实体键占用和成对抬起保护。
- 状态：已采用；设置架构升级为版本 14，旧版本恰好使用 1000 毫秒默认宽限时迁移为 5000 毫秒，自定义值保持不变。

## ADR-088：交换经典猫耳版左右眼与左右手的画面方向

- 日期：2026-09-10
- 背景：用户实际点击后确认，原先“右眼原向、左眼镜像；左手原向、右手镜像”的视觉对应需要整体交换。
- 决定：首次点击左眼使用“心软软”原方向，右眼使用运行时水平镜像；点击右手使用“击掌回弹”原方向，左手使用运行时水平镜像。眼睛 4 秒内第二次点击仍统一播放不镜像的“十二周年·哭唧唧”，脸部、脚部和其它身体映射均不改变。
- 实现：只交换 `BodyInteractionResolver` 返回的 `MirrorHorizontally` 标志，不复制、不反转或覆盖原始素材与运行图集；程序回弹会继续跟随手部镜像方向。
- 状态：已采用，覆盖 ADR-082 中左右眼和左右手的方向分配；脚部仍保持右脚原向、左脚镜像。

## ADR-089：网易云改回全局快捷键并重整音乐动画规则

- 日期：2026-09-10
- 背景：向网易云窗口投递 `WM_APPCOMMAND` 虽能定向控制，但目标未完整消费消息时会进入 Windows Shell 媒体命令链并显示系统媒体浮窗。真实日志还显示，部分 `Process.Start` 返回成功后网易云进程会立即退出，旧等待流程仍持续显示“正在打开”却不会再次尝试。音乐设置把自动、固定、停用和单项彩蛋开关并列，也让普通歌曲与固定动画的关系难以理解。
- 决定：删除定向 `WM_APPCOMMAND` 路径，三个按钮统一发送用户配置的网易云全局快捷键，继续以 Core Audio 与曲名变化确认实际结果。冷启动在 3 秒仍无可控制窗口时重试，包含首次在内最多发起三次启动，但播放快捷键仍最多发送一次。媒体失败只显示原因并恢复，不播放呜呜。音乐设置改为“播放动画总开关 + 智能分配 + 固定唯一动画”：智能模式普通歌使用享受音乐、洛天依本人或合唱随机使用音乐摇摆/一键唱歌；固定三项中的任一项都会应用到所有歌手。
- 兼容：旧 `none` 继续表示总开关关闭；旧的一键唱歌布尔字段保留反序列化兼容但归一为开启，不再出现在设置页。
- 状态：已采用，覆盖 ADR-087 的定向媒体命令、媒体呜呜反馈以及 ADR-086 中“歌手分流和设置项不变”的部分。

## ADR-090：控制岛按人物比例设界限，身体动作直接恢复待机

- 日期：2026-09-10
- 背景：50% 时固定控制岛会超出透明窗口，200% 时歌名岛又随窗口拉得过长；身体动作结束后再跑一次青色遮罩恢复，会短暂出现偏色和位置误差。经典猫耳版摸摸头也明显短于其它动作。
- 决定：由 Core `AccessorySizingResolver` 统一计算歌名宽度和控制岛缩放，保持可点击下限并限制大尺寸上限；身体动作完整结束后直接恢复同槽位待机帧并完成反应令牌，不再追加第二次脉冲；摸摸头播放倍率降为 0.60。按用户最后一次要求，经典猫耳版手部再次交换为左手原向、右手镜像，眼睛保持左眼原向、右眼镜像。
- 状态：已采用；手部规则覆盖 ADR-088，眼睛规则不变。

## ADR-091：追包采用显式速度上限、一次性请求彩蛋与 Alpha 足迹投喂

- 日期：2026-09-10
- 背景：旧代码以“原巡航速度×3”间接得到 810/870 DIP/s，并让返程也重新加速；用户确认追逐上限 800、返程固定 850、5 秒加速，同时希望唯一包子被拖住时出现一次请求小笼包彩蛋并可直接投喂。两套 60 FPS 奔跑素材仍含源画面全局漂移，和窗口移动叠加后像低帧率抖动。
- 决定：追逐从 180 DIP/s 线性加速并在 5 秒到 800 DIP/s，返程固定 850 DIP/s；逻辑桌面对角线与 DPI 适配继续保留。唯一包子在满速后连续拖动 3 秒时，每轮只播放一次“心律共鸣·可爱”并定格末帧；新包子打断等待但不重播。投喂使用整个圆形包子足迹与当前人物 Alpha 的重叠，不以包子中心或矩形命中替代；成功后 150 ms 切张嘴、400 ms 弧线入嘴，有剩余目标时 350 ms 后继续。闭嘴段以 1.35 倍速约 0.54 秒结束。
- 动画：两套奔跑源循环先用上部 64% Alpha 重心对齐周期中位数，再以 premultiplied RGBA 双向光流补到 60 帧；进食帧不做位置稳定，避免改变嘴部表演。最终 V1/V2 循环首尾重心差均低于 0.2 像素。
- 素材边界：晶蓝礼服右侧发丝针孔只在一个 7×22 像素左右的紧约束多边形内用邻近发色补齐；左右两块大透明间隙保持 Alpha 透明。原图不覆盖，参数写入元数据并同步重建动作首尾帧。
- 状态：已采用。

## ADR-092：经典猫耳反应柔和收尾，晶蓝动作提高运行采样

- 日期：2026-09-10
- 背景：经典猫耳版部位表情结束后直接换回待机会形成一瞬硬切，摸摸头即使降到 0.60 倍仍偏短；晶蓝礼服动作图集只有 240×260，桌宠放到 200% 时需拉伸到约 440×476 物理像素，细线和五官明显变糊。目录中的新版晶蓝待机原图仍是无 Alpha 的烘焙棋盘 RGB 图，且灰格比上一版更深。
- 决定：摸摸头维持 0.60 倍速并有限循环 2 次，总展示约 4 秒；经典猫耳全部部位反应以 110 ms 纯透明淡出，在不可见中点恢复锚定待机，再以 170 ms 淡入，不叠加闪光、颜色或缩放。晶蓝十项动作运行帧提高到 360×390、显示槽保持 220×238 DIP，挑选器预览仍为 240×260。新版待机从指定原图以灰度低色差背景阈值 160 重新生成透明 PNG，保留人物和左右发丝大开口，并继续局部补齐已确认的小针孔。
- 权衡：360×390 比 440×476 满倍率原生像素小，仍可能在 200% 下有少量插值，但相较旧图集有显著清晰度提升，同时避免运行资产直接增长到约四倍；一次只解码当前动作，实测 200% 模式二预览私有内存约 270 MiB 且窗口保持响应。
- 状态：已采用。

## ADR-093：动画与追逐共用刷新时钟并补足 200% 运行采样

- 日期：2026-09-10
- 背景：桌宠放到 200% 后，模式二 360×390 动作仍需拉伸到 440×476，模式三多数表情只有 162×162；追包人物换帧和透明顶层窗口位移又由两个独立约 16 ms `DispatcherTimer` 驱动，高速时会错拍、漏拍并在 UI 短暂停顿后一次补完大段位移，静态帧虽清楚但连续观看像低帧率模糊。请求小笼包动画还会继承向左追逐的水平镜像，导致内嵌文字反向。
- 决定：模式二十项动作从 720×720 母版直接重建为 440×476；模式三身体反应、拖拽反应及请求小笼包按显示槽补到 2 px/DIP，使用预乘 Alpha Lanczos 和轻度边缘锐化，原始候选不覆盖、不生成式重绘。两套吃包子运行帧提升到 410×410。`AnimationFramePlayer` 与追包位移统一订阅 `CompositionTarget.Rendering`，位移使用单调时钟，窗口坐标吸附当前 DPI 的物理像素，单帧时间补偿封顶 34 ms。
- 时序：追逐由 180 DIP/s 在 3.5 秒达到 800 DIP/s；返程继续固定 850 DIP/s。包子入嘴后，V1/V2 分别从第 120/112 帧以 1.1 倍速播到第 172 帧，约 0.79/0.91 秒。请求小笼包动画播放前强制把方向恢复为正向，恢复追逐后才再次按目标左右镜像。
- 权衡：运行时动画目录由约 283.6 MiB 增至约 392.8 MiB，换取 200% 档位的 1:1 采样；模式二单次真实 QA 私有内存约 379 MiB。图集仍按需解码且原始 720×720 序列不进入安装包，后续如继续压缩，应优先研究多分辨率按需包而不是再次降低当前大尺寸清晰度。
- 状态：已采用，覆盖 ADR-091 的 5 秒加速、统一第 128 帧/1.35 倍速闭嘴和 ADR-092 的 360×390 模式二采样。

## ADR-094：高分辨率动作使用动画 WebP 并限制解码缓存

- 日期：2026-09-11
- 背景：2 px/DIP 清晰度方案把运行时动画目录提高到约 392.8 MiB，其中模型二十项 440×476 动作约占 303 MiB。PNG 图集逐帧保存完整人物，不能有效利用相邻画面高度相似的时间冗余；若重新缩图或降帧，又会直接撤销用户确认的放大清晰度和动作流畅度。
- 决定：模型二十项、模式三已提高到 2 px/DIP 的身体动作/拖拽/请求动画，以及两套 410×410 吃包子动作，统一构建为质量 95、精确 Alpha 的动画 WebP；逻辑帧尺寸、帧数、逐帧时长、光流补帧和显示 DIP 全部保持。应用随自包含包携带 SkiaSharp Win32 x64 解码器，不依赖系统 WebP 扩展；小素材和单帧继续用 PNG 图集，避免无收益的格式迁移。
- 内存：WebP 首次播放时解码为冻结的 WPF `Pbgra32 BitmapSource`，播放器缓存按估算解码像素限制为 192 MiB，并以最近使用顺序回收非当前大动作。编码器合并完全重复帧时，解码器按物理帧时长扩展回清单逻辑帧，保持现有范围索引和动作时长。
- 发布：被替换的 28 个 PNG 图集共 377.07 MiB，新 WebP 共 112.85 MiB，运行时动画目录降至 128.59 MiB。自包含 `0.1.0.34` MSIX 为 207.02 MiB，发布目录为 321.08 MiB；仅保留 `zh-Hans` 卫星资源，并从发布项删除第三方原生 PDB。官方源序列完整保留且可重复重建。
- 状态：已采用；覆盖 ADR-093 中“继续用 PNG 图集并暂不压缩”的权衡，不改变任何产品触发规则或动画画面尺寸。

## ADR-095：保留 WPF 并以 .NET Framework 4.8 作为默认完整安装目标

- 日期：2026-09-11
- 背景：高分辨率动画改为 WebP 后，自包含 .NET 10 MSIX 仍为 207.02 MiB，其中安装包继续携带完整 Desktop Runtime。用户要求完整安装、不拆动画资源，也不希望目标电脑额外下载运行时；重写为其它 UI 技术会触及透明窗口、像素命中、OLE 拖放、通知、音频和大量已验证状态逻辑。
- 决定：保留 C#/WPF 和现有工程边界；源码项目在 `EnableNetFrameworkBuild=true` 时同时构建 `net48`，打包脚本默认选择 .NET Framework 4.8 x64，清单最低系统版本收敛到 Windows 10 22H2（19045）。受支持 Windows 已包含兼容的 .NET Framework，MSIX 继续一次安装本体及全部动画，不增加运行时下载或可选资源包。日常构建仍默认 .NET 10，`Net10SelfContained` 作为显式兼容回退。
- 实现：共享兼容层补足参数检查、数值 API、随机数、文本分割、`TimeOnly` 及编译器属性；平台层为旧目标选用兼容的 NAudio/Windows SDK Contracts，并对公开 WinRT 调用的 RPC HRESULT 做等价失败关闭。发布布局只保留当前 x64 SkiaSharp 原生库，剔除其它架构、macOS 库和调试符号；Core、Animation、Platform 三组测试都在 net10 与 net48 上运行。
- 结果：`0.1.0.36` 签名 MSIX 为 141,967,058 字节（135.39 MiB），较 `0.1.0.34` 自包含包减少 71.63 MiB（34.6%）；完整旁加载 ZIP 为 141,867,125 字节（135.30 MiB）。本机真实安装后从 WindowsApps 启动，加载 63 项动画和两套身体区域图，通知状态为 `Allowed`，进程正常响应且日志无未处理异常。
- 权衡：安装版不再承诺 Windows 10 1809，最低为仍受项目支持的 22H2；需要覆盖更旧、被精简掉系统组件或特殊企业镜像时，发布者仍可显式构建较大的 .NET 10 自包含包。没有选择 Electron、Qt/C++ 或整体重写，因为它们不能减少 128.59 MiB 的动画主体，且迁移风险远高于可获得的额外体积收益。
- 状态：已采用，默认安装交付从 .NET 10 自包含切换为 .NET Framework 4.8；不改变产品功能、动画画质、帧率或隐私边界。

## ADR-096：安装版与真便携版双交付，通知能力只承诺给有包身份的版本

- 日期：2026-09-11
- 背景：相同版本已经安装且桌宠主进程正在运行时，旧安装脚本会跳过重复注册、再启动一个立即被单实例保护结束的进程，成功控制台也随即关闭，用户感知为“安装没反应”。用户同时需要解压即用、可放任意目录的版本，又希望 QQ/微信 `UserNotificationListener` 在不同电脑可用。
- 决定：提供两个边界清晰的成品。便携版默认使用 net48，解压后直接运行 EXE；程序以同目录标记自动进入便携存储，不要求 `--portable`，但不声称支持系统通知监听。完整安装版继续使用 MSIX 包身份，安装脚本创建指向 AppsFolder AUMID 的桌面快捷方式，成功后总是弹出结果；若同版本主实例已运行则明确告知并保留它，不制造无反应的第二次启动。
- 平台约束：`UserNotificationListener` 仍必须由具有 `uap3:userNotificationListener` 声明的包身份进程在 UI 线程请求用户授权；无法用进程扫描、QQ/微信数据库或窗口抓取替代。微软的外部位置身份包从 Windows 10 2004 起可以让传统 EXE/MSI 安装目录保留包身份，因此“自选目录 + 通知”技术上可行，但仍需安装器注册签名包并处理卸载，不属于真便携。
- 结果：`0.1.0.37` 便携 ZIP 为 141,573,824 字节（135.02 MiB），直接双击 EXE实测写入相邻 `UserData`，清理脚本停止精确路径进程并删除该目录。完整旁加载 ZIP 为 141,867,941 字节（135.30 MiB），本机真实升级后创建桌面快捷方式、包状态 `Ok`、进程响应正常且通知状态保持 `Allowed`；重复运行安装脚本会报告既有实例，不再静默。
- 权衡：当前 MSIX 的实际安装目录由 Windows 管理，不承诺任意路径；未来若用户确认路径选择高于 MSIX 的干净更新/卸载，应单独实现并签署“传统安装器 + 外部位置身份包”，而不是让便携版暗中注册系统组件。
- 状态：已采用。

## ADR-097：“一键唱歌”移除竖排文字并降低嘴型节奏

- 日期：2026-09-11
- 背景：正式听歌动画虽已用相邻官方原帧组成往返闭环，但画面左侧仍带固定的“一键唱歌”竖排文字，角色放到桌面后显得拥挤；每帧 100 毫秒也使嘴型连续变化过快。
- 决定：官方 16 帧 GIF 保持只读；派生脚本继续只取源第 `7→15→8` 帧，并在每一帧固定坐标带 `(0,15)-(33,126)` 清除左侧文字 Alpha。该坐标带止于左侧动态音符之前，角色、音符和其它像素不重绘。每帧时长由 100 毫秒改为 160 毫秒，16 帧整圈由 1.60 秒延长到 2.56 秒，嘴型变化速度降为旧版的 62.5%。
- 验证：脚本在编码前逐像素断言坐标带外 RGBA 与官方源帧相同、坐标带内 Alpha 全透明；输出解码后再次确认 16 帧、每帧 160 毫秒、总周期 2560 毫秒，运行图集和设置页缩略图同步重建。
- 状态：已采用，覆盖 ADR-086 的 100 毫秒帧时长；相邻帧往返闭环、音乐分流和设置选择规则不变。

## ADR-098：播放按钮快速反馈与有边界的洛天依歌手匹配

- 日期：2026-09-11
- 背景：人物音乐动画为掩盖网易云切歌加载保留 5 秒静音宽限，但播放按钮复用同一状态后，用户在网易云内暂停也要等待数秒；桌宠自身发送暂停/播放后同样不能立刻看到按钮变化。智能动画只匹配首个或完全等于“洛天依”的歌手字段，又漏掉合唱中的后位歌手和 `洛天依Official`。
- 决定：人物动画的 5 秒抗闪宽限保持不变，新增独立 `MusicPlaybackIndicatorTracker`，以 250 毫秒采样和 750 毫秒连续静音更新控制岛按钮。桌宠成功发送播放/暂停快捷键时按钮立即显示预期结果，最多保持 2 秒；可靠样本确认后结束预期，命令未生效则自动回正。上一首/下一首的已知加载保护期间不把短暂无声喂给按钮快速判断，避免切歌误闪。歌手匹配按中英文常见合唱分隔符、`feat./featuring/with/vs` 和紧邻词尾解析，字段任意位置的独立 `洛天依` / `Luo Tianyi` 及其 `Official` 后缀均视为洛天依参与；`洛天依然` 等仅前缀相同的名字继续排除。
- 音量弹层：继续使用 `StaysOpen=false` 保留点击其它位置关闭；音量图标再次点击时显式关闭，并在弹层的自动关闭事件与同次按钮 `Click` 之间设置 250 毫秒抑制窗，避免关闭后立即重开。
- 权衡：网易云当前没有稳定注册系统媒体会话，外部播放状态只能由 Core Audio 有声近似判断；750 毫秒比人物动画更灵敏，但歌曲本身持续静音超过该时长时按钮可能暂时显示播放。该判断只影响按钮，不切断人物动画，下一次有声采样会立即恢复。
- 状态：已采用。

## ADR-099：时间问候让位音乐，模式三以横向甩动替代降落彩蛋

- 日期：2026-09-11
- 背景：时间问候、开机问候、音乐动画和中等待机此前各自恢复画面，切歌加载与跨时段容易互相抢占；经典猫耳摸头通过重复慢放延长后动作显得迟缓。用户同时取消快速下甩“降落”和所有“呜呜”反馈，并指定傍晚、模式三旋转拖拽及睡眠范围。
- 决定：时间划为 06:00～12:00、12:00～13:30、13:30～18:00、18:00～20:00、20:00～06:00 五段，傍晚使用“十二周年·饿”；启动与跨界都只展示 10 秒。音乐播放时不启动问候，停歌后稳定等待 10 秒再补播，期间重新播放立即让位；用户人物输入和媒体控制输入可取消展示。`眠了呼吸` 仅经典猫耳版使用，“嘿嘿”收到按下或拖拽输入时恢复待机。
- 动画：摸头以显式 28 帧 `0→9→0→9` 路径形成约三次连续抚摸，每帧约 80 ms、总计 2.24 秒；重罪/黑化有效速度调整为约 0.8/0.6。经典猫耳拖拽由 `RapidBackAndForthDragTracker` 判断 900 ms 内三段至少 32 DIP、360 DIP/秒的横移和两次换向，触发无限循环旋转舞，下一次点击或音乐开始时退出。
- 删除：移除 `DownwardFlingTracker`、`LandingBounceMotion`、降落运行资产与清单引用；操作失败改为气泡专用并移除“呜呜”运行资产。动画挑选器删除用户点名的 12 项预览和三项旧文件吞食派生 WebP，新增三个外观模式的简明触发总览；官方原始表情素材保持不变。
- 通知韧性：本机升级后实际观察到 `UserNotificationListener.NotificationChanged` 订阅可能以 `0x803E0105` 异步进入 WPF 调度器，普通事件订阅 `try/catch` 无法可靠拦截。正式监听改为每 750 毫秒读取官方 Toast 快照，首次只建基线、后续按 ID 处理新增项；单通道门控防止重叠，平台瞬断在下一轮自动重试，彻底避开不稳定事件桥接且不弹错误框。
- 状态：已采用。

## ADR-100：乐正绫音乐彩蛋与低干扰天依提示条

- 日期：2026-09-11
- 背景：智能音乐动画已能区分洛天依，但乐正绫本人或合唱仍被当作普通歌曲；官方“十二周年·打 call”196 帧实际是同一 14 帧动作重复 14 次。桌宠又会为“快捷键已发送”“切歌成功”等可从按钮和动画直接看出的过程弹出深色文字条，既遮挡人物又频繁打断观看。上一轮还把拖拽本身当成退出“嘿嘿”的输入，与用户希望移动桌宠后继续保持该状态不符。

## ADR-101：以任务栏闪烁补齐 QQ / 微信提醒，并提高旋转舞手势门槛

- 日期：2026-09-12
- 背景：本机安装版已有包身份、`UserNotificationListener` 授权为 `Allowed`，但用户在新版微信保留未读后仍没有任何提醒。实机检查确认当前微信进程为 `Weixin.exe` / `WeChatAppEx.exe`，且没有注册 Windows Toast 来源；旧实现只有 Toast 快照，因此“监听已启动”并不等于客户端真的提供了通知。模式三原有三段移动、两次换向也容易在普通拖动后撤回时误触发旋转舞。
- 决定：保留 Toast 快照作为可提供应用图标与会话标题的首选通道，同时让桌宠自己的顶层窗口通过 `RegisterShellHookWindow` 接收 `HSHELL_FLASH` 任务栏闪烁。回退通道只将系统给出的 HWND 解析为 PID 和进程名，内置识别 QQ/QQNT/WeChat/Weixin/WeChatAppEx；不读取窗口标题、控件树、聊天文件或正文。按来源合并 8 秒内的连续闪烁，来源回到前台后重置；Shell 注册失败时安全停用，不影响 Toast。旋转舞门槛改为 1400 ms 内五段有效横移、四次换向，即至少两次完整左右往返；32 DIP 与 360 DIP/秒阈值不变。
- 验证：独立 `Weixin.exe` 测试窗调用 Windows `FlashWindowEx` 后，安装版只收到一次来源事件；安全状态下直接展示，启动问候期间则延后并在问候结束后展示。测试窗不含消息内容，也不访问真实微信。真实客户端仍需后台收到一条新消息验证其自身是否产生 Toast 或任务栏闪烁；现有未读和程序启动前事件不补报。
- 状态：已采用；通知回退扩展 ADR-031/033/099，便携版也可使用仅显示来源的闪烁通道；旋转手势门槛覆盖 ADR-099 的 900 ms / 两次换向规则。
## ADR-064：晶蓝礼服采用可点击唤醒的两段式长待机

- 日期：2026-09-12
- 决定：取消晶蓝礼服版 5 分钟“嘿嘿”，保留 1～5 分钟每轮一次随机哈欠；连续无输入 30 分钟后，以 50:50 选择“睡觉”或“鸭子坐”。睡觉播放到源第 220 帧闭眼卧姿、鸭子坐播放到源第 120 帧闭眼坐姿后定格；只有点击人物才续播各自后段并回到待机，桌面其它输入不隐式唤醒。睡觉动作单独使用 488×476 运行画布和 244×238 DIP 显示槽，保持原人物比例并完整容纳横向头发。
- 决定：定格后立即且每 5 分钟按 60:35:5 选择 zzz、梦见包子、梦见乐正绫，允许连续重复。梦境云朵点击时播放约 1.3 秒的“云朵消散”，zzz 直接移除。
- 素材：睡觉源帧的 Z 字只在人物上方经审计的 `250,0,520,290` 区域、源帧 147～240 内从派生帧清除，并把全透明像素的隐藏 RGB 清零；原始 PNG 保留。小装饰只清除与画布边缘连通的近白/近黑键控背景，避免误删云朵内部白色与乐正绫深色轮廓；随后按可见联合边界裁切并生成小尺寸动画 WebP。
- 理由：中等待机表情与晶蓝礼服画风不一致，而长时间姿态需要“进入—保持—醒来”的完整行为语义。独立装饰播放器能在不复制主人物整帧的情况下低成本增加梦境变化，并允许点击唤醒时同步消散。

## ADR-102：消息提醒采用 30 秒可抢占展示，挑选器按模式分层

- 日期：2026-09-12
- 背景：QQ/微信提醒启动后，1 秒安全状态轮询会看到状态机处于一次性反应，旧判断只允许持续状态，因此把提醒自己的反应立即取消；用户看到的效果只有一闪。动画挑选器又把三套外观专属动画和公共场景全部混在同一总览，难以判断每个模式实际使用哪些素材。
- 决定：消息提醒以 30 秒作为当前最短展示期，单帧“好奇”人物的程序摇摆在期间无限循环；安全判断允许当前消息令牌继续占用展示槽。来源应用进入前台、全屏/锁屏、拖拽或更高优先级反应仍可提前打断。挑选器增加模式一、模式二、模式三和三个模式通用四个入口；模式页列出该模式专属动画以及实际会覆盖到它的公共动画，公共页只列三个模式共有项，完整候选素材仍在独立区域管理。
- 状态：已采用；30 秒是便于用户继续体验调整的临时长时参数，不改变通知隐私、去重或发现通道。

## ADR-103：托盘与人物菜单分层，音乐悬浮岛采用显式开关

- 日期：2026-09-12
- 决定：托盘左键只显示／召回桌宠；右键提供显示、隐藏、完整设置和确认退出。人物右键放位置锁、置顶、音乐悬浮岛和紧凑大小调整，完整滑杆和低频设置归完整设置。
- 决定：音乐悬浮岛默认关闭，由人物右键统一开关并持久化；关闭时歌名、控制和音量全部不可见，不留下小播放按钮。取消讨论中的暂停 10 分钟自动收起设计，播放／暂停／切歌都不改变用户开关。启用后沿用鼠标悬停及离开 5 秒淡出，未运行网易云时保留完整控制岛供主动启动。
- 理由：音乐功能是用户选择的辅助入口，不应在纯桌宠互动时抢占视觉；位置锁只限制拖动，继续保留身体点击、摸头和双击换装。
- 实现：设置 schema v15 新增两个默认 false 字段，v14 无损迁移；所有音乐附件显示路径检查统一开关，包括异步结果和反馈恢复。隐藏人物时抑制追包及消息展示，召回不修改永久置顶偏好。


## 2026-09-12：托盘退出改为单击执行

用户明确取消退出二次确认。托盘点击退出后直接走原有告别动画与关闭流程；删除确认／取消界面及其按鼠标位置重复定位，面板打开前固定本次锚点。此决定取代此前要求确认退出的规则。

## ADR-104：动画展示槽与音乐附件尺寸脱钩

- 日期：2026-09-12
- 背景：按当前动画 DisplayWidth 缩放歌曲岛会使待机／听歌的岛宽不一致；每次切换重新夹紧窗口，过渡后再按不同 Alpha 边界对齐，会在靠边时发生二次位移。
- 决定：所有三种模式使用当前运行清单最大显示宽高构成稳定透明槽，保留素材原显示尺寸并底部居中；歌曲岛单独使用 220 DIP 参考尺寸随用户倍率计算，100% 宽 226 DIP，播放控制保持 178×46 DIP。切换动画不重新缩放或移动窗口。
- 边界：普通靠边摆放按稳定槽为较大动作留空；明确向外拖拽、躲藏细条和身体命中仍按真实 Alpha。附件上下换侧与过渡锚点不再读取摆动／裁剪边界。原始素材和运行时动画不改动。
