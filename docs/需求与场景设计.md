# 洛天依桌宠：需求与场景设计

> 状态：草案 v0.1
>
> 更新日期：2026-08-30
>
> 本文只记录已经讨论确认的规则。其余动画映射等待继续挑选后补充。

## 1. 产品目标

桌宠是一个独立运行的 Windows 透明窗口。它通过待机、音乐、通知和鼠标互动表现状态，同时提供少量系统控制功能。

设计目标：

1. 不打断用户当前工作或游戏。
2. 动画有明确触发原因，避免无意义地频繁播放。
3. 用户的永久设置始终高于一次性动画的临时设置。
4. 所有外部应用联动都采用公开、低权限的 Windows 能力。
5. 场景和动画通过配置关联，后续更换素材不需要重写检测代码。

## 2. 动画调度模型

动画分为两类：

- **持续状态**：基础待机、随机待机、音乐舞蹈、睡眠、拖拽。
- **限时反应**：时间问候持续 30 秒；音量变化、切歌反馈、QQ/微信提醒、原神启动、错误和成功提示按各自时长结束。

一次性反应播放结束后，重新计算当前持续状态，而不是固定回到待机。例如播放音乐时收到 QQ 消息，提醒结束后应继续跳舞。

每条场景规则至少包含：

- 事件来源；
- 动画标识；
- 优先级；
- 循环次数或最长时长；
- 是否允许鼠标互动中断；
- 冷却时间；
- 是否申请临时置顶；
- 播放结束后的恢复策略。

### 2.1 建议优先级

从高到低：

1. 用户正在拖拽或直接操作桌宠；
2. 系统锁屏、显示器关闭和程序退出；
3. 原神启动等明确的一次性场景；
4. QQ/微信提醒；
5. 音乐和音量操作反馈；
6. 时间问候；
7. 音乐持续舞蹈；
8. 随机待机；
9. 基础待机或睡眠。

用户拖拽始终可以中断普通反应动画，避免桌宠失去操控感。

### 2.2 通用失败反馈

操作失败或等待超时统一使用“心律共鸣·呜呜晃动”。该动效由静态表情叠加短促左右晃动生成，并同时显示简短气泡：

- 普通失败：“操作失败，请再试一次”；
- 等待超时：“等太久了，再试一次吧”；
- 网易云没有确认状态：“网易云没有响应”；
- 文件未能移入回收站：“没有放进回收站，文件还在原处”。

气泡只说明结果和下一步，不显示异常堆栈、完整文件路径或其它隐私信息。失败反馈播放一次后重新计算持续状态。

## 3. 置顶规则

用户设置和临时动画必须分开保存：

```text
实际置顶 = 用户永久置顶 || 当前存在临时置顶请求
```

临时动画结束时只撤销自己的临时请求，不能直接把窗口设置为非置顶。因此，用户原本选择置顶时，原神动画结束后仍然置顶。

桌宠窗口不得抢夺键盘焦点。全屏游戏位于前台时，默认取消普通通知的临时置顶；受保护游戏进入独占全屏后，原神启动反应可以提前结束或延后到桌面显示。

## 4. 网易云音乐

### 4.1 控制

第一阶段功能：

- 上一首；
- 下一首；
- 播放；
- 暂停或继续。

控制继续使用网易云音乐的全局快捷键，不接入网易云接口。快捷键由用户在网易云设置中配置，桌宠保存相同的按键组合。

当前默认组合与用户本机网易云设置页显示的一致：上一首 `Ctrl+Alt+Left`、
播放/暂停 `Ctrl+Alt+P`、下一首 `Ctrl+Alt+Right`。
用户需要让网易云中的全局快捷键与桌宠配置保持一致；后续设置页允许修改，默认
组合不应被当作网易云所有版本都固定不变的私有协议。

正式控制入口不是右键菜单。鼠标移入桌宠时，在角色动画正下方的独立预留区域显示
天依蓝玻璃质感控制岛，只显示上一首、播放/暂停和下一首；品牌主色使用
`#66CCFF`，图标采用可随 DPI 清晰缩放的矢量路径。控制岛不覆盖角色、表情文字或身体
交互区，从下方轻微上浮淡入；鼠标移出桌宠后短暂延迟并淡出，未悬停时完全隐藏且不
参与命中。播放状态由 Core Audio 检测结果决定，中间图标随状态显示播放或暂停。每个
按钮的工具提示展示当前配置的全局快捷键。

当 `cloudmusic.exe` 尚未运行时，用户点击播放/暂停按钮不再对空气发送快捷键。桌宠先通过
Windows 注册的 App Paths 定位并启动网易云，定位失败时只检查几个明确的常见安装目录，
不扫描磁盘。等待阶段静止显示“心律共鸣·加载中”原始单帧图片，不附加摇摆、呼吸或位移，
并持续显示“正在打开网易云音乐”的文字。冷启动约 2 秒后如果仍未检测到音乐，桌宠只发送
一次用户配置的播放快捷键；Core Audio 真正检测到有声后立即结束等待并进入本首歌曲对应的
音乐动画。整个冷启动最多等待 30 秒，超时后播放“呜呜晃动”并恢复原显示模式。网易云只有
存在可交互主窗口时才视为已经运行并保持现有播放/暂停流程；退出主界面后即使仍残留无窗口
的后台子进程，再次点击播放/暂停也会重新启动网易云，而不是向残留进程发送无效快捷键。

鼠标移入桌宠时，角色动画正上方同时显示当前歌曲名称；有歌手信息时以较小字号显示在
下一行。桌宠发起上一首或下一首后先显示“正在切换歌曲”，检测到曲目变化后显示新歌名
约 4 秒。用户从网易云或其它设备直接切歌时，只要 Windows 可观察到标题变化，也显示
同样的短暂提示。歌名区域独立预留 52 DIP，不覆盖角色。

受保护游戏位于前台时，安全模式禁止发送模拟键盘输入。此时按钮可以显示“游戏安全模式下已暂停快捷键”，或者要求用户使用真实键盘媒体键。

快捷键发送需要至少 350 毫秒间隔；发送前若前台进程无法安全确认，或用户正按住
相关按键及 Ctrl/Alt/Shift/Windows 修饰键，本次操作直接取消。桌宠只释放本次
自己按下的键，不校正、不接管用户原有键盘状态。

### 4.2 状态检测

- 使用 Windows Core Audio 定位网易云音乐的音频会话。
- 连续检测到有效声音后进入音乐状态。
- 普通短暂无声继续使用约 1.0 秒宽限，覆盖常见切歌加载间隙；用户亲自在桌宠上点击暂停后进入 2 秒快速确认窗口，Core Audio 首次检测到静音就立即确认，不再额外等待完整宽限。
- 长时间无声或播放器退出后回到待机。
- 可选使用 Windows 系统媒体会话读取播放/暂停状态和歌曲变化；这不是网易云私有接口。
- 曲目信息优先读取 Windows 系统媒体会话；当前网易云版本没有注册媒体会话时，只兜底
  读取 `cloudmusic.exe` 由 Windows 桌面管理器公开的主窗口标题，并按“歌曲 - 歌手”
  解析。不得读取进程内存、窗口正文或网易云私有文件。
- 曲名和歌手只在内存中短暂保存用于显示，不写入日志、不保存播放历史。

“快捷键已经发送”和“播放器已经改变状态”应分开处理。无法确认结果时只显示操作反馈，不显示误导性的成功提示。

### 4.3 已确认的播放反馈

- 桌宠定位以音乐陪伴为主。歌手不是洛天依或暂时无法读取歌手时，循环“心律共鸣·享受音乐”，表现为戴耳机陪用户听歌；
- 歌手字段包含独立的“洛天依”或 `Luo Tianyi`（包括合唱）时，在“心律共鸣·享受音乐”和“九周年·音乐摇摆”中随机选择一个，表现为洛天依跟随自己的歌曲唱歌；
- 切歌导致歌手分类变化时重新选择对应动画；不得从曲名猜测歌手，也不读取网易云账号、歌单或内部数据；
- 选中的动画作为本次播放会话的音乐持续动画循环，不再区分“开始播放动画”和“持续播放动画”；
- 暂停后再次继续播放时重新按当前歌手分类选择；洛天依歌曲重新随机两个候选之一；
- “享受音乐”使用 0.5 倍播放速度；持续循环只使用文字已完整显示的稳定帧并往返闭环，人物在相邻动作间衔接，英文文字不随每轮循环反复入场；处理后的文件为 `assets/animations/processed/心律共鸣_享受音乐_无缝_0.5x.gif`；
- 音乐状态临时覆盖 Q 版小人或完整全身显示，但不修改用户选择的显示模式；音乐停止后恢复此前选择；
- 上一首、下一首等操作等待播放器返回时只显示歌名区域的“正在切换歌曲…”文字，不播放“加载中”素材；“心律共鸣·加载中”的静态原图只用于网易云尚未运行时的冷启动等待；
- 加载动画只在等待超过约 400 毫秒后显示，避免正常切歌时闪烁；
- 等待成功结束后播放“心律共鸣·OK”；
- 暂停后进入持续约 1 分钟的“九周年·没睡醒呼吸”；一分钟结束后恢复用户原本选择的 Q 版小人或完整全身模式；
- 恢复播放会立即中断“没睡醒呼吸”并重新按当前歌手选择音乐动画；这一分钟内双击“没睡醒呼吸”也会提前退出暂停展示，但只恢复原显示模式，不切换 Q 版小人/完整全身选择。

加载状态必须设置超时。超时后退出加载动画并进入待机或错误反馈，不能无限循环。

### 4.4 显示模式恢复约束

用户处于完整全身模式时，开始播放音乐会由本次随机选中的音乐动画临时覆盖；这只改变当前播放内容，不改变用户选择的完整全身模式。音乐停止后恢复完整全身待机。用户原本处于 Q 版小人模式时同理恢复 Q 版小人。音乐覆盖期间即使用户切换显示模式，也只更新被记住的用户选择，待音乐停止后再显示新选择。

## 5. 音量控制与反馈

当前版本不再控制或监听 Windows 系统主音量：设置窗口不显示系统音量滑块、滚轮开关、
外部主音量反馈开关或步长；桌宠窗口的滚轮也不写入默认输出设备。旧版配置中的 `volume`
字段只为兼容已有 `settings.json` 保留，不参与当前运行。

后续如恢复音量能力，只允许操作 Windows 音量合成器中属于 `cloudmusic.exe` 的应用音频
会话：枚举当前输出设备的会话，用会话进程号匹配网易云的全部实例，并通过
`ISimpleAudioVolume` 读写这些会话。网易云尚未创建音频会话、会话正在重建或输出设备变化时
必须显示暂不可用，绝不能退回系统主音量。具体入口与反馈动画需经用户确认后再启用。

## 6. 待机与时间

建议默认阈值，之后允许用户调整：

- 没有播放音乐且没有其他事件：默认显示用户提供的 Q 版小人全身立绘；用户双击后切换到完整全身互动待机；
- 正在播放音乐且没有其他事件：循环本次播放会话随机选中的“享受音乐”或“音乐摇摆”；
- 45 秒～3 分钟：允许随机待机；
- 连续无输入达到约 3 分钟且没有播放音乐：进入“心律共鸣·嘿嘿”中等时长待机；恢复输入后回到用户选择的 Q 版小人或完整全身模式；“十二周年·躺平”取消触发并退出运行时安装内容，原始候选素材保留；
- 连续无输入达到 30 分钟且没有播放音乐：进入睡眠；每秒只读检查一次输入空闲时长；
- 系统锁屏或显示器关闭：停止高帧率渲染。

长时间睡眠保留“代号洛天依·眠了呼吸”并持续低幅度呼吸，触发门槛改为连续无输入 30 分钟。检测到鼠标或键盘输入、Windows 解锁或电源恢复后直接重新计算并恢复当前持续状态，不再播放“心律共鸣·苏醒弹出”。

启动时间段已经确认如下：

- 06:00（含）～12:00（不含）：播放“收藏集·早安浮动”，表达早上好；
- 12:00（含）～13:30（不含）：播放“十周年·干饭弹跳”；
- 13:30（含）～20:00（不含）：播放“十周年·摸鱼漂浮”，作为下午问候；
- 20:00（含）～次日 06:00（不含）：播放“十周年·晚安浮动”。

“眠了呼吸”与“晚安浮动”的用途已经调换：前者负责 30 分钟长睡眠，后者负责夜间启动问候。

四段时间问候在每次桌宠正式启动时触发，包括用户手动启动和 Windows 开机自启动，并持续展示 30 秒。如果桌宠一直运行，则在本地时间跨过 06:00、12:00、13:30 或 20:00 时自动展示新时段问候 30 秒；同一时段内不重复触发。高优先级事件可以临时打断，系统空闲后再重试尚未展示的边界问候。Windows 解锁或电源恢复只恢复持续状态，不播放额外苏醒动画，也不修改用户选择的 Q 版小人或完整全身模式。

7 月 12 日（洛天依生日）和 12 月 12 日（用户生日）增加“十二周年·生日快乐”待机彩蛋。彩蛋只在没有音乐、拖拽或其它一次性反应的待机期间触发，每次随机等待 45～90 分钟，播放一次后重新随机，不能进入普通高频待机池。

### 6.1 用户主动退出

用户通过桌宠右键菜单选择“退出桌宠”时，播放一次“心律共鸣·裂开晃动”，约 0.7～0.85 秒后关闭程序。退出动画期间忽略重复退出请求。

Windows 关机、注销、进程崩溃或系统强制结束时不等待退出动画，以免阻塞系统流程；这些路径仍优先保存能够安全保存的状态。

## 7. 原神启动

确认行为：

1. 监听原神进程由未运行变为运行；
2. 播放“心律共鸣·你不许玩”一次；动画结束后保持最后一帧，使动画与停留合计约 5 秒；
3. 播放期间申请临时置顶，但不激活窗口；
4. 播放结束释放临时置顶；
5. 如果用户原本永久置顶，结束后继续置顶；
6. 同一个游戏进程生命周期只触发一次；
7. 全屏安全模式生效时可以提前结束、跳过置顶或延后显示。

默认进程名候选为 `YuanShen.exe` 和 `GenshinImpact.exe`，通过配置维护，不依赖窗口标题。

### 原神后台低频彩蛋

除启动反应外，新增“心律共鸣·拜托”作为原神持续运行期间的低频彩蛋：

1. 仅在原神进程仍存在、但当前前台进程不是原神时计时和显示；
2. 每个 60 分钟的后台活跃窗口随机选择第 5～55 分钟触发一次，并设置 45 分钟硬冷却，避免相邻时间窗出现连续弹出；
3. 到达触发时间时若原神已经回到前台或进入全屏，暂停显示并在重新进入后台后随机延后 5～15 分钟；
4. 在桌宠当前显示器的 Windows 工作区内随机选择位置，保留 24 像素安全边距，保证角色完整可见且不覆盖任务栏；
5. 临时移动到随机位置，播放“拜托”一次；动画结束后恢复此前的位置、持续动画和用户置顶设置；
6. 弹出窗口始终不激活、不抢焦点；原神前台时不申请临时置顶；
7. 原神进程结束、电脑锁屏或桌宠进入睡眠时取消尚未触发的计时。

这项彩蛋只读取进程是否存在以及 Windows 当前前台进程标识，不读取游戏内存、窗口画面、模块、线程或网络数据，也不向游戏发送任何输入。

## 8. QQ 与微信提醒

确认动画：**代号洛天依·好奇摇摆**。该素材右侧已有类似消息提示的图形，适合用作统一通知反应。

行为规则：

1. 仅在来源应用不位于前台时提醒；
2. 提醒卡显示 QQ/微信应用图标，以及系统通知明确提供的联系人昵称或群名；标题缺失或结构不明确时只显示“QQ 有新消息”或“微信有新消息”；
3. 只读取通知的第一个标题元素，而且必须确认另有独立正文元素；绝不读取、显示、保存或记录正文值；
4. 3 秒内的重复通知合并；
5. 一次提醒默认播放一次好奇摇摆；
6. 普通桌面环境可以临时置顶约 2 秒，但不抢焦点；
7. 全屏游戏前台时不覆盖游戏，改为保存一个待查看标记；
8. 通知结束后回到此前的持续状态。

Windows `UserNotification` 当前公开的结构化接口可以取得应用图标和文本元素，但没有提供联系人头像字段。联系人头像因此作为可选能力：若以后系统公开接口直接提供，则在内存中临时显示，并把 QQ/微信小图标作为角标；当前版本稳定回退为应用图标，不读取聊天缓存、不抓窗口、不访问网络头像地址。

检测优先使用 Windows 通知访问能力，兼容任务栏窗口闪烁事件。如果系统通知、声音和任务栏闪烁全部关闭，则在不读取应用内部数据的前提下无法保证检测到消息。

## 9. 鼠标互动

桌宠具有两个显示模式：

- **Q 版小人模式**：每次启动默认使用用户在 2026-09-05 提供的新 Q 版小人全身立绘，占用较小的桌面空间；源图烘焙的近白棋盘格只按画布边缘连通区域移除，不重绘人物；上一版 Q 版原图继续留在候选目录；
- **完整全身互动模式**：双击 Q 版小人后进入，启用身体区域命中；设置页提供带预览的三套可选外观：“华裳长发版”（新完整全身待机，默认）、“晶蓝礼服版”（Q 版小人全身待机新图）和“经典猫耳版”（上一版 Q 版小人全身待机）。再次双击完整全身角色后切回 Q 版小人。每套外观使用独立命中图，切换外观不删除其它素材。

双击间隔默认不超过 300 毫秒。第一次单击需要短暂等待双击判定；确认不是双击后才分发身体区域互动。双击只切换模式，不同时播放单击动画。临时事件动画结束后回到事件前选中的显示模式；应用重新启动时仍默认从 Q 版小人开始，不记忆上一次的全身模式。

鼠标位于当前角色画面的不透明人物像素上时，使用用户提供的天依服装“指向”手型；透明画布、歌名区和控制岛不强制替换系统指针。只有完整全身互动模式启用身体命中、并且当前位置实际命中头发/头顶摸头区域时，才改用专属“摸摸头”手型；离开该区域立即恢复普通指向手型。两种手型均编译为带准确热点的本地 Windows `.cur`，不使用全局鼠标 Hook。

完整全身互动模式使用透明像素命中，并划分左右眼、脸部、嘴部、头发/头顶、左右手、胸部、下体敏感区域、普通身体和左右脚。已经确认的映射如下：

- 点击左眼或右眼：播放一次“心律共鸣·心软软”；眼睛是脸部内部的更小命中区域；
- 短按嘴部：播放一次“心律共鸣·啾啾”；
- 短按脸部但未命中眼睛或嘴部：播放一次“十二周年·贴贴”；
- 按住头发或头顶区域并左右移动，持续约 350 毫秒、累计约 24 DIP 且至少换向一次：判定为摸头，播放一次“天依游学记·国乐季 · 摸摸”；短按头顶也播放一次作为易用性兜底；
- 点击左手或右手：播放一次“十周年·击掌回弹”；
- 点击胸部或下体敏感区域：第一次播放一次“心律共鸣·重罪”；两个敏感矩形缩小，只覆盖明确中心区域，把更多身体画面留给普通部位；
- 在第一次胸部/下体点击后的 4 秒内，再次点击这两个区域中的任意一个：播放一次“心律共鸣·黑化”；
- 点击左脚或右脚：播放一次“十周年·糟了晃动”，不进入黑化重复点击判断；
- 点击没有被眼睛、脸、嘴、头顶、手、敏感区域或脚命中的普通身体部位：固定播放真正的“十二周年·抱抱”。官方素材包把两个文件名写反，实际“抱抱”画面来自 `12_在吗.gif`；旋转舞、九周年点赞、八周年点赞、我推和真好已取消本场景触发，只保留候选；
- “天依游学记·国乐季 · 摸摸”固定用于摸头；“心律共鸣·可爱”不再承担该状态；
- “黑化”触发后进入 10 秒敏感区域冷却，期间不重复播放黑化，避免连续刷屏；
- 滚轮：当前不绑定功能，不改变系统或其它应用音量；
- 右键：保留开发验证和退出；设置、始终置顶与开机自启动由 Windows 系统托盘菜单提供；
- Windows 右下角托盘菜单提供 50%～200% 的“显示大小”滑杆；拖动时立即预览，松手后保存。倍率统一作用于待机、音乐、互动、边缘和吃包子人物动画，不修改原始素材，也不改变控制岛按钮尺寸；
- 在 Q 版小人模式按住左键并移动超过约 6 像素：进入拖拽并自动切换为“心律共鸣·膨胀”；动画完整播放一次后固定末帧，不因继续拖动而循环；
- 在完整全身互动模式进入拖拽：保持原完整全身待机画面，只移动桌宠窗口；不切换“膨胀”或任何专用全身拖拽动作；
- 正在播放音乐时进入拖拽：无论用户选择的是迷你还是完整全身模式，都保持本次播放会话的当前音乐动画，不切换“膨胀”或完整全身模型；
- Q 版小人模式普通松开鼠标左键：不播放“降落”，经短脉冲遮罩从“膨胀”自然恢复 Q 版小人或拖拽期间更新后的持续状态；只有总向下移动至少约 72 DIP、最近 180 ms 仍向下至少 22 DIP 且速度达到约 650 DIP/s 的快速下甩才播放一次“代号洛天依·降落弹跳”和弹簧位移；
- 完整全身互动模式松开鼠标左键：不播放降落动画；画面已经是完整全身待机时无需再次切换，如果拖拽前存在音乐等持续状态，则平滑恢复该状态。
- 音乐播放状态松开鼠标左键：不播放降落动画，继续同一音乐动画。

命中优先级为：窗口拖拽判定 > 双击模式切换 > 摸头手势 > 最小身体区域。眼睛和嘴部命中优先于脸部；鼠标移动超过 6 像素后不再把松手识别成身体点击；脸部与头顶重叠时，短按按最小区域分发，按住并抚摸头顶才触发摸头。胸部和下体共用同一个 4 秒重复点击计时器，双脚和普通身体不使用该计时器。

只有没有播放音乐的 Q 版小人模式发生明确快速下甩时才播放一次“代号洛天依·降落弹跳”，随后返回拖拽前状态；落地时在素材外层叠加一次弹簧位移。普通松手、完整全身互动模式以及音乐播放状态均不播放降落，直接保持或平滑恢复拖拽前持续状态；若同时达到边缘收纳门槛，边缘收纳优先。

身体区域反应动画结束后，进入 800 毫秒身体互动恢复期。这段时间忽略新的身体单击和摸头候选，防止动画尾部的误触在恢复待机后排队播放；双击显示模式切换和窗口拖拽不受限制。双击识别仍会取消第一次待决单击，因此恢复期不会把双击拆成身体单击。

### 9.1 屏幕边缘躲藏

- 单纯把人物画面贴到左边缘、右边缘或任务栏上方时只执行贴边摆放，不进入躲藏；继续向屏幕外拖过约 28 DIP 才视为明确的躲藏意图，并在尚未松手前切换为对应动画预演。顶部不触发。
- 边缘预演开始后继续使用进入预演前的拖拽人物边界计算越界深度，不因“完整全身”和“偷看/闪亮登场”素材尺寸不同而改变判定；退出门槛为约 14 DIP，形成 14 DIP 回差，避免鼠标停在临界位置时反复切换图片。
- 左右边缘使用“十二周年·偷看”：松手后以原速播放第 7～3 帧无文字收回段；鼠标悬停后以当前素材速度的 1.3 倍从第 3 帧完整正放到第 19 帧，逐步显示“偷看”文字并展开到素材中的完整人物。移出时不把文字倒放进墙内，而是回到第 7～3 帧收回段。
- 右侧使用原方向，左侧水平镜像，保证角色始终从对应屏幕内侧探头。
- “十二周年·偷看”原始官方 GIF 保持不变；资产编译阶段先把每帧统一缩为 240×240，再裁掉右侧人物外的大半墙体，得到 196×240 运行时帧并按 155×190 DIP 等比例显示。裁剪保留全部“偷看”文字、头发、脸、手和靠人物侧的一小段墙面，不把裁后画面横向拉伸回原宽度。
- 左右隐藏完成后只暴露裁后画面靠墙侧约 9.2%（约 14 DIP）的砖墙窄条，并按该裁剪区而非完整透明窗口对齐屏幕边缘和设置鼠标触发面；不再显示人工绘制的天依蓝三点条或整块宽墙。
- 底边使用“十二周年·闪亮登场”：收回以当前素材速度的 0.7 倍从没有文字的第 5 帧开始下钻到第 3 帧，钻出仍以原速使用第 3～7 帧效果；最终只裁出贴着任务栏上沿的猫耳/头发作为触发面。
- 边缘动画在同一播放段内改变方向时沿用当前帧，不回到动画首帧；由完整含字的左右展开切回隐藏时，为满足“收回不显示文字”，允许直接进入第 7 帧无文字收回段。动画结束后固定目标帧，不闪现另一轮的开头。
- 人物接近屏幕工作区底边约 80 DIP 时，控制岛切换到人物上方，并排在歌名/作者信息之上；离开底边后恢复人物下方布局。
- 从展开状态开始拖拽会立即退出边缘模式并恢复普通拖拽；边缘模式不显示音乐控制岛，也不接受身体点击。

## 10. 桌面文件拖放与回收站

桌宠注册为普通 Windows OLE 文件拖放目标。为避免全局 Shell Hook、鼠标 Hook 或资源管理器扩展，不监听文件在桌面任意位置开始拖动的瞬间；真实文件或文件夹进入桌宠窗口（包含人物上下为歌名和控制岛预留的透明区域）时，才开始互动：

1. `DragEnter`：播放一次“心律共鸣·给我”；动画走完后固定最后一帧，不循环，也不自动恢复待机；
2. 只有指针位于当前可见人物画面内并停留至少约 400 毫秒时才接受松手，防止只是路过桌宠就误投；
3. `DragLeave`：结束定格并恢复此前动画，不对文件做任何操作；
4. `Drop`：仅接受 Windows `CF_HDROP` 提供的真实本地文件系统路径；
5. 使用 Shell `IFileOperation` 配合允许撤销和回收站标志，将文件或文件夹移入 Windows 回收站；
6. 成功后播放一次“心律共鸣·OK”；处理期间不再播放“加载中摇摆”，只保留“给我”末帧和气泡文字；
7. 如果目标磁盘、网络位置或虚拟文件不支持回收站，则保留原文件并显示失败反馈，绝不退化成永久删除；
8. 不支持按住 Shift 永久删除，也不调用 `File.Delete`、`DeleteFile` 或绕过回收站的删除方式；
9. 文件操作期间桌宠不抢键盘焦点，原神等受保护应用位于前台时禁用文件接收区。

拖放本身视为用户对本次文件移动的明确操作。设置中仍提供总开关；首次开启时说明“松手到桌宠会把项目移入回收站”。文件夹和一次超过 10 个项目的批量拖放需要额外确认。

### 10.1 “吃文件”视觉候选（尚未接入运行时）

为了避免仅靠静态图片摇摆，候选流程改为复用官方表情中的真实动作片段：

1. 奔向桌面文件时使用收藏集“来喽”的前扑姿势，角色画面做轻微上下起伏，真正的位置变化由桌宠窗口沿桌面坐标移动完成；
2. 到达目标或文件松手到桌宠后，切换为洛天依 11 周年 QQ 动态表情“干饭”中的一轮完整拿起、送入口中和咀嚼片段；
3. 文件缩略图或文件类型图标作为独立图层向嘴边移动并缩小，动画结束后才显示 Windows 回收站的真实成功或失败结果；
4. 两套官方画风切换处使用约 120～180 毫秒交叉淡化，不额外生成新的洛天依人物画面。

对应候选预演位于 `候选素材_官方/10_新添加_文件吞食组合候选/`，当前只进入动画挑选器，需用户确认后才替换“给我 → OK”的正式反馈。

“用户在桌面自行删除文件后桌宠跑过去吃”的模式是独立后续功能：只能观察公开的桌面目录与 Shell 图标位置，不注入资源管理器、不安装全局 Hook，也不替用户再次删除。它只在能可靠匹配删除前图标位置时播放；无法可靠匹配时不猜测文件名或位置。

1. 桌面项目进入回收站或从桌面位置消失后，在其最近一次桌面图标中心生成一个悬浮小笼包。

6. 设置页可即时关闭此功能。全屏、原神等受保护游戏前台、锁屏或无法确认前台状态时不生成/继续追逐。
