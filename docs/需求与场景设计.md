# 洛天依桌宠：需求与场景设计

> 状态：草案 v0.1
>
> 更新日期：2026-08-30
>
> 本文只记录已经讨论确认的规则。其余动画映射等待继续挑选后补充。

## 1. 产品目标

桌宠是一个独立运行的 Windows 透明窗口。它通过待机、音乐、通知和鼠标互动表现状态，同时提供少量系统控制功能。

设计目标：

1. 不打断用户当前工作或游戏。
2. 动画有明确触发原因，避免无意义地频繁播放。
3. 用户的永久设置始终高于一次性动画的临时设置。
4. 所有外部应用联动都采用公开、低权限的 Windows 能力。
5. 场景和动画通过配置关联，后续更换素材不需要重写检测代码。

## 2. 动画调度模型

动画分为两类：

- **持续状态**：基础待机、随机待机、音乐舞蹈、睡眠、拖拽。
- **一次性反应**：启动问候、音量变化、切歌反馈、QQ/微信提醒、原神启动、错误和成功提示。

一次性反应播放结束后，重新计算当前持续状态，而不是固定回到待机。例如播放音乐时收到 QQ 消息，提醒结束后应继续跳舞。

每条场景规则至少包含：

- 事件来源；
- 动画标识；
- 优先级；
- 循环次数或最长时长；
- 是否允许鼠标互动中断；
- 冷却时间；
- 是否申请临时置顶；
- 播放结束后的恢复策略。

### 2.1 建议优先级

从高到低：

1. 用户正在拖拽或直接操作桌宠；
2. 系统锁屏、显示器关闭和程序退出；
3. 原神启动等明确的一次性场景；
4. QQ/微信提醒；
5. 音乐和音量操作反馈；
6. 时间问候；
7. 音乐持续舞蹈；
8. 随机待机；
9. 基础待机或睡眠。

用户拖拽始终可以中断普通反应动画，避免桌宠失去操控感。

### 2.2 通用失败反馈

操作失败或等待超时统一使用“心律共鸣·呜呜晃动”。该动效由静态表情叠加短促左右晃动生成，并同时显示简短气泡：

- 普通失败：“操作失败，请再试一次”；
- 等待超时：“等太久了，再试一次吧”；
- 网易云没有确认状态：“网易云没有响应”；
- 文件未能移入回收站：“没有放进回收站，文件还在原处”。

气泡只说明结果和下一步，不显示异常堆栈、完整文件路径或其它隐私信息。失败反馈播放一次后重新计算持续状态。

## 3. 置顶规则

用户设置和临时动画必须分开保存：

```text
实际置顶 = 用户永久置顶 || 当前存在临时置顶请求
```

临时动画结束时只撤销自己的临时请求，不能直接把窗口设置为非置顶。因此，用户原本选择置顶时，原神动画结束后仍然置顶。

桌宠窗口不得抢夺键盘焦点。全屏游戏位于前台时，默认取消普通通知的临时置顶；受保护游戏进入独占全屏后，原神启动反应可以提前结束或延后到桌面显示。

## 4. 网易云音乐

### 4.1 控制

第一阶段功能：

- 上一首；
- 下一首；
- 播放；
- 暂停或继续。

控制继续使用网易云音乐的全局快捷键，不接入网易云接口。快捷键由用户在网易云设置中配置，桌宠保存相同的按键组合。

受保护游戏位于前台时，安全模式禁止发送模拟键盘输入。此时按钮可以显示“游戏安全模式下已暂停快捷键”，或者要求用户使用真实键盘媒体键。

### 4.2 状态检测

- 使用 Windows Core Audio 定位网易云音乐的音频会话。
- 连续检测到有效声音后进入音乐状态。
- 短暂无声使用约 1.5 秒宽限，避免歌曲间隙造成动画频繁切换。
- 长时间无声或播放器退出后回到待机。
- 可选使用 Windows 系统媒体会话读取播放/暂停状态和歌曲变化；这不是网易云私有接口。

“快捷键已经发送”和“播放器已经改变状态”应分开处理。无法确认结果时只显示操作反馈，不显示误导性的成功提示。

### 4.3 已确认的播放反馈

- 每次从暂停或停止变为播放时，在“心律共鸣·享受音乐”和“九周年·音乐摇摆”中随机选择一个；
- 选中的动画作为本次播放会话的音乐持续动画循环，不再区分“开始播放动画”和“持续播放动画”；
- 暂停后再次继续播放时结束上一次选择，并重新从这两个候选中随机选择；
- “享受音乐”使用 0.5 倍播放速度，处理后的文件为 `assets/animations/processed/心律共鸣_享受音乐_0.5x.gif`；
- 音乐状态临时覆盖“嘿嘿”或完整全身显示，但不修改用户选择的显示模式；音乐停止后恢复此前选择；
- 上一首、下一首等操作如果需要等待播放器返回结果，使用“心律共鸣·加载中摇摆”；
- 加载动画只在等待超过约 400 毫秒后显示，避免正常切歌时闪烁；
- 等待成功结束后播放“心律共鸣·OK”；
- 暂停后播放“九周年·没睡醒呼吸”5 秒，然后回到基础待机；
- 如果用户在这 5 秒内再次点击播放，立即中断“没睡醒呼吸”，重新随机选择并循环一个音乐动画。

加载状态必须设置超时。超时后退出加载动画并进入待机或错误反馈，不能无限循环。

### 4.4 显示模式恢复约束

用户处于完整全身模式时，开始播放音乐会由本次随机选中的音乐动画临时覆盖；这只改变当前播放内容，不改变用户选择的完整全身模式。音乐停止后恢复完整全身待机。用户原本处于“嘿嘿”模式时同理恢复“嘿嘿”。音乐覆盖期间即使用户切换显示模式，也只更新被记住的用户选择，待音乐停止后再显示新选择。

## 5. 系统音量

桌宠同时提供控制和监听：

- 鼠标停在桌宠上滚动滚轮，调整系统主音量；
- 右键菜单可以提供音量滑块；
- 用户通过键盘、任务栏或耳机旋钮调整系统音量时，也触发桌宠反馈。

确认映射：

- 提高音量使用“心律共鸣·共鸣之声”原动画；
- 降低音量使用“心律共鸣·共鸣之声”的预处理倒放版本 `assets/animations/processed/心律共鸣_共鸣之声_倒放.gif`；
- 静音和解除静音暂时不播放动画，只更新音量气泡和静音图标。

连续音量变化需要防抖：快速调整期间只保持一个动画，并实时更新音量百分比；停止变化约 500 毫秒后结束。相同动画建议设置约 2 秒冷却，防止反复重播。

## 6. 待机与时间

建议默认阈值，之后允许用户调整：

- 没有播放音乐且没有其他事件：默认进入较小的“嘿嘿”迷你待机；用户双击后切换到官方模型版完整全身互动待机；
- 正在播放音乐且没有其他事件：循环本次播放会话随机选中的“享受音乐”或“音乐摇摆”；
- 45 秒～5 分钟：允许随机待机；
- 15 分钟以上且没有播放音乐：进入睡眠；
- 系统锁屏或显示器关闭：停止高帧率渲染。

长时间睡眠使用“十周年·晚安浮动”。检测到鼠标或键盘输入后，播放短暂苏醒动画，再重新计算当前状态。

启动时间段已经确认如下：

- 06:00（含）～12:00（不含）：播放“收藏集·早安浮动”，表达早上好；
- 12:00（含）～13:30（不含）：播放“十周年·干饭弹跳”；
- 13:30（含）～20:00（不含）：播放“十周年·摸鱼漂浮”，作为下午问候；
- 20:00（含）～次日 06:00（不含）：播放“代号洛天依·眠了呼吸”。

“眠了呼吸”此前没有在 34 个保留项中勾选，但原始文件仍在素材库中，现在补充为正式使用的动画。

时间问候只在启动或系统休眠恢复时触发一次，不应整点重复打扰。

### 6.1 用户主动退出

用户通过桌宠右键菜单选择“退出桌宠”时，播放一次“心律共鸣·裂开晃动”，约 0.7～0.85 秒后关闭程序。退出动画期间忽略重复退出请求。

Windows 关机、注销、进程崩溃或系统强制结束时不等待退出动画，以免阻塞系统流程；这些路径仍优先保存能够安全保存的状态。

## 7. 原神启动

确认行为：

1. 监听原神进程由未运行变为运行；
2. 播放“心律共鸣·你不许玩”三次；
3. 播放期间申请临时置顶，但不激活窗口；
4. 播放结束释放临时置顶；
5. 如果用户原本永久置顶，结束后继续置顶；
6. 同一个游戏进程生命周期只触发一次；
7. 全屏安全模式生效时可以提前结束、跳过置顶或延后显示。

默认进程名候选为 `YuanShen.exe` 和 `GenshinImpact.exe`，通过配置维护，不依赖窗口标题。

### 原神后台低频彩蛋

除启动反应外，新增“心律共鸣·拜托”作为原神持续运行期间的低频彩蛋：

1. 仅在原神进程仍存在、但当前前台进程不是原神时计时和显示；
2. 每个 60 分钟的后台活跃窗口随机选择第 5～55 分钟触发一次，并设置 45 分钟硬冷却，避免相邻时间窗出现连续弹出；
3. 到达触发时间时若原神已经回到前台或进入全屏，暂停显示并在重新进入后台后随机延后 5～15 分钟；
4. 在桌宠当前显示器的 Windows 工作区内随机选择位置，保留 24 像素安全边距，保证角色完整可见且不覆盖任务栏；
5. 临时移动到随机位置，播放“拜托”一次；动画结束后恢复此前的位置、持续动画和用户置顶设置；
6. 弹出窗口始终不激活、不抢焦点；原神前台时不申请临时置顶；
7. 原神进程结束、电脑锁屏或桌宠进入睡眠时取消尚未触发的计时。

这项彩蛋只读取进程是否存在以及 Windows 当前前台进程标识，不读取游戏内存、窗口画面、模块、线程或网络数据，也不向游戏发送任何输入。

## 8. QQ 与微信提醒

确认动画：**代号洛天依·好奇摇摆**。该素材右侧已有类似消息提示的图形，适合用作统一通知反应。

行为规则：

1. 仅在来源应用不位于前台时提醒；
2. 气泡只显示“QQ 有新消息”或“微信有新消息”；
3. 不读取发送者、群名或消息正文；
4. 3 秒内的重复通知合并；
5. 一次提醒默认播放一次好奇摇摆；
6. 普通桌面环境可以临时置顶约 2 秒，但不抢焦点；
7. 全屏游戏前台时不覆盖游戏，改为保存一个待查看标记；
8. 通知结束后回到此前的持续状态。

检测优先使用 Windows 通知访问能力，兼容任务栏窗口闪烁事件。如果系统通知、声音和任务栏闪烁全部关闭，则在不读取应用内部数据的前提下无法保证检测到消息。

## 9. 鼠标互动

桌宠具有两个显示模式：

- **迷你待机模式**：每次启动默认使用“心律共鸣·嘿嘿”，占用较小的桌面空间；
- **完整全身互动模式**：双击“嘿嘿”后切换到“官方模型·完整全身待机”，启用身体区域命中；再次双击完整全身角色后切回“嘿嘿”。

双击间隔默认不超过 300 毫秒。第一次单击需要短暂等待双击判定；确认不是双击后才分发身体区域互动。双击只切换模式，不同时播放单击动画。临时事件动画结束后回到事件前选中的显示模式；应用重新启动时仍默认从“嘿嘿”开始，不记忆上一次的全身模式。

完整全身互动模式使用透明像素命中，并划分左右眼、脸部、嘴部、头发/头顶、左右手、胸部、下体敏感区域、普通身体和左右脚。已经确认的映射如下：

- 点击左眼或右眼：播放一次“心律共鸣·心软软”；眼睛是脸部内部的更小命中区域，优先于脸部“啾啾”；
- 短按脸部或嘴部：播放一次“心律共鸣·啾啾”；
- 按住头发或头顶区域并往返移动，持续约 600 毫秒：判定为摸头，播放一次“心律共鸣·可爱”；
- 点击左手或右手：播放一次“十周年·击掌回弹”；
- 点击胸部或下体敏感区域：第一次播放一次“心律共鸣·重罪”；
- 在第一次胸部/下体点击后的 4 秒内，再次点击这两个区域中的任意一个：播放一次“心律共鸣·黑化”；
- 点击左脚或右脚：播放一次“十周年·糟了晃动”，不进入黑化重复点击判断；
- 点击没有被眼睛、脸/嘴、头顶、手、敏感区域或脚命中的普通身体部位：从“十周年·旋转舞”“九周年·点赞动作”“八周年·点赞动作”“心律共鸣·我推”“心律共鸣·真好”中随机播放一次，并避免连续两次选中同一动画；
- “心律共鸣·可爱”不加入普通身体随机池，因为它已经固定用于摸头；
- “黑化”触发后进入 10 秒敏感区域冷却，期间不重复播放黑化，避免连续刷屏；
- 滚轮：调整系统音量；
- 右键：打开设置菜单；
- 在“嘿嘿”迷你模式按住左键并移动超过约 6 像素：进入拖拽并自动切换为“心律共鸣·膨胀”循环；
- 在完整全身互动模式进入拖拽：保持当前完整全身待机动画，不替换为“膨胀”，仅让窗口跟随鼠标并叠加轻微倾斜；
- “嘿嘿”迷你模式松开鼠标左键：播放一次“代号洛天依·降落弹跳”并叠加弹簧位移，随后重新计算持续状态；
- 完整全身互动模式松开鼠标左键：不播放降落动画，直接恢复完整全身待机；如果拖拽前存在音乐等持续状态，则平滑恢复该状态。

命中优先级为：窗口拖拽判定 > 双击模式切换 > 摸头手势 > 最小身体区域。眼睛命中优先于脸部；鼠标移动超过 6 像素后不再把松手识别成身体点击；脸部与头顶重叠时，短按脸/嘴触发“啾啾”，按住并抚摸头顶才触发“可爱”。胸部和下体共用同一个 4 秒重复点击计时器，双脚和普通身体不使用该计时器。

只有“嘿嘿”迷你模式松手后播放一次“代号洛天依·降落弹跳”，随后返回拖拽前状态；落地时在素材外层叠加一次弹簧位移。完整全身互动模式松手后不播放降落，直接恢复拖拽前持续状态。

身体区域反应动画结束后，进入 800 毫秒身体互动恢复期。这段时间忽略新的身体单击和摸头候选，防止动画尾部的误触在恢复待机后排队播放；双击显示模式切换和窗口拖拽不受限制。双击识别仍会取消第一次待决单击，因此恢复期不会把双击拆成身体单击。

## 10. 桌面文件拖放与回收站

桌宠注册为普通 Windows OLE 文件拖放目标。为避免全局 Shell Hook 或鼠标 Hook，不监听文件在桌面任意位置开始拖动的瞬间；当真实文件或文件夹进入桌宠可见区域外扩约 72 像素的接收区时，才开始互动：

1. `DragEnter`：播放“心律共鸣·给我”，显示明确的回收站投放高亮；
2. 文件需要在接收区停留至少约 400 毫秒，防止只是路过桌宠就误投；
3. `DragLeave`：取消高亮，恢复此前动画，不对文件做任何操作；
4. `Drop`：仅接受 Windows `CF_HDROP` 提供的真实本地文件系统路径；
5. 使用 Shell `IFileOperation` 配合允许撤销和回收站标志，将文件或文件夹移入 Windows 回收站；
6. 成功后播放一次“心律共鸣·OK”；操作超过 400 毫秒时可暂时播放“加载中摇摆”；
7. 如果目标磁盘、网络位置或虚拟文件不支持回收站，则保留原文件并显示失败反馈，绝不退化成永久删除；
8. 不支持按住 Shift 永久删除，也不调用 `File.Delete`、`DeleteFile` 或绕过回收站的删除方式；
9. 文件操作期间桌宠不抢键盘焦点，原神等受保护应用位于前台时禁用文件接收区。

拖放本身视为用户对本次文件移动的明确操作。设置中仍提供总开关；首次开启时说明“松手到桌宠会把项目移入回收站”。文件夹和一次超过 10 个项目的批量拖放需要额外确认。
