## 1. 产品目标

桌宠是一个独立运行的 Windows 透明窗口。它通过待机、音乐、通知和鼠标互动表现状态，同时提供少量系统控制功能。

设计目标：

1. 不打断用户当前工作或游戏。
2. 动画有明确触发原因，避免无意义地频繁播放。
3. 用户的永久设置始终高于一次性动画的临时设置。
4. 所有外部应用联动都采用公开、低权限的 Windows 能力。
5. 场景和动画通过配置关联，后续更换素材不需要重写检测代码。

## 2. 动画调度模型

动画分为两类：

- **持续状态**：基础待机、随机待机、音乐舞蹈、睡眠、拖拽。
- **限时反应**：时间问候持续 10 秒且可被用户输入或音乐打断；音量变化、切歌反馈、原神启动、错误和成功提示按各自时长结束。

一次性反应播放结束后，重新计算当前持续状态，而不是固定回到待机。QQ／微信提醒独立于动画状态，播放音乐时收到消息仍继续跳舞。

每条场景规则至少包含：

- 事件来源；
- 动画标识；
- 优先级；
- 循环次数或最长时长；
- 是否允许鼠标互动中断；
- 冷却时间；
- 是否申请临时置顶；
- 播放结束后的恢复策略。

### 2.1 建议优先级

从高到低：

1. 用户正在拖拽或直接操作桌宠；
2. 系统锁屏、显示器关闭和程序退出；
3. 原神启动等明确的一次性场景；
4. 其它普通一次性反馈（QQ／微信提醒不参与动画抢占）；
5. 音乐和音量操作反馈；
6. 时间问候；
7. 音乐持续舞蹈；
8. 随机待机；
9. 基础待机或睡眠。

用户拖拽始终可以中断普通反应动画，避免桌宠失去操控感。

### 2.2 通用失败反馈

普通操作失败或等待超时只显示原因气泡并恢复待机或此前持续状态，不播放“心律共鸣·呜呜晃动”。失败气泡包括：

- 普通失败：“操作失败，请再试一次”；
- 等待超时：“等太久了，再试一次吧”；
- 网易云没有确认状态：“网易云没有响应”；
- 文件未能移入回收站：“没有放进回收站，文件还在原处”。

气泡只说明结果和下一步，不显示异常堆栈、完整文件路径或其它隐私信息。失败反馈播放一次后重新计算持续状态。

## 3. 置顶规则

用户设置和临时动画必须分开保存：

```text
实际置顶 = 用户永久置顶 || 当前存在临时置顶请求
```

临时动画结束时只撤销自己的临时请求，不能直接把窗口设置为非置顶。因此，用户原本选择置顶时，原神动画结束后仍然置顶。

桌宠窗口不得抢夺键盘焦点。全屏游戏位于前台时，默认取消普通通知的临时置顶；受保护游戏进入独占全屏后，原神启动反应可以提前结束或延后到桌面显示。

## 4. 网易云音乐

### 4.1 控制

第一阶段功能：

- 上一首；
- 下一首；
- 播放；
- 暂停或继续。

控制不接入网易云私有接口。上一首、播放/暂停和下一首使用网易云设置页可配置的全局
快捷键，桌宠通过 `SendInput` 模拟同一组合键。不得再向窗口投递 `WM_APPCOMMAND`：该消息
未被目标窗口完整消费时会进入 Windows Shell 的媒体命令链，并可能弹出系统媒体浮窗。

当前默认组合与用户本机网易云设置页显示的一致：上一首 `Ctrl+Alt+Left`、
播放/暂停 `Ctrl+Alt+P`、下一首 `Ctrl+Alt+Right`。
用户需要保持网易云中的全局快捷键与桌宠配置一致；默认组合不应被当作网易云所有版本
都固定不变的私有协议。命令发出后仍用 Core Audio 和曲名变化确认结果，不把按键发送成功
误报为播放器已经响应。

音乐悬浮岛默认关闭，由桌宠右键菜单的“显示音乐悬浮岛”统一开关并持久化；关闭时歌名、播放控制与网易云音量全部隐藏，不留下小播放按钮，播放、暂停、切歌和异步刷新都不能自动重新开启。不存在暂停 10 分钟的自动收起规则。开关不影响音乐检测和人物听歌动画。

用户勾选“显示音乐悬浮岛”后，鼠标移入桌宠时，在角色动画正下方的独立预留区域显示
天依蓝玻璃质感控制岛，依次显示上一首、播放/暂停、下一首和网易云独立音量；品牌主色使用
`#66CCFF`，图标采用可随 DPI 清晰缩放的矢量路径。控制岛不覆盖角色、表情文字或身体
交互区，从下方轻微上浮淡入；鼠标移出桌宠后继续保留 5 秒再淡出，未悬停时完全隐藏且不
参与命中。播放按钮使用独立于人物动画宽限的快速状态：桌宠成功发送播放/暂停快捷键后立即切换图标，网易云外部停止时连续约 0.75 秒静音即更新图标；人物音乐动画仍使用完整 5 秒宽限。最右侧
扬声器按钮使用实心天依蓝，点击后在按钮正上方向上展开竖向滑杆；其余媒体按钮的工具提示
展示当前配置的全局快捷键。

当 `cloudmusic.exe` 尚未运行时，用户点击播放/暂停按钮不再对空气发送快捷键。桌宠先通过
Windows 注册的 App Paths 定位并启动网易云，定位失败时只检查几个明确的常见安装目录，
不扫描磁盘。等待阶段静止显示“心律共鸣·加载中”原始单帧图片，不附加摇摆、呼吸或位移，
并持续显示“正在打开网易云音乐”的文字。冷启动至少等待 2 秒，并优先等到 Windows 已能
读取网易云当前曲目；若 10 秒仍没有曲目信息则使用超时兜底。若启动请求返回成功但 3 秒后
仍没有可控制窗口，桌宠最多自动重试两次；准备好后只发送一次全局播放/暂停快捷键。Core Audio 真正检测到有声后结束
“加载中”，先播放一次“心律共鸣·OK”，再进入本首歌曲对应的音乐持续动画。整个冷启动
最多等待 30 秒。启动、控制或切歌超时只显示明确的文字提示并恢复待机/此前持续状态，
不再请求“心律共鸣·呜呜”，也不显示“动画素材暂时不可用”占位。网易云只有
存在可交互主窗口时才视为已经运行并保持现有播放/暂停流程；退出主界面后即使仍残留无窗口
的后台子进程，再次点击播放/暂停也会重新启动网易云，而不是向残留进程发送无效快捷键。

音乐悬浮岛已开启时，鼠标移入桌宠，角色动画正上方同时显示当前歌曲名称；无曲目信息时显示简短的“未在播放”；有歌手信息时以较小字号显示在
下一行。桌宠发起上一首或下一首后先显示“正在切换歌曲”，检测到曲目变化后显示新歌名
约 5 秒。用户从网易云或其它设备直接切歌时，只要 Windows 可观察到标题变化，也显示
同样的短暂提示。歌名区域独立预留 52 DIP，不覆盖角色。

受保护游戏位于前台时，安全模式禁止发送模拟键盘输入。此时按钮可以显示“游戏安全模式下已暂停快捷键”，或者要求用户使用真实键盘媒体键。

快捷键发送需要至少 350 毫秒间隔；发送前若前台进程无法安全确认，或用户正按住
相关按键及 Ctrl/Alt/Shift/Windows 修饰键，本次操作直接取消。桌宠只释放本次
自己按下的键，不校正、不接管用户原有键盘状态。

### 4.2 状态检测

- 使用 Windows Core Audio 定位网易云音乐的音频会话。
- 连续检测到有效声音后进入音乐状态。
- 普通短暂无声或音频会话在切歌时短暂重建，人物动画使用约 5.0 秒宽限；这段时间保持当前音乐动画，不闪回待机。播放按钮另用 0.75 秒连续静音门槛，外部暂停通常在 0.75～1 秒内显示播放图标；桌宠成功发送播放/暂停快捷键时先即时切换按钮，并以 2 秒确认窗等待 Core Audio，若命令没有真正生效则按可靠采样自动纠正。用户亲自在桌宠上点击暂停后，人物状态仍以首次静音立即确认，不额外等待完整宽限。
- 连续超过 5 秒无声或会话缺失后回到待机；桌宠发起上一首/下一首时另有最长 15 秒的加载保护，曲名变化可先播放一次 OK，但音乐动画保持到新声音恢复或保护超时。
- 可选使用 Windows 系统媒体会话读取播放/暂停状态和歌曲变化；这不是网易云私有接口。
- 曲目信息优先读取 Windows 系统媒体会话；当前网易云版本没有注册媒体会话时，只兜底
  读取 `cloudmusic.exe` 由 Windows 桌面管理器公开的主窗口标题，并按“歌曲 - 歌手”
  解析。不得读取进程内存、窗口正文或网易云私有文件。
- 曲名和歌手只在内存中短暂保存用于显示，不写入日志、不保存播放历史。

“快捷键已经发送”和“播放器已经改变状态”应分开处理。无法确认结果时只显示操作反馈，不显示误导性的成功提示。

### 4.3 已确认的播放反馈

- 设置页先提供“播放音乐时使用动画”总开关；关闭时保持当前桌宠外观，但媒体控制、歌名与网易云独立音量仍正常工作；
- 默认使用“智能分配”：普通或未知歌手固定播放“享受音乐”；包含“乐正绫”或 `Yuezheng Ling` 本人、`Official` 后缀或参与合唱时，持续循环“十二周年·打 call”；包含“洛天依”或 `Luo Tianyi` 本人、`Official` 后缀或参与合唱时，仍在“音乐摇摆”和“一键唱歌”两个彩蛋中随机选择。两位歌手同时出现时洛天依分流优先；
- 用户也可以固定“享受音乐”“音乐摇摆”或“一键唱歌”中的任意一项；固定后不再判断歌手，所有歌曲只播放这一种动画；
- 选中的动画作为当前播放会话的音乐持续动画循环，不再区分“开始播放动画”和“持续播放动画”；修改设置后如果正在播放音乐，立即切换到新规则解析出的动画；
- 循环候选由统一登记表提供，未来增加音乐动作时必须同步加入登记表与设置选项，不在窗口代码中散落特殊分支；
- “享受音乐”使用 0.5 倍播放速度；持续循环只使用文字已完整显示的稳定帧并往返闭环，人物在相邻动作间衔接，英文文字不随每轮循环反复入场；处理后的文件为 `assets/animations/processed/心律共鸣_享受音乐_无缝_0.5x.gif`；
- “一键唱歌”裁掉按键入场及左侧竖排文字，只保留角色主体和动态音符；稳定段使用源第 7→15→8 帧往返闭环，每帧 160 毫秒、每圈 2.56 秒，嘴型速度为旧版的 62.5%，末帧回到首帧也只跨相邻原动作，不用交叉淡化生成重影；
- 音乐状态临时覆盖 Q 版小人或完整全身显示，但不修改用户选择的显示模式；音乐停止后恢复此前选择；
- 上一首、下一首等操作等待播放器返回时只显示歌名区域的“正在切换歌曲…”文字，不播放“加载中”素材；加载期间即使声音或音频会话暂时消失，也保持当前音乐动画；“心律共鸣·加载中”的静态原图只用于网易云尚未运行时的冷启动等待；
- 加载动画只在等待超过约 400 毫秒后显示，避免正常切歌时闪烁；
- 等待成功结束后播放“心律共鸣·OK”；
- 暂停确认后立即停止音乐动画并恢复用户原本选择的 Q 版小人或完整全身模式；不播放“九周年·没睡醒呼吸”，也不保留一分钟暂停展示；
- 暂停后恢复播放时按用户选择的随机或固定规则重新解析音乐动画；暂停期间双击恢复正常的三种完整全身外观循环行为。

加载状态必须设置超时。超时后退出加载动画并进入待机或错误反馈，不能无限循环。

### 4.4 显示模式恢复约束

用户处于完整全身模式时，开始播放音乐会由当前随机或固定规则选中的音乐动画临时覆盖；这只改变当前播放内容，不改变用户选择的完整全身模式。音乐停止后恢复完整全身待机。用户原本处于 Q 版小人模式时同理恢复 Q 版小人。音乐覆盖期间即使用户切换显示模式，也只更新被记住的用户选择，待音乐停止后再显示新选择。

## 5. 音量控制与反馈

当前版本不控制或监听 Windows 系统主音量：设置窗口不显示系统主音量、滚轮开关、外部
主音量反馈开关或步长；桌宠窗口的滚轮也不写入默认输出设备。旧版配置中的系统主音量字段
只为兼容已有 `settings.json` 保留，不参与当前运行。

网易云独立音量只在悬浮控制岛提供竖向快捷滑杆，不在设置页重复出现。滑杆支持从轨道
任意位置按下后直接连续拖动，无需先抓住圆形滑块。它枚举所有活动输出设备，
用会话进程号匹配当前全部 `cloudmusic.exe` 实例，并通过 `ISimpleAudioVolume` 同步读写匹配
会话；这与 Windows 11 音量合成器中的应用音量属于同一层，不改变系统主音量、游戏、语音
或其它应用。网易云尚未播放并创建会话、会话正在重建或音频设备暂不可用时，滑杆禁用并
显示原因，用户可在播放后重新打开控制岛滑杆；任何失败都绝不能退回系统
主音量。控制岛只在悬浮时显示，不绑定滚轮或音量反馈动画。

设置窗口采用左侧分类导航：常规、音乐、通知、关于。常规页保留启动、置顶、双击换装和吃包子四项；音乐页依次显示播放动画总开关、带规则说明和预览的“智能分配”、以及三张“固定唯一动画”预览卡；通知页保留 QQ/微信提醒与 Windows 授权状态；关于页集中展示本地运行和隐私边界。左栏人物随页面切换：常规使用“心律共鸣·我推”，音乐使用“心律共鸣·真好”，通知使用“心律共鸣·天哪”，关于使用睁眼且保留原始 `Join Us!` 文字的“心律共鸣·加入我们”；四张均从官方透明 PNG 按可见边界等比裁入，不擦字、不重绘。页面专属台词保留且不附加角色署名。程序 EXE、设置窗口和系统托盘使用同一枚由晶蓝礼服全身图裁出的近景大头图标。

## 6. 待机与时间

建议默认阈值，之后允许用户调整：

- 没有播放音乐且没有其他事件：默认显示用户提供的 Q 版小人全身立绘；用户双击后切换到完整全身模式；
- 正在播放音乐且没有其他事件：默认按歌手智能分配；普通或未知歌手固定循环“享受音乐”，包含乐正绫时循环“十二周年·打 call”，包含洛天依时优先在“音乐摇摆”和裁掉按键入场后的“一键唱歌”中随机选择。关闭播放动画总开关时保持当前外观；固定三项中的任意一项时，所有歌手都只使用该动画；
- 45 秒～3 分钟：允许随机待机；
- 经典猫耳版且没有播放音乐时，连续无输入达到 2 分钟先播放“十周年生日·摸鱼一分钟”的 00:59→00:00 精确一分钟倒计时，画面开始后独立计时 60 秒进入“心律共鸣·嘿嘿”；晶蓝礼服版不使用倒计时，在无操作 1～5 分钟之间每轮随机播放一次同模型“打哈欠”，也不再进入“嘿嘿”；华裳长发版永不触发“嘿嘿”。单击等直接操作或离开对应外观后恢复当前外观；按住拖拽期间及松手后均保留经典猫耳版的“嘿嘿”，不把它误判成退出输入；
- 连续无输入达到 30 分钟且没有播放音乐：进入睡眠；每秒只读检查一次输入空闲时长；
- 系统锁屏或显示器关闭：停止高帧率渲染。

经典猫耳版长时间睡眠保留“代号洛天依·眠了呼吸”并持续低幅度呼吸，只在连续无输入 30 分钟后触发。晶蓝礼服版同样以 30 分钟为门槛，但改为 50:50 随机进入“睡觉”或“鸭子坐”：先播放进入段，再分别定格在睡觉第 220 帧闭眼卧姿或鸭子坐第 120 帧闭眼坐姿；两段长待机都必须保持人物原大小并为头侧装饰保留透明空间，睡觉横向卧姿还必须完整显示左右头发。桌面其它键鼠输入不自动解除，点击人物才播放剩余起身段并恢复待机，不能在鼠标按下时瞬间跳回默认待机。定格后立即且每 5 分钟按 60:35:5 随机循环 zzz、梦见包子、梦见乐正绫，允许连续相同；最小 Z 与最小云朵从人物头侧同一位置开始，装饰在屏幕右侧放不完整时镜像到左侧对称位置。zzz 全程保持淡蓝色，不能在飘高后变灰；点击唤醒时包子/乐正绫梦境先快速云朵消散，zzz 直接隐藏。华裳长发版不进入长睡眠。

启动时间段已经确认如下：

- 06:00（含）～12:00（不含）：播放“收藏集·早安浮动”，表达早上好；
- 12:00（含）～13:30（不含）：播放“十周年·干饭弹跳”；
- 13:30（含）～18:00（不含）：播放“十周年生日·来不及了！”原始动画，作为下午问候；保留文字、透明背景及每帧 100 毫秒的原生节奏；
- 18:00（含）～20:00（不含）：播放“十二周年·饿”，作为傍晚问候；
- 20:00（含）～次日 06:00（不含）：播放“十周年·晚安浮动”。

“眠了呼吸”与“晚安浮动”的用途已经调换：前者负责 30 分钟长睡眠，后者负责夜间启动问候。

五段时间问候在每次桌宠正式启动时触发，包括用户手动启动和 Windows 开机自启动，并持续展示 10 秒。如果桌宠一直运行，则在本地时间跨过 06:00、12:00、13:30、18:00 或 20:00 时自动展示新时段问候 10 秒；同一时段内不重复触发。任何直接用户输入可以打断当前问候。音乐持续动画始终优先：正在播放时先保留待补问候；音乐停止后再稳定等待 10 秒，仍处于该时间段才补播，等待或问候期间重新播放音乐则立即让位。Windows 解锁或电源恢复只恢复持续状态。

7 月 12 日（洛天依生日）和 12 月 12 日（用户生日）增加“十二周年·生日快乐”待机彩蛋。彩蛋只在没有音乐、拖拽或其它一次性反应的待机期间触发，每次随机等待 45～90 分钟，播放一次后重新随机，不能进入普通高频待机池。

### 6.1 用户主动退出

用户通过 Windows 系统托盘右键快捷面板点击“让天依休息（退出）”时直接进入退出流程，不再二次确认；随后，播放一次“心律共鸣·裂开晃动”，约 0.7～0.85 秒后关闭程序。退出动画期间忽略重复退出请求。桌宠人物右键仅提供第 8 节规定的常用菜单，不提供退出入口。

Windows 关机、注销、进程崩溃或系统强制结束时不等待退出动画，以免阻塞系统流程；这些路径仍优先保存能够安全保存的状态。

## 7. 原神启动

确认行为：

1. 监听原神进程由未运行变为运行；
2. 播放“心律共鸣·你不许玩”一次；动画结束后保持最后一帧，使动画与停留合计约 5 秒；
3. 播放期间申请临时置顶，但不激活窗口；
4. 播放结束释放临时置顶；
5. 如果用户原本永久置顶，结束后继续置顶；
6. 同一个游戏进程生命周期只触发一次；
7. 全屏安全模式生效时可以提前结束、跳过置顶或延后显示。

默认进程名候选为 `YuanShen.exe` 和 `GenshinImpact.exe`，通过配置维护，不依赖窗口标题。

### 原神后台低频彩蛋

除启动反应外，新增“心律共鸣·拜托”作为原神持续运行期间的低频彩蛋：

1. 仅在原神进程仍存在、但当前前台进程不是原神时计时和显示；
2. 每个 60 分钟的后台活跃窗口随机选择第 5～55 分钟触发一次，并设置 45 分钟硬冷却，避免相邻时间窗出现连续弹出；
3. 到达触发时间时若原神已经回到前台或进入全屏，暂停显示并在重新进入后台后随机延后 5～15 分钟；
4. 在桌宠当前显示器的 Windows 工作区内随机选择位置，保留 24 像素安全边距，保证角色完整可见且不覆盖任务栏；
5. 临时移动到随机位置，播放“拜托”一次；动画结束后恢复此前的位置、持续动画和用户置顶设置；
6. 弹出窗口始终不激活、不抢焦点；原神前台时不申请临时置顶；
7. 原神进程结束、电脑锁屏或桌宠进入睡眠时取消尚未触发的计时。

这项彩蛋只读取进程是否存在以及 Windows 当前前台进程标识，不读取游戏内存、窗口画面、模块、线程或网络数据，也不向游戏发送任何输入。

## 8. QQ 与微信提醒

采用文末“耳旁图标与共享会话列表”确认规则。消息到来时保留当前待机／音乐动画，默认仅更新微信／QQ 图标及本地待处理次数，正文由用户悬停或固定展开。微信在上、QQ 在下；无提醒隐藏并上移补位。三形态按实际 Alpha 轮廓分别校准，桌宠在右则提醒放左，在左则放右；拖动与展开期间固定方向，中线迟滞避免抖动。

QQ 主要使用授权的 Windows Toast；微信使用既有只读公开会话字段与任务栏闪烁回退。首次旧未读不补报、重复通知 ID 不再入列；无法读取详情时保留来源条目，不读取聊天历史、数据库或远程头像。名称与摘要只驻留本地待处理列表，不写文件或上传。

同会话合并，昵称与最新摘要各占一行，行计数合计为应用角标；最多 3 行高，更多内部滚动。数字是桌宠内待处理事件次数，不是客户端真实未读数。悬停 300 ms 打开、离开共同区域 500 ms 关闭；点击固定，再次点击或外部点击收起。跨间隙保持展开，阅读期间冻结已有行顺序与滚动位置。

收起不清空提醒；右键会话／应用可忽略／清空对应本地记录，不删除聊天也不修改客户端已读。微信公开字段确认已读时移除对应会话；QQ 不假定打开应用即读完全部会话。新事件仍可重新入列。全屏、锁屏、安全隐藏时隐藏交互窗口；待处理记录仍只保存在内存中。

## 9. 鼠标互动

桌宠正式使用同一完整全身显示槽，并在三套外观之间切换：

- **完整全身模式**：启动后使用当前保存的外观；双击按固定顺序循环三套外观，设置关闭循环后固定当前项；
  - “华裳长发版”（新完整全身待机，默认）是纯展示模式，不响应身体触摸；
  - “晶蓝礼服版”（Q 版小人全身待机新图）使用用户导出的独立多边形命中图、9 组同模型身体动作和专属打哈欠待机动作；未标注区域保持无反应；
  - “经典猫耳版”（上一版 Q 版小人全身待机）继续使用现有表情包互动，因为人物造型与表情包风格一致。

## 10. 桌面文件拖放与回收站

桌宠注册为普通 Windows OLE 文件拖放目标。为避免全局 Shell Hook、鼠标 Hook 或资源管理器扩展，不监听文件在任意目录开始拖动的瞬间；从桌面或任意资源管理器目录拖出的真实文件/文件夹进入桌宠窗口（包含人物上下为歌名和控制岛预留的透明区域）时，才开始互动。桌面外壳和最大化资源管理器都属于 `explorer.exe`，即使窗口覆盖整个屏幕也允许投放，不要求用户预先点击或激活桌宠：

1. `DragEnter`：播放一次“心律共鸣·给我”；动画走完后固定最后一帧，不循环，也不自动恢复待机；
2. 只有指针位于当前可见人物画面内并停留至少约 400 毫秒时才接受松手，防止只是路过桌宠就误投；
3. `DragLeave`：结束定格并恢复此前动画，不对文件做任何操作；
4. `Drop`：仅接受 Windows `CF_HDROP` 提供的真实本地文件系统路径；
5. 使用 Shell `IFileOperation` 配合允许撤销和回收站标志，将文件或文件夹移入 Windows 回收站；
6. 成功后结束“给我”定格并播放一次“心律共鸣·大成功”，随后恢复此前持续动画；不使用“心律共鸣·OK”，不生成包子，也不进入追逐或进食动画；
7. 如果目标磁盘、网络位置或虚拟文件不支持回收站，则保留原文件并显示失败反馈，绝不退化成永久删除；
8. 不支持按住 Shift 永久删除，也不调用 `File.Delete`、`DeleteFile` 或绕过回收站的删除方式；
9. 文件操作期间桌宠不抢键盘焦点，原神等受保护应用位于前台时禁用文件接收区。

拖放本身视为用户对本次文件移动的明确操作，并作为始终可用的快捷回收站入口。设置中的“桌面吃包子动画”只控制桌面项目消失后的追逐，不关闭快捷回收站。文件夹和一次超过 10 个项目的批量拖放需要额外确认。

### 10.1 “吃文件”历史视觉候选（已明确不用于快捷回收站）

为了避免仅靠静态图片摇摆，候选流程改为复用官方表情中的真实动作片段：

1. 奔向桌面文件时使用收藏集“来喽”的前扑姿势，角色画面做轻微上下起伏，真正的位置变化由桌宠窗口沿桌面坐标移动完成；
2. 旧方案曾考虑在文件松手到桌宠后切换为洛天依 11 周年 QQ 动态表情“干饭”；按当前决定，快捷回收站不采用这段演出，素材仅留作历史候选；
