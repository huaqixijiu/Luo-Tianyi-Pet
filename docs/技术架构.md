# 技术架构

> 状态：基线 v1
> 目标：让桌宠场景、动画和 Windows 联动可以独立测试和替换。

## 1. 技术基线

- 语言：C#；
- 运行时：源码默认以 .NET 10 构建，安装版同时兼容并默认发布为 .NET Framework 4.8；
- UI：WPF；
- 平台：完整安装版支持 Windows 10 22H2（19045）及 Windows 11；
- 测试：单元测试 + Windows 集成测试 + 视觉检查清单；
- 发布：默认为 .NET Framework 4.8 x64 完整 MSIX，保留 .NET 10 x64 自包含回退；
- 权限：普通用户。

选择 WPF 的原因是桌宠核心需求集中在透明无边框窗口、非激活置顶、像素命中、拖放和 Win32/COM 互操作。现代 Windows 能力通过独立的平台适配层接入，避免 UI 直接依赖系统 API。继续使用同一套 C#/WPF 源码而不重写桌宠；条件编译兼容层只补足 .NET Framework 4.8 缺少的基础 API，并由两套目标框架测试约束行为一致。

## 3. 核心状态模型

桌宠不是单一的“当前动画”，而是三个正交状态：

```text
用户显示模式
  compact / fullBodyInteractive

持续状态
  idle / mediumIdle / musicPlaying / sleeping / dragging / hiddenForSafety

一次性反应
  startup / interaction / mediaCommand / notification / genshin / volume / result
```

动画调度器根据三者和优先级生成唯一的 `PlaybackPlan`。一次性反应结束后重新求值，而不是写死返回某个动画。

M2 的实际核心实现为 `PetStateMachine`：一次性反应使用唯一令牌结束，旧动画回调不能清除后来覆盖它的反应；同源事件可按 `mergeKey` 合并并在完成后进入冷却；低优先级事件不会覆盖高优先级事件；过期事件直接丢弃。拖拽单独进入持续状态并记住拖拽前状态，拖拽期间收到音乐状态变化时只更新待恢复状态。

音乐播放状态同时保存当前播放会话选中的动画 ID。`MusicAnimationOptions.FixedOptions` 是可扩展的唯一循环候选登记表，当前登记“享受音乐”、“音乐摇摆”和“一键唱歌”；设置保存 `automatic-by-artist`、`none` 或某个已登记动画 ID。`MusicPlaybackAnimationSelector` 在自动模式接收公开媒体歌手字段：普通/未知歌手解析为“享受音乐”，包含洛天依本人或合唱时在“音乐摇摆/一键唱歌”中抽取；固定模式直接返回用户所选动画，不再判断歌手，因此它会成为所有歌曲的唯一画面。`none` 对应设置页播放动画总开关关闭，仍保留 `MusicPlaying` 业务状态和媒体控制，仅由 `PetVisualState` 回退解析当前外观。旧版 `EnableLuoTianyiSingingEasterEgg` 字段只为配置迁移保留，设置保存时归一为开启。设置保存、开始播放、暂停后继续或曲目身份变化都会重新解析。两项 GIF 派生均由可复现脚本裁掉一次性入场，原素材不覆盖；“一键唱歌”还在固定坐标带逐帧清除左侧 `一键唱歌` 竖排文字，角色与两侧动态音符不重绘，并把稳定段按源第 7→15→8 帧往返编排。编译脚本强制检查包含闭环边界在内的每次跳转都只相差一个源帧，每帧 160 毫秒、整圈 2.56 秒，相对旧版 100 毫秒节奏降速至 62.5%。未来新增音乐动作只需登记选项与歌手路由，不应在窗口事件中增加按序号判断。

事件流：

```text
Windows 事件或用户输入
        ↓
平台适配器生成领域事件
        ↓
场景规则过滤、去重、冷却与安全检查
        ↓
状态归约器更新三类状态
        ↓
动画调度器生成 PlaybackPlan
        ↓
WPF 窗口播放、定位、命中和恢复
```

## 4. 动画管线

原始 GIF、WebP、SVGA、PNG 和官方模型文件不直接散落在 UI 代码中引用。`AssetCompiler` 读取动画清单，输出统一的运行时元数据：

```text
id
sourcePath
runtimePath
canvasWidth / canvasHeight
frameDurations
loopPolicy
alphaBounds
anchor
contentHash
transformations
```

第一阶段先用一个 GIF、一个动态 WebP 和完整全身待机做原型。只有确认内存、透明度和帧时序后，才批量转换全部已选素材。处理后的每项资产必须保存来源路径、哈希和转换参数。

正式运行统一使用完整全身显示槽，并由 `AppearancePreferences.FullBodyStyle` 在 `official-v4-chibi-full-body-idle`、`user-chibi-crystal-full-body-idle`、`user-chibi-classic-full-body-idle` 三项间保存当前外观。双击按固定顺序循环，`EnableFullBodyStyleCycling=false` 时不再改变外观；旧 `user-chibi-compact-idle` 仅作为兼容资产保留。三套待机外观统一使用 220×238 DIP 显示槽。`ResolveFullBodyInteractionMode` 同步决定触摸策略：长发版禁用，晶蓝礼服版开放用户提供的同模型连续动作，经典猫耳版开放既有表情包互动；状态机只有在当前策略具备可执行素材时才开放身体命中。

晶蓝礼服源图的棋盘格是完全不透明的 RGB 内容，不是真 Alpha。当前 1205×1306 原图的灰格低至约 177，因此 `prepare_full_body_idle.py` 使用最低通道 160、低色差候选，从画布边缘洪泛背景，并允许用可审计的源像素矩形标记被发丝或薄纱线条围住的内部假背景；矩形内仍只清除背景候选，不擦除蓝黄装饰、深色轮廓或其它有色细节。本项目第二版使用左侧 `210,640,380,855` 与右侧 `900,640,1060,860` 两个源图区域。用户另明确要求补齐右侧发丝内一个针孔大小的透明缺口；脚本只在归一化坐标多边形 `[(359,315),(364,317),(366,334),(362,337),(359,333)]` 内以邻近不透明发色插值 117 个缺损像素，不做通用闭运算，因此左右两块大三角透明间隙保持不变。全部参数写入派生元数据。

桌宠局部指针素材保存在 `候选素材_官方/12_用户提供_鼠标指针`，`prepare_cursor_asset.py` 按原图 Alpha 边界裁切、缩入 64×64 透明画布并写出含热点的 32 位 Windows CUR，同时保留 PNG 预览、源/输出哈希和几何元数据。WPF 在当前 `PetImage` 的不透明像素上应用普通指向光标；Core `PetCursorResolver` 仅在身体互动启用且 `BodyHitMap` 命中 `HeadAndHair` 时返回摸头光标。主窗口载入同一普通指向光标后还会显式赋给媒体控制岛的上一首、播放/暂停、下一首、网易云独立音量按钮以及弹层整轨输入面，因此这些可点击区域不会使用系统箭头或上下调整光标。光标文件不可用时安全回退系统 Hand，不影响点击、双击或拖拽。

完整全身同模型动作候选由 `tools/animation_tools/make_full_body_action_candidates.py` 从 32 帧待机 WebP 确定性生成。变换以脚底附近为统一轴点，逐帧应用可复现的仿射位移、缩放和旋转，首尾帧严格回到同一源帧；输出仍为 480×520 透明动态 WebP。该流程只用于候选动作，不宣称具备 PMX 骨骼级局部控制；用户选定后才进入正式动画清单。

精细全身动作使用固定版本的便携式 Blender 4.5.13 LTS 和 MMD Tools 4.5.13，从仓库中的官方 PMX 直接导入材质、骨骼与表情。`blender_inspect_pmx.py` 输出可审计的骨骼/表情报告，`blender_make_drag_leg_flail.py` 以关键帧驱动双腿、膝、脚踝、躯干、手臂、头部和发辫，Eevee 透明渲染为 960×1040 PNG 序列，`pack_rendered_action.py` 再确定性缩为 480×520 无损动态 WebP，最后进入现有图集编译器。便携 Blender、插件、`.blend` 和中间帧只存放于 Git 忽略的 `.local-tools/`；动作脚本、源 PMX、派生 WebP、运行时图集和来源哈希进入仓库，可重复生成和审查。

运行时清单继续统一保存来源哈希、帧尺寸、逐帧时长和显示锚点；低体积或单帧素材保留透明 PNG 图集，通过 `CroppedBitmap` 显示。对 2 px/DIP 的高分辨率身体动作和吃包子序列，构建期改为质量 95、精确 Alpha 的动画 WebP：分辨率、帧数和时间轴不降，只利用前后帧相似性压缩。应用随包携带 SkiaSharp Win32 x64 解码器，不依赖目标电脑是否安装 Microsoft WebP Image Extensions；解码后仍转换为冻结的 WPF `Pbgra32 BitmapSource`，其余状态机和显示路径不分叉。`AnimationFramePlayer` 对解码帧使用 192 MiB LRU 上限，当前动作始终保留，离开的较大动作可回收，避免依次触发多套模型二动画后缓存无上限累积。全部资产由 `config/animation-sources.json` 和可复现脚本生成，官方原始素材不变。

不带 Alpha 的白底表情不能通过 GIF 调色板颜色编号直接指定透明色，因为人物内部的白色衣服、皮肤高光等可能被量化到同一编号。`prepare_music_idle_animations.py` 对“摸鱼一分钟”逐帧从画布四边进行近白色连通遍历，只把外部连通分量设为透明；编码完成后重新读取全部帧，若透明像素出现在受保护的内部区域则立即失败，避免再次生成“身体被扣空”的图集。

身体命中使用相对于完整全身逻辑画布的归一化区域，并先读取当前显示帧的 alpha 像素排除透明位置。经典猫耳版已按当前 480×520 立绘重新标定五官、手、敏感区域和双脚，小区域按眼睛、脸、手、敏感区域、脚、头发、普通身体的顺序优先命中。一次性表情动画播放期间关闭身体区域命中，但仍允许高优先级的窗口拖拽。开发菜单可显示与实际命中共用同一份坐标数据的调试叠层，避免显示框与真实判断漂移。

身体命中后的产品规则由 Core 层 `BodyInteractionResolver` 统一解析，窗口层不保存区域到动画的散落映射。解析器持有胸部/下体共享的 4 秒升级窗口和黑化后的 10 秒冷却；嘴部和脸部分离，普通身体固定播放“十二周年·抱抱”。摸头派生在编译期使用显式 `frameSequence` 把 10 帧重排为 28 帧连续往返并把帧时缩至 0.8 倍，运行时不再二次慢放；重罪、黑化分别在编译期形成约 0.8/0.6 倍有效速度。窗口收到播放决定后以 `PetStateMachine` 建立用户互动反应令牌；经典猫耳动作结束时由 `VisualSwapTransition.PlayFadeAsync` 在 110 ms 内淡出，完全不可见时恢复锚定待机，再用 170 ms 淡入。晶蓝礼服动作仍依靠同槽位图集自身的首尾混合直接恢复。

晶蓝礼服的十项运行时动作由 `prepare_crystal_interactions.py` 从 720×720 原始透明帧直接生成 440×476 RGBA 帧，再编码为质量 95、精确 Alpha 的动画 WebP，以固定 220×238 DIP 显示；这使 200% 桌宠比例仍有 1:1 运行采样，也不再把每一帧作为完整 PNG 图块重复存储。经典猫耳身体反应和带字请求小笼包素材由 `compile_animation_atlases.py` 按各自显示槽补足 2 px/DIP，使用预乘 Alpha Lanczos 和轻度边缘锐化后采用同一运行编码，不做生成式重绘。动画挑选器预览继续独立保持 240×260，避免非运行资源随运行清晰度一起膨胀。WPF 仍使用 `HighQuality` 位图缩放。

Windows 平台层通过公开 `GetLastInputInfo` 只读取距系统最后一次键鼠输入的时长。Core `IdleSceneResolver` 接受显式 `IdleSceneProfile`：华裳长发版没有中等待机或长睡眠；晶蓝礼服版无操作 5 分钟进入“嘿嘿”但不进入长睡眠；经典猫耳版在 2 分钟进入精确 60 秒“摸鱼一分钟”、3 分钟进入“嘿嘿”、30 分钟进入 `sleeping`。WPF 人物鼠标按下时会先把倒计时、“嘿嘿”或睡眠恢复为 `Idle`，因此拖拽也属于恢复输入。`CrystalYawnScheduler` 为每轮无操作生成 60～285 秒的单次随机门槛，只在晶蓝礼服版当前没有其它反应时播放一次 `crystal-yawn`。

启动时间问候由 Core `StartupTimeSceneResolver` 使用半开时间区间解析，06:00、12:00、
06:00、12:00、13:30、18:00、20:00 边界集中在 Core `TimeSceneTransitionTracker`。WPF 每秒观察本地时间；正式启动（包括 Windows 开机自启动）及跨边界时请求 10 秒、可取消的 `TimeGreeting` 反应。音乐有声、按钮播放预期或状态机音乐持续状态任一成立时都不启动问候；停歌后设置 10 秒资格延迟，避免切歌加载误判，期间重新有声会继续延后。左键人物输入和媒体控制输入可取消问候，音乐开始也会立即抢占；
媒体、通知或用户互动可按现有状态机优先级替换它，完成后恢复当前持续状态。四项静态官方
表情编译为单帧图集，并由 `BodyReactionMotion` 叠加浮动、弹跳或呼吸。

Windows 解锁与电源恢复由平台层 `WindowsSystemResumeSource` 订阅公开的
`SystemEvents.SessionSwitch` 和 `SystemEvents.PowerModeChanged`。Core
`SystemResumeEventGate` 把同一轮恢复在 5 秒内产生的重复事件合并；窗口只恢复当前应有的持续状态，不再播放“苏醒弹出”，也不激活、不置顶或改变用户显示模式。主动隐藏在屏幕边缘时保持隐藏，尊重用户的隐藏意图。

边缘躲藏由 Core `EdgeDockResolver.ResolveHideIntentByFractionWithHysteresis` 按当前外观的 `alphaBounds` 计算左、右、下三种越界比例，而不是使用透明窗口或整张画布。人物只与工作区边界相接时允许正常贴边，只有实际不透明人物宽度或高度至少四分之一已经越界才进入躲藏；进入预演后退回到六分之一以内才取消候选，且当前左右/下方候选在释放线之前保持锁定，屏幕角落不会因两个方向同时达标而抢占。经典猫耳版拖拽时虽然显示“膨胀”，判定和松手回正仍投影经典猫耳本体的 Alpha 边界；拖拽期间从膨胀切到偷看/闪亮登场预演时只改变 `PetImage`，保持模式三外窗边界不变，避免下一次鼠标事件因窗口缩放重新跨过门槛。拖拽越界空间以 96 DIP 为下限并随当前缩放后窗口尺寸增长，保证 50%～200% 下都能达到相同比例门槛；窗口围绕底部中心改变动画尺寸时允许透明边缘越过工作区，从而让真正可见的脚底或侧边精确贴屏。

`AnimationFramePlayer` 支持指定起止帧、固定单帧和单次范围播放速率，`AnimationFrameTimeline` 通过按速率缩放本次帧时长实现，不修改素材清单或其它使用场景。`EdgeDockFrameRouteResolver` 负责含字展开与无字收回的非对称路线。左右“偷看”以 1.3 倍速从第 3 帧展开到第 19 帧，完整保留“偷看”文字与人物，收回第 7→3 帧保持原速；底部“闪亮登场”展开第 3→7 帧保持原速，收回第 5→3 帧使用 0.7 倍速。同一段内改变方向会沿用当前帧，跨含字/无字段则回到无字收回起点。

经典猫耳版与拖拽“膨胀”都使用 220×238 DIP 的 `PetImage` 显示尺寸。`tools/animation_tools/prepare_textless_expand.py` 从官方 162×162 GIF 逐帧识别顶部橙色标题像素并将其 Alpha 清零，同时显式保护人物嘴部区域，输出无损 APNG 与来源、阈值、逐帧清理数量和哈希；人物、嘴巴、腮红、头饰和黄色星星不重新编码或重绘。编译器再通过 `padAfterResize` 把无文字帧放进 162×175 透明画布，而不是拉伸原图；两者切换时主窗口宽高保持一致。拖拽期间窗口边界约束仍借用经典猫耳版清单的 Alpha 留白，避免膨胀画面更宽时把已经贴边的角色推回屏幕内。

资产编译器支持可选的 `cropAfterResize: [left, top, right, bottom]`。它先按既有规则统一帧尺寸，再校验同一个裁剪矩形位于缩放后边界内并应用到所有帧；清单记录裁后帧宽、高、透明边界和新哈希，原始官方文件不变。“十二周年·偷看”由 240×240 裁为 186×240，运行时显示宽度同步为 147 DIP，保持人物纵向比例；裁后每帧只剩约 10 像素墙体，不再依赖完全隐藏阶段的显示层裁剪来掩盖动画中的厚墙。

隐藏完成后 `PetImage.Clip` 只暴露派生素材中的砖墙或猫耳/头发，透明按钮仅覆盖同一可见区域。左右隐藏从新的 186 像素宽“偷看”画面约 95.2% 处起裁约 4.8%，继续只显示约 7 DIP 墙面并避开人物发梢。窗口位置按缩窄后的真实裁剪边界重新贴合工作区，而不是按完整图片边界计算，因此右侧不会留下透明缝，左侧镜像后也能精确贴边。左边缘只在显示层水平镜像，不生成第二份素材。

身体部位反应以 `ReactionRequest.BlocksDisplayModeToggle=true` 标记；`PetStateMachine.IsDisplayModeToggleBlocked` 只在该反应令牌仍为当前活动反应时返回 true，WPF 双击入口据此忽略切换。反应自然完成、过期、被替换或取消时锁随活动反应一同清除，避免留下永久锁。身体反应完成后再由 `PetStateMachine.SuppressBodyInteractions` 建立 800 毫秒恢复期，`Resolve` 在此期间只把 `BodyRegionInteractionsEnabled` 设为 false；延迟单击和摸头会被抑制，但双击切换与窗口拖拽在恢复期内恢复可用。重复设置恢复期只会延长截止时间，不会意外缩短。

经典猫耳版的左右差异由 `BodyInteractionDecision.MirrorHorizontally` 携带到 WPF 播放层。右眼、右手、左脚只在动画切换被遮罩的中点修改 `PetDirectionTransform`，恢复待机或开始拖拽时复位，不复制图集，也不会把镜像遗留给后续动画。脸部继续使用用户已绘制的单个 `Face` 多边形，分发时以归一化点击横坐标 0.5 区分左右。`BodyInteractionResolver` 分别维护眼睛和脚部 4 秒成对计数器：第二次可跨左右侧，但其它身体点击会打断，第二次播放完成后下一次重新视为第一次。

头发按下后由独立 `PettingGestureRecognizer` 暂缓普通 6 DIP 拖拽：持续至少 350 毫秒、水平累计移动达到 24 DIP 且至少一次换向即可完成摸头；从起点单向位移达到 24 DIP、离开头部矩形或落到透明像素时立即取消候选并把当前位置交回窗口拖拽判定。头顶短按另有同动画兜底。完成摸头后消费本次按压，松手不会再补发身体单击或双击。

## 5. 平台适配器

### 音频与媒体

- Core Audio/WASAPI：定位 `cloudmusic.exe` 会话读取有声状态，并在设置页通过独立应用会话音量读写；不访问系统主音量；
- 系统媒体会话：在可用时读取曲名、歌手并辅助确认切歌结果；切歌期间只显示等待文字，不播放“加载中摇摆”，标题变化优先确认，Core Audio 静音后恢复作为辅助确认，15 秒超时失败关闭；
- 网易云窗口标题兜底：仅在系统媒体会话不存在时读取目标进程的顶层标题栏；
- 网易云控制：只使用用户配置的网易云全局快捷键并以公开状态确认结果；不发送会触发 Windows 系统媒体浮窗的 `WM_APPCOMMAND`；受保护应用前台时禁用。
- 网易云冷启动：Core `IMediaApplicationLauncher` 返回结构化启动结果，Windows
  `WindowsMediaApplicationLauncher` 以目标进程是否拥有可交互主窗口判断应用是否可控制，
  不把退出后残留的无窗口 GPU/渲染/常驻进程误判为已启动；需要启动时再检查前台安全状态，
  从 App Paths 或明确的常见安装目录解析 `cloudmusic.exe` 并由 Shell 启动；不扫描磁盘、
  不使用私有协议。

M3 的第一条纵向链路使用 `LuoTianyiPet.Platform.Windows.CoreAudioSessionProbe`
通过公开的 Windows Core Audio 会话接口，只读取默认多媒体输出设备中与
`cloudmusic.exe` 进程号对应的会话峰值。平台层使用 MIT 许可的
`NAudio.Wasapi` 3.0.1 作为薄封装，不解码、录制或传输音频，也不读取目标进程
内存、模块和窗口内容。Core 层 `MusicAudioActivityDetector` 以 0.001 峰值作为
默认有声阈值，每 250 毫秒采样；检测到有声立即进入播放，人物持续状态在普通外部变化连续 5.0 秒无声或会话缺失后才退出，以覆盖网易云切歌加载和会话重建。`MusicPlaybackIndicatorTracker` 单独维护控制岛按钮：连续 750 毫秒静音后切为播放图标，因此外部暂停最迟约一个采样周期后可见；桌宠成功发送播放/暂停命令时按钮先乐观切换并保持最多 2 秒，可靠音频采样确认后结束预期，命令未生效则自动纠正。桌宠请求暂停的人物状态仍在首个可靠静音样本立即确认。上一首/下一首的已知加载保护期间暂停按钮快速跟踪器不消费静音，避免切歌加载时误闪。一次临时探测失败保留原状态并重试。

运行时把检测功能作为 `settings.json` 中可独立关闭的 `media` 配置；旧版没有
`media` 节点的配置会补入安全默认值。预览和 QA 参数不启动真实会话探测，保证
确定性验证不受用户播放器状态影响。音乐事件只更新状态机：身体反应优先播放，
拖拽期间只更新拖拽后的恢复状态；日志不记录进程号、峰值、歌曲或窗口信息。

曲目信息由 Core 的 `IMediaTrackInfoSource` 抽象，Windows 实现
`SystemMediaTrackInfoSource` 每秒读取一次。它先枚举
`GlobalSystemMediaTransportControlsSessionManager`，按 `SourceAppUserModelId` 限定
网易云会话并调用 `TryGetMediaPropertiesAsync`；若当前网易云版本没有注册系统媒体会话，
再读取 `cloudmusic.exe` 顶层主窗口标题并按“歌曲 - 歌手”保守解析。标题会折叠控制字符
和多余空白，并限制为 80 个字符；歌手限制为 60 个字符。两者只保存在内存，不写日志。

主窗口顶部为 `TrackInfoBubble` 预留 52 DIP：悬停时显示缓存并立即刷新，检测到曲目变化
或桌宠发起上一首/下一首时保留 5 秒；没有可用信息时仅在悬停时显示降级说明。媒体控制
通常位于动画下方 58 DIP 区域。`AccessoryLayout` 根据人物可见边界与工作区上下边缘的
80 DIP 距离在三种布局间切换：中部为歌名在人物上、控制岛在人物下；顶部为人物在上、
歌名和控制岛依次堆叠在下；底部为歌名和控制岛依次堆叠在上、人物在下。两个堆叠布局
始终保持歌名/作者在播放控制上方，并在切换时补偿窗口坐标，使人物屏幕位置不跳动。
顶部拖拽下限按当前动画 Alpha 可见边界而非整个透明窗口计算，因此附件区可移出工作区而
人物像素仍能贴齐顶边；底部继续按实际可见图像贴齐任务栏上沿。

媒体控制由 Core 的 `IMediaCommandSender` 返回结构化结果和投递方式。Windows 平台适配器
`WindowsMediaCommandSender` 直接解析用户配置并通过 `SendInput` 发送网易云全局快捷键，
不再投递会触发 Windows Shell 媒体浮窗的 `WM_APPCOMMAND`。默认组合为
上一首 `Ctrl+Alt+Left`、播放/暂停 `Ctrl+Alt+P`、下一首 `Ctrl+Alt+Right`，发送
最小间隔 350 毫秒。适配器只查询前台窗口所属进程名并与受保护名单比较；查询失败、
受保护应用前台、相关实体键仍按下、配置无效、频率过高或系统未接受完整输入时均不
发送或报告失败。窗口只显示结果气泡并记录命令类别与结果，不记录前台进程名和用户
按键内容；“已发送”不等同于“播放器已响应”。播放/暂停按钮只把已发送的切换当作最多 2 秒的 UI 预期，不把它记录为播放器成功；采样不符时会回正。上一首/下一首发送后设置独立的 15 秒播放保持标志；音频静音或会话重建不把持续状态切回 `Idle`，曲名变化可先显示新曲并播放 OK，声音恢复后解除保持，超时才失败关闭。暂停确认后直接把持续状态恢复为 `Idle`，停止音乐动画并显示用户已选择的 Q 版小人或完整全身外观；不设置独立暂停状态和计时器，也不拦截双击。恢复播放时再按随机或固定规则进入新的音乐持续动画。

媒体控制入口是主透明窗口内的 `MediaControls` 区域，而不是右键菜单。它位于角色动画
正下方并预留 58 DIP 高度，仅在鼠标悬停或 QA 预览时可见：前三个 WPF 按钮调用同一
`IMediaCommandSender`，最右侧扬声器按钮打开 `CloudMusicVolumePopup` 竖向滑杆。角色视觉层和音乐切换闪白层均为底部控制区留出相同空间，因此
控制岛不会覆盖角色、表情文字或身体命中区域。
`MediaControlsVisibilityMotion` 负责 170 毫秒上浮淡入和 120 毫秒淡出；窗口层为控制岛和
歌名岛统一提供鼠标离开后的 5 秒宽限，重新移入会取消倒计时。隐藏期间元素为 `Collapsed`
且关闭命中，不会影响身体点击或拖拽。播放/暂停
按钮在目标进程不存在时进入最多 30 秒的冷启动反应：运行时播放已有
`resonance-loading-sway` 单帧图集并保持气泡文字，图片自身不叠加程序摇摆。启动至少 2 秒并
优先等待曲目信息可读，10 秒仍未准备好才兜底；若 3 秒内仍没有可控制窗口则最多自动重试
两次，窗口就绪后只发送一次播放/暂停快捷键。`MusicAudioActivityDetector` 确认有声时结束加载反应，先播放 `resonance-ok`，其下层
状态机已经解析为当前歌曲的音乐持续动画。启动、控制或等待失败只显示文字原因并恢复
待机或此前持续状态，不请求 `resonance-cry-shake`，因此也不会进入通用缺素材占位；目标
进程已经存在时完全复用快捷键流程。
矢量图标仍只跟随已确认的 Core Audio 状态变化；桌宠发起暂停时使用上述快速确认窗口缩短图标反馈，而不是在模拟按键刚发出时盲目翻转。

控制岛的组件样式在项目 XAML 内维护，使用 `#66CCFF` 品牌主色、蓝色玻璃表面和本地
矢量 `Path` 图标。项目参考 MahApps 圆形按钮与 IconPacks 的组件模式，但不为四个按钮
引入 MaterialDesignThemes、WPF-UI 或完整 UI 框架，避免增加十几 MB 依赖和额外主题
资源；按钮仍有独立悬浮、按下、禁用和工具提示状态。

低频桌面设置由 `TrayIconController` 使用 Windows 通知区域图标承载：打开设置、始终置顶、
开机自启动和退出。`WindowsStartupRegistrationService` 只操作当前用户 Run 项中的单一产品值；
便携版写入带 `--portable` 的绝对路径，MSIX 版写入稳定的 AppsFolder 激活命令。默认关闭，只有
用户在设置页或托盘中主动切换时才写入，关闭后仅删除该产品值。

托盘菜单另用 `ToolStripControlHost` 承载 50%～200% 的 WinForms `TrackBar`。`ValueChanged`
只在 WPF Dispatcher 上更新当前 `PetImage` 的显示宽高和透明窗口边界，`MouseUp`/键盘确认后才
保存，避免拖动过程中频繁写设置文件。倍率统一乘到动画清单的 `displayWidth/displayHeight`，
身体命中仍使用归一化坐标，因此无需按 DPI 或缩放比例重写区域；媒体控制岛保持固定可点击尺寸。

文件追逐的视觉样式由当前 `AppearancePreferences.FullBodyStyle` 自动解析：华裳长发版和晶蓝礼服版使用“甜笑寻包版”，经典猫耳版使用“元气追包版”。`BunEatingStyle` 仅为旧 JSON 兼容字段，规范化时会按当前外观重算。
V1 和 V2 都通过 `assets/animations/processed/*.meta.json` 中的 `catalogAnimations` 注册为预编译
图集；`compile_animation_atlases.py` 在普通素材编译结束后读取这些元数据并重建清单，避免未来
重新编译时丢失两套已经确认的手工 Alpha 序列。V2 源 PNG 的透明像素仍带有不可见的粉棕色 RGB，处理器必须使用 `transparent` 输入模式原样保留 Alpha，禁止依据隐藏 RGB 再次抠色。

系统主音量能力已经从 WPF 正式运行路径移除：应用不创建 `ISystemVolumeService`，窗口不
订阅端点通知，设置页不显示主音量及反馈控件，桌宠滚轮也没有音量行为。旧版领域模型、
平台适配器和 JSON 字段暂留作兼容与测试资料，但没有生产调用者，后续版本可在配置迁移完成
后清理。

网易云独立音量由 `IApplicationVolumeService` 定义领域边界，Windows 适配器每次读取或写入时
枚举所有活动的 Render 输出设备，用 `IAudioSessionControl2::GetProcessId` 匹配全部
`cloudmusic.exe` PID，再通过 `ISimpleAudioVolume` 同步读写所有匹配会话。这既适配 Windows 11
把不同应用路由到不同输出设备的情况，也自然处理网易云会话重建。该能力只保留在悬浮控制岛，
设置窗口不再重复显示音量卡片；打开弹层时重新读取当前会话值。WPF `Slider` 只负责渲染，
其上方同尺寸的透明 `CloudMusicVolumeDragSurface` 统一接收圆点、已填充轨道和未填充轨道的输入；
任意位置按下后由该输入面捕获鼠标并连续换算数值，松开或弹层关闭时结束捕获。弹层保持 WPF `StaysOpen=false`，点击其它位置仍由系统关闭；再次点击音量图标时，关闭事件与按钮点击之间使用 250 毫秒同次点击抑制窗，避免刚关闭又被按钮重新打开。弹层打开期间控制岛不会因鼠标离开主透明窗口而提前消失。
任何失败都只报告暂不可用，不得降级写入系统主音量。

所有 `--qa-*` 和 `--preview-*` 运行使用独立的 QA 单实例标识，便于在不关闭用户
正式桌宠的情况下进行透明窗口验证；QA/预览关闭时不保存窗口位置、置顶或媒体设置，
正式运行仍只允许一个实例。QA 与正式运行都不连接系统主音量；只有显式
`--qa-application-volume` 才允许隔离 QA 设置窗口连接真实网易云会话。

`SettingsWindow` 使用约 570×620 DIP 的紧凑控制台：154 DIP 左栏常驻应用头像、四项整行导航、页面专属台词和随页变化的角色图；右侧四页各自纵向滚动，58 DIP 底栏固定显示未保存状态与“保存并关闭”。常规、音乐、通知、关于分别显示“我推”“真好”“天哪”“加入我们”；关于图直接使用官方睁眼且带 `Join Us!` 的透明 PNG。音乐页首先以总开关控制是否显示播放动画；下方用一张横向预览卡解释智能分配，再用三张预览卡明确“固定唯一动画”会应用到所有歌曲。全部可键盘操作，旧的一键唱歌单独开关不再显示。切页以约 160 ms 同步淡入台词与角色图，系统减少动态效果时直接替换。`tools/ui/prepare_settings_ui_assets.py` 负责确定性 UI 派生：四张官方 PNG 分别裁切可见 Alpha 边界后等比装入 144×124 透明画布，不擦字、不重绘；从三套正式音乐运行图集各抽取代表帧、按 Alpha 可见范围适配 128×128 透明预览，并组合自动模式预览；从已经清理透明背景的晶蓝礼服运行帧裁出耳朵、脸和肩部，置于天依蓝圆角底并生成 16～256 像素多尺寸 `assets/app/luotianyi-pet.ico`。XAML 把 UI PNG 作为程序集资源，项目 `ApplicationIcon` 把 ICO 嵌入 EXE，托盘继续从当前 EXE 读取同一图标。派生元数据记录四张源图哈希、Alpha 裁剪框、输出尺寸与哈希。

### 进程与前台窗口

- 受保护游戏存在性：`PollingProtectedGameProcessMonitor` 每 2 秒只按配置的
  `YuanShen` / `GenshinImpact` 名称调用公开进程枚举，读取进程标识后立即释放对象；
- Core `ProtectedGamePresenceTracker` 合并多进程实例，正式应用启动时只建立当前基线，
  不把已经运行的游戏误报为一次新启动；
- 前台判断：`GetForegroundWindow`、`GetWindowThreadProcessId` 和当前显示器边界；查询失败、
  受保护游戏前台或任意全屏窗口前台时，原神反应失败关闭；
- `GenshinBackgroundCameoScheduler` 负责 5～55 分钟随机触发、45 分钟硬冷却，以及重新
  回到后台后的 5～15 分钟延后；进程退出、锁屏或挂起时清空计时；
- “你不许玩”只播放一轮并保持最后一帧，使动画开始到释放临时置顶合计约 5 秒；它和“拜托”都使用不激活的临时置顶令牌；后者在当前显示器工作区保留
  24 DIP 安全边距随机定位，结束后恢复原位置和用户永久置顶选择；
- 不读取进程内存、模块、线程、画面、文件或网络，不向游戏发送输入，也不保留游戏句柄。

### 通知

- `WindowsMessageNotificationSource` 使用用户授权的 Windows `UserNotificationListener`。该能力要求
  应用具有 MSIX 包身份并在清单声明 `uap3:userNotificationListener`；当前免安装 EXE 会明确返回
  `PackageIdentityRequired`，不会弹出无效权限请求；

### 文件回收站

- WPF 主窗口只接收自身 OLE 拖放提供的 `CF_HDROP` 真实本地路径，不安装全局 Hook 或资源管理器扩展；
- 文件进入窗口后由一次性反应播放 `resonance-give-me`，播放器自然停在最后帧；离开或完成投放后再结束状态机反应；
- 投放前台安全复用 `DesktopFileTreatSafety`：允许覆盖屏幕的 `explorer.exe` 桌面外壳与最大化资源管理器，因而无需先激活桌宠；其它真正全屏进程、受保护游戏和查询失败仍按失败关闭；
- 可见人物范围和 400 ms 停留门槛由窗口层判定；网络位置、磁盘根目录、无效路径和超过 100 项的投放在进入 Shell 前拒绝；
- `WindowsRecycleBinService` 在独立 STA 线程通过 Shell `IFileOperation`，同时设置 `FOF_ALLOWUNDO` 与 `FOFX_RECYCLEONDELETE`；
- 回收完成后再次检查源路径是否仍存在，用于区分成功、取消和部分失败；失败时禁止永久删除回退。成功只恢复此前持续动画，不向包子队列写入目标；投放进行中及完成后的抑制窗会过滤桌面观察器自身产生的消失事件。

## 6. 窗口和交互

- 主窗口无边框、透明、默认不进入任务栏；
- 临时置顶不激活窗口，使用请求令牌合并；
- 用户永久置顶和临时置顶分别保存；
- 保存相对显示器工作区的位置，显示器消失后自动夹回可见区域；
- 所有尺寸使用设备无关单位，命中换算到动画逻辑坐标；
- 双击先于单击分发，形成拖拽后取消身体点击；
- 输入先进入 Core 的 `PointerGestureRecognizer`：单击等待 300 ms，第二次按下命中待决单击时只发双击；移动达到 6 设备无关像素后只发拖拽开始/结束；
- 窗口拖拽不再调用阻塞式 `DragMove`，而是在鼠标捕获期间用屏幕 DIP 坐标更新窗口位置；三种全身外观中仅第三种“经典猫耳版”切到“膨胀”并单次播放后停末帧，前两种保持各自待机画面；
- 拖拽结束不再创建“降落”或程序弹簧回弹。Core `RapidBackAndForthDragTracker` 只在经典猫耳版 900 ms 内检测三段至少 32 DIP、360 DIP/秒的横向快速移动和两次换向；触发后窗口循环 `tenth-anniversary-spin-dance`，取消边缘收纳候选，松手保持，下一次点击或音乐开始时取消反应并恢复持续状态；
- 音乐持续状态优先于拖拽的显示模式外观：拖拽前正在播放音乐时，迷你和完整全身模式都保持本次音乐动画，松手不创建落地反应；播放状态若在拖拽期间发生变化，只更新松手后的恢复状态；
- 主桌宠窗口不挂载 `ContextMenu`；设置、置顶、开机自启动、显示大小和退出统一由系统托盘快捷面板提供。开发动画与身体区域验证仅保留命令行 QA 入口，不进入用户界面。
- 正式桌宠主窗口与临时包子窗口使用原生 `WS_EX_TOOLWINDOW` 并移除 `WS_EX_APPWINDOW`，不进入 Alt+Tab、Win+Tab 或任务栏窗口列表；同时拦截系统最小化命令并在异常最小化后立即恢复，使 Win+D“显示桌面”只收起普通应用窗口而保留桌宠。QA 截图实例可显式保留普通任务窗口样式。

# 文件小笼包追逐（2026-09-01）

- `IDesktopItemDisappearanceSource` 是 Core 层可启停边界；Windows 实现用 `FileSystemWatcher` 观察用户/公共桌面，用 UI Automation 缓存桌面图标中心，不向 Core 传递路径。
- `BunTargetWindow` 是独立 64×64 透明、可拖动目标窗口；主窗口每帧读取其当前中心，因此用户在被吃掉前移动包子会实时改变追踪目标。鼠标屏幕坐标先通过当前窗口的 `TransformFromDevice` 转回 DIP，再写入 WPF `Left/Top`，避免 125%～200% 缩放时拖动距离翻倍。
- `BunChasePlanner` 只负责与帧率无关的二维靠近计算，已用单元测试覆盖到达与不越界；主窗口负责最近目标排序、方向镜像、进食曲线、返回原位和状态机令牌。
- 源视频不直接在运行时解码。构建工具读取用户确认的 121 帧透明 PNG，以 sRGB 可见颜色和原 Alpha 为准，联合裁切后生成 410×410 运行帧；相邻帧在中性底上计算一次双向 Farneback 光流，再按多个目标时间位置分别扭曲前后帧并以预乘 Alpha 合成。两套奔跑循环均输出 60 帧，进食时间轴仍为 173 个 16 ms 逻辑帧（约 62.5 FPS），再编码为质量 95、精确 Alpha 的动画 WebP；编码器会把末尾两张完全相同的闭嘴帧合为一个 32 ms 物理帧，运行解码器按清单时长还原为两个逻辑帧，因此既不丢展示时间也不越过原第 172 帧索引。安装包不携带 OpenCV；资产维护环境按 `tools/animation_tools/requirements.txt` 安装 Pillow、NumPy 和 OpenCV Headless。
- `BunChasePlanner` 以本段奔跑累计时间计算速度，从 180 DIP/s 线性加速，3.5 秒达到明确的 800 DIP/s 上限；返程不复用加速曲线，固定为 850 DIP/s。原生显示器工作区像素先除以 WPF 当前 DPI 比例得到逻辑尺寸，再以 1920×1080 对角线为基准计算 1～2 倍速度系数：2K 100% 约 1.33、4K 100% 为 2、4K 200% 回到 1。16:9 的 1080p/2K/4K 单屏对角线追逐理论值均约 4.11 秒。人物换帧和窗口位移不再由两个独立 `DispatcherTimer` 驱动，而是统一订阅 `CompositionTarget.Rendering`；每个可见帧按单调时钟计算位移、坐标四舍五入到当前 DPI 的物理像素，若 UI 线程短暂停顿则单帧最多补 34 ms 位移，防止为追赶时间产生大幅瞬移。两套奔跑序列在光流重采样前先用画面上部 64% 的 Alpha 重心对齐到周期中位数；premultiplied RGBA 亚像素平移保持循环首尾差低于 0.2 像素。甜笑寻包版的张嘴中心按运行画布横向 62.5%、纵向 45.2% 标定，朝左时绕人物中心镜像为横向 37.5%。
