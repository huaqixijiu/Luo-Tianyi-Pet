# 技术架构

> 状态：基线 v1
> 目标：让桌宠场景、动画和 Windows 联动可以独立测试和替换。

## 1. 技术基线

- 语言：C#；
- 运行时：.NET 10 LTS；
- UI：WPF；
- 平台：Windows 10 1809+、Windows 11；
- 测试：单元测试 + Windows 集成测试 + 视觉检查清单；
- 发布：先自包含免安装包，再增加 MSIX；
- 权限：普通用户。

选择 WPF 的原因是桌宠核心需求集中在透明无边框窗口、非激活置顶、像素命中、拖放和 Win32/COM 互操作。现代 Windows 能力通过独立的平台适配层接入，避免 UI 直接依赖系统 API。

只有在模块出现真实职责后才建立对应项目，避免空工程泛滥；命名和边界以本文件为目标结构。

## 3. 核心状态模型

桌宠不是单一的“当前动画”，而是三个正交状态：

```text
用户显示模式
  compact / fullBodyInteractive

持续状态
  idle / mediumIdle / musicPlaying / sleeping / dragging / hiddenForSafety

一次性反应
  startup / interaction / mediaCommand / notification / genshin / volume / result
```

动画调度器根据三者和优先级生成唯一的 `PlaybackPlan`。一次性反应结束后重新求值，而不是写死返回某个动画。

M2 的实际核心实现为 `PetStateMachine`：一次性反应使用唯一令牌结束，旧动画回调不能清除后来覆盖它的反应；同源事件可按 `mergeKey` 合并并在完成后进入冷却；低优先级事件不会覆盖高优先级事件；过期事件直接丢弃。拖拽单独进入持续状态并记住拖拽前状态，拖拽期间收到音乐状态变化时只更新待恢复状态。

音乐播放状态同时保存本次曲目对应的动画 ID。`MusicArtistMatcher` 只检查已解析的歌手字段，将以 `/`、`、`、逗号、`&`、加号或分号分隔的独立“洛天依”/`Luo Tianyi` 识别为独唱或合唱；不从曲名猜测。`MusicPlaybackAnimationSelector` 对洛天依歌曲从 0.5 倍速“享受音乐”和“音乐摇摆”中随机选择，对其它或未知歌手固定使用戴耳机的“享受音乐”作为陪听动画。每次暂停后继续或曲目身份变化时重新按歌手分类选择。两项均作为持续动画循环；其它高优先级反应结束时由状态机恢复当前选择。“享受音乐”的运行时源不直接循环原始一次性 GIF，而是由可复现脚本提取文字稳定区间并生成相邻帧往返闭环，避免人物跨帧跳变和文字重复入场。

事件流：

```text
Windows 事件或用户输入
        ↓
平台适配器生成领域事件
        ↓
场景规则过滤、去重、冷却与安全检查
        ↓
状态归约器更新三类状态
        ↓
动画调度器生成 PlaybackPlan
        ↓
WPF 窗口播放、定位、命中和恢复
```

## 4. 动画管线

原始 GIF、WebP、SVGA、PNG 和官方模型文件不直接散落在 UI 代码中引用。`AssetCompiler` 读取动画清单，输出统一的运行时元数据：

```text
id
sourcePath
runtimePath
canvasWidth / canvasHeight
frameDurations
loopPolicy
alphaBounds
anchor
contentHash
transformations
```

第一阶段先用一个 GIF、一个动态 WebP 和完整全身待机做原型。只有确认内存、透明度和帧时序后，才批量转换全部已选素材。处理后的每项资产必须保存来源路径、哈希和转换参数。

默认紧凑模式使用 `user-chibi-compact-idle`，来源为用户放入候选目录的 `Q版小人全身.png`；源文件实际为烘焙近白棋盘格的 RGB 图片，`prepare_full_body_idle.py` 以更宽松但仍限制为画布边缘连通区域的阈值生成透明 Alpha，再等比例装入 480×520 画布并以 180×195 DIP 显示。完整全身互动模式继续使用稳定 ID `official-v4-chibi-full-body-idle`、220×238 DIP 显示槽和既有身体命中图。两种模式均保持底部锚点，音乐临时覆盖、拖拽、边缘收纳和一次性反应无需新增状态维度。

完整全身同模型动作候选由 `tools/animation_tools/make_full_body_action_candidates.py` 从 32 帧待机 WebP 确定性生成。变换以脚底附近为统一轴点，逐帧应用可复现的仿射位移、缩放和旋转，首尾帧严格回到同一源帧；输出仍为 480×520 透明动态 WebP。该流程只用于候选动作，不宣称具备 PMX 骨骼级局部控制；用户选定后才进入正式动画清单。

精细全身动作使用固定版本的便携式 Blender 4.5.13 LTS 和 MMD Tools 4.5.13，从仓库中的官方 PMX 直接导入材质、骨骼与表情。`blender_inspect_pmx.py` 输出可审计的骨骼/表情报告，`blender_make_drag_leg_flail.py` 以关键帧驱动双腿、膝、脚踝、躯干、手臂、头部和发辫，Eevee 透明渲染为 960×1040 PNG 序列，`pack_rendered_action.py` 再确定性缩为 480×520 无损动态 WebP，最后进入现有图集编译器。便携 Blender、插件、`.blend` 和中间帧只存放于 Git 忽略的 `.local-tools/`；动作脚本、源 PMX、派生 WebP、运行时图集和来源哈希进入仓库，可重复生成和审查。

M1 原型将选定动画编译为透明 PNG 图集，并用 JSON 清单保存每帧时长和图集网格。WPF 只加载当前清单中经过哈希校验的图集，通过 `CroppedBitmap` 逐帧显示；这避免在运行时混用 GIF/WebP 解码器，也保留完整 RGBA 透明度。图集由 `config/animation-sources.json` 和可复现脚本生成，原始素材不变。

身体命中使用相对于完整全身逻辑画布的归一化区域，并先读取当前显示帧的 alpha 像素排除透明位置。小区域按眼睛、脸、手、敏感区域、脚、头发、普通身体的顺序优先命中。一次性表情动画播放期间关闭身体区域命中，但仍允许高优先级的窗口拖拽。开发菜单可显示与实际命中共用同一份坐标数据的调试叠层，避免显示框与真实判断漂移。

身体命中后的产品规则由 Core 层 `BodyInteractionResolver` 统一解析，窗口层不保存区域到动画的散落映射。解析器持有胸部/下体共享的 4 秒升级窗口和黑化后的 10 秒冷却；嘴部和脸部分离，普通身体固定播放“十二周年·抱抱”。上游素材包把 `11_抱抱.gif` 与 `12_在吗.gif` 的可见文案命名颠倒，运行时通过逐帧核对后使用实际显示“抱抱”的 `12_在吗.gif`。窗口收到播放决定后以 `PetStateMachine` 建立用户互动反应令牌，并在跨画风遮罩过渡中切换素材；动画结束只有匹配令牌的回调才能恢复当前持续状态。

Windows 平台层通过公开 `GetLastInputInfo` 只读取距系统最后一次键鼠输入的时长。Core `IdleSceneResolver` 维护 3 分钟与 30 分钟两个边界：达到 3 分钟进入 `mediumIdle` 并循环“嘿嘿”，达到 30 分钟且持续状态不是音乐、音乐暂停、拖拽或安全隐藏时进入 `sleeping` 并显示“眠了呼吸”；“躺平”不再进入状态机或安装内容。WPF 每秒只读轮询一次；睡眠后的首次输入只恢复当前空闲时长对应的持续状态，不再播放“苏醒弹出”。`BirthdayEasterEggScheduler` 只按本地月日与 45～90 分钟随机窗口调度生日反应，不保存操作历史。

启动时间问候由 Core `StartupTimeSceneResolver` 使用半开时间区间解析，06:00、12:00、
13:30、20:00 边界不散落在窗口代码中。Core `TimeSceneTransitionTracker` 保存当前时段基线，WPF 每秒观察一次本地时间；正式启动（包括用户启用的 Windows 开机自启动）及运行中跨过边界时请求 `TimeGreeting` 优先级反应，并以 30 秒限时展示器循环对应程序动效；
媒体、通知或用户互动可按现有状态机优先级替换它，完成后恢复当前持续状态。四项静态官方
表情编译为单帧图集，并由 `BodyReactionMotion` 叠加浮动、弹跳或呼吸。

Windows 解锁与电源恢复由平台层 `WindowsSystemResumeSource` 订阅公开的
`SystemEvents.SessionSwitch` 和 `SystemEvents.PowerModeChanged`。Core
`SystemResumeEventGate` 把同一轮恢复在 5 秒内产生的重复事件合并；窗口只恢复当前应有的持续状态，不再播放“苏醒弹出”，也不激活、不置顶或改变用户显示模式。主动隐藏在屏幕边缘时保持隐藏，尊重用户的隐藏意图。

边缘躲藏由 Core `EdgeDockResolver.ResolveHideIntentWithHysteresis` 按人物画面而非透明窗口外框计算左、右、下三种越界深度。人物只与工作区边界相接时允许正常贴边，继续向外超过 28 DIP 才进入躲藏；进入预演后沿用切换素材前缓存的拖拽人物本地边界，并在退回 14 DIP 内保持当前候选，避免完整全身素材与“偷看/闪亮登场”尺寸变化导致判定来回翻转。拖拽窗口临时允许 96 DIP 受控越界，松手未达到阈值时把人物画面夹回工作区。WPF 使用人物实际变换后边界对齐，消除原窗口左右 8 DIP、底部 66 DIP 预留造成的空隙。

`AnimationFramePlayer` 支持指定起止帧、固定单帧和单次范围播放速率，`AnimationFrameTimeline` 通过按速率缩放本次帧时长实现，不修改素材清单或其它使用场景。`EdgeDockFrameRouteResolver` 负责含字展开与无字收回的非对称路线。左右“偷看”以 1.3 倍速从第 3 帧展开到第 19 帧，完整保留“偷看”文字与人物，收回第 7→3 帧保持原速；底部“闪亮登场”展开第 3→7 帧保持原速，收回第 5→3 帧使用 0.7 倍速。同一段内改变方向会沿用当前帧，跨含字/无字段则回到无字收回起点。

资产编译器支持可选的 `cropAfterResize: [left, top, right, bottom]`。它先按既有规则统一帧尺寸，再校验同一个裁剪矩形位于缩放后边界内并应用到所有帧；清单记录裁后帧宽、高、透明边界和新哈希，原始官方文件不变。“十二周年·偷看”由 240×240 裁为 196×240，运行时显示宽度同步从 190 DIP 调为 155 DIP，保持人物的纵向比例，避免把较窄画面再次拉宽。

隐藏完成后 `PetImage.Clip` 只暴露派生素材中的砖墙或猫耳/头发，透明按钮仅覆盖同一可见区域。左右隐藏在裁后“偷看”画面的 90% 处起裁，宽度约 9.2%，155 DIP 显示尺寸下约 14 DIP；窗口位置按裁剪后的变换边界贴合工作区，而不是按完整图片边界计算，因此右侧不会留下整块宽墙，左侧镜像后也能精确贴边。左边缘只在显示层水平镜像，不生成第二份素材。

身体反应完成后由 `PetStateMachine.SuppressBodyInteractions` 建立 800 毫秒恢复期，`Resolve` 在此期间只把 `BodyRegionInteractionsEnabled` 设为 false。延迟单击和摸头入口依赖该标志，因此会被抑制；双击模式切换直接更新用户显示模式，窗口拖拽直接进入拖拽状态，两者不依赖该标志，所以不会被恢复期阻断。重复设置恢复期只会延长截止时间，不会意外缩短。

头发按下后由独立 `PettingGestureRecognizer` 暂缓普通 6 DIP 拖拽：持续至少 350 毫秒、水平累计移动达到 24 DIP 且至少一次换向即可完成摸头；从起点单向位移达到 24 DIP、离开头部矩形或落到透明像素时立即取消候选并把当前位置交回窗口拖拽判定。头顶短按另有同动画兜底。完成摸头后消费本次按压，松手不会再补发身体单击或双击。

## 5. 平台适配器

### 音频与媒体

- Core Audio/WASAPI：定位 `cloudmusic.exe` 会话、读取有声状态和系统主音量；
- 系统媒体会话：在可用时读取曲名、歌手并辅助确认切歌结果；切歌期间只显示等待文字，不播放“加载中摇摆”，标题变化优先确认，Core Audio 静音后恢复作为辅助确认，15 秒超时失败关闭；
- 网易云窗口标题兜底：仅在系统媒体会话不存在时读取目标进程的顶层标题栏；
- 网易云控制：只发送用户配置的全局快捷键；受保护应用前台时禁用。
- 网易云冷启动：Core `IMediaApplicationLauncher` 返回结构化启动结果，Windows
  `WindowsMediaApplicationLauncher` 先检查目标进程与前台安全状态，再从 App Paths 或明确的
  常见安装目录解析 `cloudmusic.exe` 并由 Shell 启动；不扫描磁盘、不使用私有协议。

M3 的第一条纵向链路使用 `LuoTianyiPet.Platform.Windows.CoreAudioSessionProbe`
通过公开的 Windows Core Audio 会话接口，只读取默认多媒体输出设备中与
`cloudmusic.exe` 进程号对应的会话峰值。平台层使用 MIT 许可的
`NAudio.Wasapi` 3.0.1 作为薄封装，不解码、录制或传输音频，也不读取目标进程
内存、模块和窗口内容。Core 层 `MusicAudioActivityDetector` 以 0.001 峰值作为
默认有声阈值，每 250 毫秒采样；检测到有声立即进入播放，普通外部变化连续 1.0 秒无声才退出，会话消失立即退出。桌宠刚发送播放/暂停命令且当前确为播放状态时，另开 2 秒快速确认窗口：首个可靠静音样本即可确认暂停，不必等待通用宽限；仍有声或探测失败则继续按普通检测处理。一次临时探测失败保留原状态并重试，避免设备切换时来回闪烁。

运行时把检测功能作为 `settings.json` 中可独立关闭的 `media` 配置；旧版没有
`media` 节点的配置会补入安全默认值。预览和 QA 参数不启动真实会话探测，保证
确定性验证不受用户播放器状态影响。音乐事件只更新状态机：身体反应优先播放，
拖拽期间只更新拖拽后的恢复状态；日志不记录进程号、峰值、歌曲或窗口信息。

曲目信息由 Core 的 `IMediaTrackInfoSource` 抽象，Windows 实现
`SystemMediaTrackInfoSource` 每秒读取一次。它先枚举
`GlobalSystemMediaTransportControlsSessionManager`，按 `SourceAppUserModelId` 限定
网易云会话并调用 `TryGetMediaPropertiesAsync`；若当前网易云版本没有注册系统媒体会话，
再读取 `cloudmusic.exe` 顶层主窗口标题并按“歌曲 - 歌手”保守解析。标题会折叠控制字符
和多余空白，并限制为 80 个字符；歌手限制为 60 个字符。两者只保存在内存，不写日志。

主窗口顶部为 `TrackInfoBubble` 预留 52 DIP：悬停时显示缓存并立即刷新，检测到曲目变化
或桌宠发起上一首/下一首时保留 4 秒；没有可用信息时仅在悬停时显示降级说明。媒体控制
通常位于动画下方 58 DIP 区域；人物距工作区底边不超过 80 DIP 时，上下预留空间对调，
控制岛移动到歌名/作者上方，人物屏幕位置保持不变。三者在任务栏附近仍不互相覆盖。

快捷键控制由 Core 的 `IMediaCommandSender` 返回结构化结果，Windows 平台适配器
`WindowsMediaCommandSender` 负责解析用户配置并调用 `SendInput`。默认组合为
上一首 `Ctrl+Alt+Left`、播放/暂停 `Ctrl+Alt+P`、下一首 `Ctrl+Alt+Right`，发送
最小间隔 350 毫秒。适配器只查询前台窗口所属进程名并与受保护名单比较；查询失败、
受保护应用前台、相关实体键仍按下、配置无效、频率过高或系统未接受完整输入时均不
发送或报告失败。窗口只显示结果气泡并记录命令类别与结果，不记录前台进程名和用户
按键内容；“已发送”不等同于“播放器已响应”。只有观察到曲名变化或切歌音频间隙后恢复才播放 OK，未观察到变化时最多等待 15 秒并显示失败反馈。暂停确认后进入独立 `MusicPaused` 持续状态，播放“九周年·没睡醒呼吸”最长 60 秒；期间双击只提前收起暂停反馈，不切换用户选择的 Q 版小人/完整全身模式，恢复播放则立即进入新的音乐持续动画。

媒体控制入口是主透明窗口内的 `MediaControls` 区域，而不是右键菜单。它位于角色动画
正下方并预留 58 DIP 高度，仅在鼠标悬停或 QA 预览时可见，使用三个 WPF 按钮调用同一
`IMediaCommandSender`。角色视觉层和音乐切换闪白层均为底部控制区留出相同空间，因此
控制岛不会覆盖角色、表情文字或身体命中区域。
`MediaControlsVisibilityMotion` 负责 170 毫秒上浮淡入、220 毫秒移出宽限和 120 毫秒
淡出；隐藏期间元素为 `Collapsed` 且关闭命中，不会影响身体点击或拖拽。播放/暂停
按钮在目标进程不存在时进入最多 30 秒的冷启动反应：运行时播放已有
`resonance-loading-sway` 单帧图集并保持气泡文字，图片自身不叠加程序摇摆。启动约 2 秒后若
Core Audio 尚未有声，只发送一次播放快捷键；`MusicAudioActivityDetector` 确认有声时完成反应，
状态机直接解析当前歌曲的音乐持续动画。启动、快捷键或等待失败完成该反应后播放呜呜反馈；目标
进程已经存在时完全复用原快捷键流程。
矢量图标仍只跟随已确认的 Core Audio 状态变化；桌宠发起暂停时使用上述快速确认窗口缩短图标反馈，而不是在模拟按键刚发出时盲目翻转。

控制岛的组件样式在项目 XAML 内维护，使用 `#66CCFF` 品牌主色、蓝色玻璃表面和本地
矢量 `Path` 图标。项目参考 MahApps 圆形按钮与 IconPacks 的组件模式，但不为三个按钮
引入 MaterialDesignThemes、WPF-UI 或完整 UI 框架，避免增加十几 MB 依赖和额外主题
资源；按钮仍有独立悬浮、按下、禁用和工具提示状态。

低频桌面设置由 `TrayIconController` 使用 Windows 通知区域图标承载：打开设置、始终置顶、
开机自启动和退出。`WindowsStartupRegistrationService` 只操作当前用户 Run 项中的单一产品值；
便携版写入带 `--portable` 的绝对路径，MSIX 版写入稳定的 AppsFolder 激活命令。默认关闭，只有
用户在设置页或托盘中主动切换时才写入，关闭后仅删除该产品值。

系统音量由 Core 的 `ISystemVolumeService` 抽象，Windows 实现
`WindowsSystemVolumeService` 使用 NAudio 的 `AudioEndpointVolume` 访问默认多媒体输出
端点。鼠标滚轮每格默认改变 2%，写入前只查询当前前台进程名并按受保护名单失败关闭。
外部变化同时订阅 Core Audio 通知并每 250 毫秒只读采样兜底；
`SystemVolumeChangeTracker` 保存上一个可用快照，分类提高、降低、静音、解除静音并过滤
重复值。通知和采样即使同时到达，也只有第一个实际变化会产生反馈。

提高和降低分别用 `volume:increase`、`volume:decrease` 合并键进入 `PetStateMachine`。
500 毫秒内的同方向变化只延长当前反应而不重播，结束后同方向动画冷却 2 秒；气泡仍
实时更新。调高使用原版“共鸣之声”，调低使用带来源哈希的倒放素材；静音状态只显示
`🔇/🔊` 和百分比。用户互动等更高优先级反应可以覆盖音量动画，结束后仍按当前持续
状态恢复，不固定返回“嘿嘿”。

声音与反馈设置使用独立的普通 WPF 窗口，由用户从桌宠右键“设置…”明确打开。滑块通过
同一个 `ISystemVolumeService.TrySetLevel` 写入系统音量，因此与滚轮共享受保护游戏前台
失败关闭规则；滚轮开关、外部反馈开关和步长通过 `UpdatePreferences` 在运行中生效并立即
写入 `settings.json`。外部反馈关闭时同时退订 Core Audio 通知并停止轮询，重新开启时先
读取当前快照作为新基线，不补播关闭期间发生的变化。

所有 `--qa-*` 和 `--preview-*` 运行使用独立的 QA 单实例标识，便于在不关闭用户
正式桌宠的情况下进行透明窗口验证；QA/预览关闭时不保存窗口位置、置顶或媒体设置，
正式运行仍只允许一个实例。QA 默认不连接真实系统音量；只有显式加入
`--qa-system-volume` 才启用 Core Audio 读写与外部变化反馈。

### 进程与前台窗口

- 受保护游戏存在性：`PollingProtectedGameProcessMonitor` 每 2 秒只按配置的
  `YuanShen` / `GenshinImpact` 名称调用公开进程枚举，读取进程标识后立即释放对象；
- Core `ProtectedGamePresenceTracker` 合并多进程实例，正式应用启动时只建立当前基线，
  不把已经运行的游戏误报为一次新启动；
- 前台判断：`GetForegroundWindow`、`GetWindowThreadProcessId` 和当前显示器边界；查询失败、
  受保护游戏前台或任意全屏窗口前台时，原神反应失败关闭；
- `GenshinBackgroundCameoScheduler` 负责 5～55 分钟随机触发、45 分钟硬冷却，以及重新
  回到后台后的 5～15 分钟延后；进程退出、锁屏或挂起时清空计时；
- “你不许玩”只播放一轮并保持最后一帧，使动画开始到释放临时置顶合计约 5 秒；它和“拜托”都使用不激活的临时置顶令牌；后者在当前显示器工作区保留
  24 DIP 安全边距随机定位，结束后恢复原位置和用户永久置顶选择；
- 不读取进程内存、模块、线程、画面、文件或网络，不向游戏发送输入，也不保留游戏句柄。

### 通知

- `WindowsMessageNotificationSource` 使用用户授权的 Windows `UserNotificationListener`。该能力要求
  应用具有 MSIX 包身份并在清单声明 `uap3:userNotificationListener`；当前免安装 EXE 会明确返回
  `PackageIdentityRequired`，不会弹出无效权限请求；
- 设置页只在用户点击“申请通知访问权限”后，从 UI 线程调用 `RequestAccessAsync`。拒绝、未指定、
  包身份缺失和平台不可用分别显示，不影响音乐、互动等其它功能；
- 平台适配器读取 `AppInfo.AppUserModelId`、应用显示名、应用 Logo 和通知创建时间，用于判断 QQ/微信来源并显示应用图标；
- 联系人昵称/群名只取 Toast 绑定的第一个文本元素，且仅当绑定至少还有一个独立正文元素时才接受。代码只读取第一个元素的 `Text`，不会访问后续元素的正文值；标题经控制字符清理并限制为 64 字符，结构不明确时返回空；
- 当前 `UserNotification.Notification.Visual` 的结构化绑定没有联系人头像接口，因此领域模型保留可选的内存头像槽，但 Windows 适配器暂不填充；UI 使用应用 Logo 回退，不解析聊天缓存、私有 XML、远程 URL 或窗口画面；
- `MessageNotificationCoordinator` 在内存中执行 3 秒同源去重、来源应用前台抑制和不安全状态延后，并随延后项临时保存来源、标题和图标；清空或展示后释放，不写磁盘。
  游戏/全屏、锁屏、拖拽、睡眠或边缘隐藏期间不展示，回到安全桌面后最多补播一次；
- 提醒播放一次“代号洛天依·好奇摇摆”，独立提醒卡显示应用来源、图标和可用的联系人/群标题；窗口只
  临时置顶且不激活，结束后恢复用户永久置顶选择和此前持续动画；
- `packaging/Package.appxmanifest.template` 保存最小能力声明；`tools/packaging/build_msix.ps1` 生成
  .NET 10 x64 自包含布局、开发证书、签名 MSIX 和 SHA-256。包图标从正式“十二周年·抱抱”
  无文字帧确定性生成；私钥、随机密码、发布布局和包都在 Git 忽略的 `artifacts/msix/`；
- 构建脚本只创建文件，不安装证书或包。测试证书未受信任时签名状态显示链不受信任，这是安装前
  的预期状态；信任公钥、安装包和通知权限申请必须分三步由用户明确确认。

### 文件回收站

- WPF 主窗口只接收自身 OLE 拖放提供的 `CF_HDROP` 真实本地路径，不安装全局 Hook 或资源管理器扩展；
- 文件进入窗口后由一次性反应播放 `resonance-give-me`，播放器自然停在最后帧；离开或完成投放后再结束状态机反应；
- 可见人物范围和 400 ms 停留门槛由窗口层判定；网络位置、磁盘根目录、无效路径和超过 100 项的投放在进入 Shell 前拒绝；
- `WindowsRecycleBinService` 在独立 STA 线程通过 Shell `IFileOperation`，同时设置 `FOF_ALLOWUNDO` 与 `FOFX_RECYCLEONDELETE`；
- 回收完成后再次检查源路径是否仍存在，用于区分成功、取消和部分失败；失败时禁止永久删除回退。

## 6. 窗口和交互

- 主窗口无边框、透明、默认不进入任务栏；
- 临时置顶不激活窗口，使用请求令牌合并；
- 用户永久置顶和临时置顶分别保存；
- 保存相对显示器工作区的位置，显示器消失后自动夹回可见区域；
- 所有尺寸使用设备无关单位，命中换算到动画逻辑坐标；
- 双击先于单击分发，形成拖拽后取消身体点击；
- 输入先进入 Core 的 `PointerGestureRecognizer`：单击等待 300 ms，第二次按下命中待决单击时只发双击；移动达到 6 设备无关像素后只发拖拽开始/结束；
- 窗口拖拽不再调用阻塞式 `DragMove`，而是在鼠标捕获期间用屏幕 DIP 坐标更新窗口位置；迷你模式切到“膨胀”并单次播放后停末帧，完整全身模式保持原待机画面，不再切专用骨骼拖拽动作；
- 拖拽结束按用户显示模式分流：迷你模式普通松手经遮罩恢复持续动画，`DownwardFlingTracker` 只在总下移、最近下移和最近速度同时达标时创建“降落”及弹簧回弹；完整全身模式始终不创建落地反应，若拖拽前持续状态与当前全身画面不同则使用遮罩恢复，否则无需重播；
- 音乐持续状态优先于拖拽的显示模式外观：拖拽前正在播放音乐时，迷你和完整全身模式都保持本次音乐动画，松手不创建落地反应；播放状态若在拖拽期间发生变化，只更新松手后的恢复状态；
- 右键菜单和托盘提供设置、置顶、紧急隐藏和退出。

## 7. 配置和持久化

仓库中的示例配置不保存用户私人设置。运行时配置放在：

```text
%LOCALAPPDATA%/LuoTianyiPet/
  settings.json
  state.json
  logs/
```

使用 `--portable` 启动时不访问上述目录，全部可变数据改为：

```text
<便携包解压目录>/UserData/
  settings.json
  logs/
```

便携测试包不注册 MSIX、不导入证书、不创建服务或注册表项。包内清理脚本只在同时存在
`PORTABLE_TEST_PACKAGE.marker` 和本包可执行文件、且目标确认为当前解压目录内的 `UserData`
时执行；它只停止路径完全匹配的便携进程并删除该目录，不操作本机安装版或其它文件。
便携版没有包身份，因此 Windows 通知监听按设计不可用。

- `settings.json`：用户选择和功能开关；
- `state.json`：窗口位置等可恢复状态；
- 日志：只记录版本、事件类别、错误代码和性能数据，不记聊天内容或完整文件路径。

配置包含 `schemaVersion`，升级时先备份再迁移。损坏配置应回退到默认值并保留诊断副本。

## 8. 测试策略

- Core：状态优先级、恢复、冷却、跨午夜时间段、双击/拖拽判定；
- Animation：清单验证、帧时序、循环、透明边界和缺失资产降级；
- Windows：音频会话消失、显示器变化、全屏安全模式、通知权限拒绝；
- 文件：只用自动创建的临时文件验证进入回收站，并人工确认可恢复；
- 视觉：100%、125%、150% DPI，多显示器边缘，深浅桌面背景；
- 性能：待机 CPU、内存、睡眠恢复和长时间动画稳定性。
# 文件小笼包追逐（2026-09-01）

- `IDesktopItemDisappearanceSource` 是 Core 层可启停边界；Windows 实现用 `FileSystemWatcher` 观察用户/公共桌面，用 UI Automation 缓存桌面图标中心，不向 Core 传递路径。
- `BunTargetWindow` 是独立 64×64 透明、可拖动目标窗口；主窗口每帧读取其当前中心，因此用户在被吃掉前移动包子会实时改变追踪目标。
- `BunChasePlanner` 只负责与帧率无关的二维靠近计算，已用单元测试覆盖到达与不越界；主窗口负责最近目标排序、方向镜像、进食曲线、返回原位和状态机令牌。
- 源视频不直接在运行时解码。构建工具先用 Blender 以 sRGB 输入、Standard 视图变换提取 121 帧，禁止默认 AgX 对二维视频素材再次色调映射；随后以可复现脚本生成 256×256 透明图集和元数据。运行时复用现有图集播放器，避免新增视频编解码依赖。
- 文件拖到桌宠的删除动作仍由 `IRecycleBinService` 完成。只有 Shell 返回成功才生成包子；观察到桌面项目消失只触发动画，不执行任何第二次文件操作。
