# 完整全身基础待机动画调研

> 目标：寻找桌宠在没有事件时长期展示的完整全身动画，并确定洛天依桌宠后续的制作方向。

## 1. 常见实现

成熟桌宠通常把“主待机”和“随机表情”分开：

- 主待机是完整全身、动作幅度很小、可以长时间无缝循环的动画；
- 主待机常见时长为 4～6 秒，包括缓慢呼吸、重心轻微左右移动和一次眨眼；
- 东张西望、打哈欠、挥手等动作只偶尔插播，结束后回到主待机；
- 进入睡眠前有单独的趴下或坐下过渡，睡眠结束后有单独的苏醒过渡；
- 拖拽、落地、点击反应属于高优先级动作，不直接修改主待机资源。

## 2. 参考项目

### DeskPet-Furina

项目将默认待机设计为 6 秒往返循环，角色轻微起伏；长时间待机才随机插播东张西望和打哈欠，并使用单独的趴下、睡眠和醒来过渡。

参考：<https://github.com/Ice-teapop/desktop-pet>

### TonyNa Desktop Pet

角色包将 `idle` 作为第一条基础动作，其他挥手、跳跃和移动动作按状态切换。每个角色用图集和动作清单记录帧数、速度与动作行。

参考：<https://github.com/TonyNa-code/desktop-pet>

### os-pet

该项目把完整全身侧面角色作为基准，最小可用待机只需要 2～4 帧。推荐的 4 帧循环为正常、轻微压缩/上移、回到正常、轻微拉伸/下移，形成呼吸和起伏感。

参考：<https://github.com/akhanreviews/os-pet>

### ChatGPT / Codex Pets v2

规范中的基础待机使用 6 帧，表现平静呼吸与眨眼；第一帧同时作为减少动效模式下的静态姿势。其他等待、执行、失败和注视方向与待机分开。

参考：<https://github.com/xiongxianzhu/chatgpt-pets>

### 传统 Shimeji 桌宠

常见状态链为 `idle → idle-to-sleep → sleep → sleep-to-idle`，说明“站立待机”和“进入睡眠”应该有明确过渡，而不是直接切换两张表情。

参考：<https://github.com/tommyli3318/desktop-pet>

## 3. 对本项目的结论

当前素材中的“嘿嘿”是半身表情 GIF，适合作为过渡期基础待机，但无限循环时会显得动作语义过强，也不利于后续划分头部、手部和身体点击区域。

项目已经拥有官方“洛天依 V4 公式服 Q 版”PMX 模型，因此更合适的长期方案是从该模型确定性地渲染一套透明背景、完整全身的二维帧，而不是继续混用比例和裁切不同的表情包。

建议制作：

1. **完整全身主待机**：6 帧、4～6 秒循环，轻微呼吸、重心摆动、一次眨眼；
2. **看向鼠标**：头部和视线轻微偏转，不转动整个身体；
3. **进入随机待机过渡**：主姿势停稳后再播放挥手、好奇或表情 GIF；
4. **从随机动作返回**：最后一帧在位置、比例和脚底锚点上回到主待机第一帧；
5. **减少动效模式**：使用主待机第一帧静态展示；
6. **统一锚点**：所有全身帧的脚底中心固定，避免角色在循环时漂移。

## 4. 建议的主待机节奏

| 时间点 | 动作 |
|---|---|
| 0% | 正常站姿、睁眼 |
| 20% | 身体上移约 1%，胸肩轻微抬起 |
| 40% | 回到中位，头发与衣摆稍微滞后 |
| 55% | 快速眨眼 |
| 75% | 重心轻微偏向另一侧 |
| 100% | 回到第一帧，可无缝循环 |

动作幅度应尽量小。主待机的任务是让角色“活着”，不是持续抢夺用户注意力。
