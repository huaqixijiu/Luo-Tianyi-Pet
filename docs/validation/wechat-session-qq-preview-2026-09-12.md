# 微信会话字段验证与 QQ 统一详情更新

日期：2026-09-12。版本：0.1.0.64。未安装或运行 wxauto／机器人框架，只验证同类公开 UIA 字段。

## 微信实际结果

- 客户端 4.1.13.12；定向原生探针确认 Visible=True、Minimized=False、Foreground=False。后台可发现 session_list，并读取 11 个 session_item 条目。连续三次定向观察结构保持一致。
- 当前 4 个条目含 18、72、96、65 的“[数字条]”标记，72／96 对应条目同时含免打扰标记。这些只是已暴露会话字段，不能求和宣称全局未读总数；未出现标记也记为未知，不武断当成零。
- 会话 Name 不是独立计数字段：第一行是名称，第二行常把未读标记与摘要拼在一起。wxauto 的整串正则能匹配，但也可能误读正文里的相同格式；不能把独立整行规则当成所有版本的可靠结构。本轮未验证 99+、新消息增加／已读减少或滚动外条目。
- 初次 computer-use 整窗可访问性快照范围过宽，随后改用定向只读诊断，跳过 chat_message_page 和消息列表，原始文本不保存。仅使用标题已明确匹配的微信主窗口；没有切换聊天、输入、发送消息、读取内存或数据库。
- 尝试使用 computer-use 最小化按钮时返回 coordinate input geometry is unavailable；原生探针复核窗口仍未最小化。已请用户手动最小化，尚未收到完成回复，因此**最小化读取未验证**。不把后台可读扩大为最小化／关闭到托盘也可读。
- 微信读取保留在诊断工具，不接入桌宠持续监听；后续入口是完成最小化＋一条受控新消息的字段变化对照。

## QQ 已实现与验证

- 统一 QQ 详细提醒开关控制昵称、系统通知预览及新增通知计数；关闭后清空这三项和托盘补充未读数，只保留来源图标与来源提醒。
- 预览来自结构化 Toast 的独立正文槽，最多 120 字符、卡片内两行，空或异常正文回退为昵称；单槽或空标题不把正文误认成昵称。不开启时跳过文字读取，异步读完后再次核对开关代次。
- 新通知以系统 ID＋创建时间识别；初始快照仅建立基线，不补报历史。连续不同 Toast 不再被 3 秒来源合并吞掉；重复快照、Shell 持续闪烁不增加消息条数。QQ 回到前台、关闭详情或重启桌宠后计数清零。此计数不是 QQ 未读总数。
- 同一来源新通知更新当前卡片，不重播动画；其他来源继续排队。Toast 的昵称／预览不会被多会话托盘摘要覆盖而错配。加入预览的卡片随右边缘换侧，文字保持正常方向。
- 双目标 Release 编译 0 警告／0 错误；Core 520、Windows 131、Animation 37，各两个目标，总计 1376 项自动化通过。包含重复／连续通知、延后累计、关停清理、前台重置、文本槽边界、长文本及 emoji、相同 ID 更新时间等检查。
- .NET 48、.NET 10 各 35 项真实 WPF 检查通过，正式发布 EXE 同样 35 项通过。检查 50／100／200% 人物大小、左右边缘、不抢焦点、统一关闭清空、设置复用与未知前台／全屏降级；已查看合成测试文字的窗口渲染图。
- 在已授权包身份内对本机最近一条真实 QQ Toast 调用正式读取链路：开启时 TitleLength=4、PreviewLength=2，关闭时两者 0；没有输出或保存文字值。该项验证现有通知的解析，**不是新消息到达后完整界面的最终验收**；已请用户发送两条新消息核对递增与显示。
