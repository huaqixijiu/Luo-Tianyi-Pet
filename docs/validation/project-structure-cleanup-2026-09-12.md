# 项目目录整理与旧版本清理（2026-09-12）

## 范围与结果

- 主发布目录每类保留 `0.1.0.56` 和 `0.1.0.51`，共保留 2 个 MSIX、2 个便携 ZIP、2 个安装 ZIP及对应校验材料；不影响其他工作区和正式已安装版本（检查开始时为 `0.1.0.59`，其它任务随后继续升级）。
- 清理 112 个旧发布文件（含同名校验文件），共 11,498,383,111 字节。
- 清理 11 处已结束的框架体积实验/解压验证输出，共 1,406 个文件、2,666,897,603 字节。
- 总计删除 1,518 个文件、14,165,280,714 字节，约 **13.19 GiB**（按文件逻辑大小统计，不是磁盘空闲空间差值）。
- 3 份专题文档分别进入 `docs/research/` 和 `docs/authoring/`；旧 `artifacts/research/`、`artifacts/review/` 归入 `artifacts/archive/2026-09-11/`。文档移动时核对哈希，内容只更新必要路径引用。
- 新增[目录与归档指南](../目录与归档指南.md)，README 同步实际阶段、目录及 SDK 使用说明。

逐个发布文件的相对路径、处理动作、大小和 SHA-256 见 [发布清理清单](project-structure-releases-2026-09-12.json)；旧实验的目录与文件数见[实验清理清单](project-structure-experiments-2026-09-12.json)。旧安装包本身不另存一份；未提交源码生成的历史包不保证能逐字节重建。

## 保留边界

原始素材、运行时及加工资产、源代码、用户已有未提交改动、原暂存区、Git 历史、注册的 4 个项目内工作区、当天联调与 QA 输出、签名私钥、便携目录及其 `UserData` 均保留。体积对比中的 `net48-publish-optimized/UserData` 被识别并连同测试程序保留；编码对比样本也保留。

当天其它开发任务持续更新摸鱼倒计时和消息提醒，目录整理没有合并或覆盖其源码。主项目当前下一步继续由项目总控记录，本轮不重新发布或安装应用。

## 实际验证

- .NET SDK 10.0.400 用户级安装可用；普通 PATH 解析到了无 SDK 的系统 dotnet，验证使用用户级完整路径。
- 以 `-p:EnableNetFrameworkBuild=true --artifacts-path artifacts/maintenance/build` 隔离构建整个解决方案：net10/net48 成功，0 警告、0 错误。
- 相同路径与双目标执行 `dotnet test --no-build`：每个目标 Core 522、Animation 37、Windows 126，共 **1370/1370**，无失败或跳过。验证针对当时磁盘源码，包含其它任务已同步的功能变更；本整理提交只包含结构和维护文件。
- 清理工具隔离测试通过：只预览、数字版本排序（9/10）、保留包校验失败时不删旧版、包与校验文件同步清理、未知文件与 `UserData` 保留、重复运行无操作、目录链接拒绝。
- 保留的便携/安装 ZIP 与其发布 SHA-256 一致；最新 MSIX 与 `SHA256SUMS.txt` 一致。旧文件实际删除前再次计算 SHA-256，发生变化则停止。
- 旧实验清理限定于逐一列出的绝对项目内路径，检查无目录链接、无 `.git`、无 `UserData`、无当天修改和从该目录运行的桌宠进程。

本轮不修改窗口、透明度、命中、动画内容或外部应用联动，因此不新增视觉及模拟输入验收。运行时资产校验和文档链接核对结果见同日开发日志。目录结构整理提交与其它任务暂存内容隔离，分支为 `codex/organize-project-files-20260912`。

验证结束后清理本轮 `artifacts/maintenance/build` 的请求被自动审批拒绝，返回 `blocked by policy`，因此该临时构建目录保留；上述 13.19 GiB 是旧文件删除量，不代表包含新构建输出在内的净磁盘变化。
